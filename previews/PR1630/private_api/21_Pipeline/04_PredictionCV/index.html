Prediction CV: private API

The pipeline fold loop

cross_val_predict over a Pipeline fits the whole pipeline on each training window and predicts on each test window. It also replaces each TimeDependent schedule of the pipeline with its value for the fold, before fit runs. So no value that the pipeline passes to the optimiser is a schedule, and neither fit nor run_step reads the fold.

A scheme built by OnlineIndexWalkForward or OnlineDateWalkForward is an online scheme. With one, the loop fits the pipeline once on the first training window, adds the rows of each later fold with partial_fit!, and gets the fitted result from fit(pipe) with no data. Online(pipe) goes through the same cross_val_predict methods, and refits the whole pipeline at each fold on a buffer of the rows so far. The online pipeline page documents both.

PortfolioOptimisers.pipeline_cross_val_predict — Function
pipeline_cross_val_predict(pipe::Pipeline_OnlPipe, data::Prices_RR, cv::MRCVR; ex = FLoops.ThreadedEx(), id = nothing)
pipeline_cross_val_predict(pipe::Pipeline_OnlPipe, data::Prices_RR, cv::CVER; ex = FLoops.ThreadedEx(), id = nothing)

Run the body of the cross_val_predict methods of a Pipeline, for a Pipeline, for Online(pipe) and for Resume(res).

Algorithm

  1. Check the entry with assert_pipeline_entry.
  2. Split data with cv, giving train_idx and test_idx, and refuse shuffled folds with assert_unshuffled_folds.
  3. Read the evaluation keywords of cv with fold_evaluation, and the drift of the held weights with held_weights_drift, giving hwd.
  4. For MultipleRandomised, put the (train, test, asset) tuples of the folds into one vector for each path, giving dict. Run each path with pipeline_path_fit_and_predict through parallel_folds, and return the paths as a PopulationPredictionResult. Each path carries its own id, so the method ignores id. It accepts id because the Online(pipe) and Resume(res) methods for CVER pass it, and they forward this scheme to this method.
  5. For a scheme with contiguous test rows, run the folds through fold_loop. Each fold fits with pipeline_fold_fit and predicts its test rows. The online arm of the loop resolves Online(pipe) at its warm-up, and passes the pipeline from each fold to the next. Return the predictions as a MultiPeriodPredictionResult with id and the estimator that the online arm threaded.

Validation

  • Everything assert_pipeline_entry, assert_unshuffled_folds and fold_loop refuse.

Combinatorial and asset-resampling over a returns-level pipeline

A pipeline over returns runs the schemes with many paths in the same way as a plain optimiser. CombinatorialCrossValidation fits each split on its training rows, which need not be contiguous, and predicts its test groups. MultipleRandomised runs the inner walk-forward of each path on a view of the input that holds a subset of the assets. The pipeline fits again on that subset, and never takes a subset of a state it already fitted.

PortfolioOptimisers.pipeline_path_fit_and_predict — Function
pipeline_path_fit_and_predict(pipe::Pipeline_OnlPipe, data::Prices_RR, folds, path_id; ex, wd, hwd, fa, pws, store_weight_path, strict, cv) -> MultiPeriodPredictionResult

Run one path of MultipleRandomised over a Pipeline on price-level or returns-level data. The path is an inner walk-forward over a subset of the assets.

Algorithm

  1. Read the training rows train_idx and the test rows test_idx of each fold from folds. folds holds one (train, test, asset) tuple for each fold of the path, in the order of the split.
  2. For fold i, view data on the asset subset of the fold with pipeline_asset_view, which indexes the assets the same way at both levels. The pipeline fits again on each subset, so it never selects from a fitted universe.
  3. Through fold_loop, fit the pipeline on the training rows of each fold with pipeline_fold_fit, and predict its test rows. The loop resolves each schedule for the fold, and the context holds path_id. When the folds of cv are a timeline and the pipeline needs_previous_weights, the loop runs the folds of the path in sequence and gives each fold the weights of the previous fold. This gives the predictions and est, the estimator that the online arm threaded.
  4. Sort the predictions by their test rows with sort_predictions.

Returns

  • MultiPeriodPredictionResult: The predictions of the path, with the id path_id and the estimator est.

Schedules in the steps of a pipeline

The functions below apply the schedule logic to each step of a pipeline. The check for a schedule looks through every step. So does the replacement of each schedule by its value for the fold, which also unwraps a schedule inside a PipelineStep. A run with no folds sets each schedule step to its default. After the replacement, pipeline_step_factory gives the weights of the previous fold, w_prev, to the optimisation steps.

PortfolioOptimisers.update_time_dependent_step — Function
update_time_dependent_step(est, ctx::TimeDependentContext, all_binds::Bool)

Resolve one Pipeline step for the fold that ctx describes. This is the part of update_time_dependent_estimator that applies to one step.

Algorithm

  1. Resolve an optimisation step, a TimeDependent step and a nested pipeline through update_time_dependent_estimator. A schedule step gives its entry for the fold, an estimator or a precomputed result. An optimisation step resolves its scheduled fields, and a nested pipeline resolves its own steps.
  2. Resolve a PipelineStep that wraps a schedule to the entry of step 1, with no wrapper. The wrapper only declares the slot that dispatch cannot infer, and run_step dispatches on the entry. An entry can be a result, and a wrapper cannot hold one.
  3. Return a PipelineStep that wraps a callable unchanged. Resolve the estimator of any other PipelineStep by this algorithm, giving newest. Rebuild the wrapper around newest when newest is a new value.
  4. Return every other step unchanged.

Validation

  • Everything update_time_dependent_estimator refuses. This includes an entry of a callable schedule that is not an optimiser.

The rows of a pipeline fold

A fold of returns data records its rows on its PredictionResult when every fitted step of the pipeline keeps the observations of the window. A realised factor_attribution of the cross-validation reads those rows to find the block rows of each fold. A preprocessing step states whether it keeps them with keeps_observations.

PortfolioOptimisers.fitted_step_keeps_observations — Function
fitted_step_keeps_observations(fitted, data::Prices_RR) -> Bool

Return true when one fitted step of a pipeline keeps every observation of a data window.

It is the companion of apply_fitted_step, and it reads the same data levels. A step whose data level is the level of data changes the window, so it keeps the observations exactly when keeps_observations says so. A preprocessing step of the other level, a PricesToReturns step on returns data, and the result of every other step, such as a prior or an optimisation result, return the window unchanged, so they keep the observations. A nested PipelineResult keeps them when each of its own steps does.

Arguments

  • fitted: The fitted result of one step, from a PipelineResult.
  • data: The data window that the step receives.

Returns

  • flag::Bool: true when the window that the step returns holds the observations of data, in the same order.

PortfolioOptimisers.apply_fitted_steps_keeping — Function
apply_fitted_steps_keeping(results::Tuple, data::Prices_RR) -> (data′, kept::Bool)

Apply the fitted steps of a pipeline to a data window, in step order, and say whether the window kept its observations.

It is apply_fitted_steps with one more answer. The returns-data method of predict(res::PipelineResult, data::AbstractReturnsResult, window) reads kept, and the fold records its rows when it is true.

Algorithm

  1. Set kept to true.
  2. For each fitted result f in results, in step order, set kept to false when fitted_step_keeps_observations is false for f and the current data. Then replace data with apply_fitted_step(f, data).

  • results: The fitted result of each step, from a PipelineResult.
  • data: The data window.

Returns

  • data′: The changed data window, as apply_fitted_steps returns it.
  • kept::Bool: true when every step keeps the observations of the window.

PortfolioOptimisers.pipeline_fold_prediction — Function
pipeline_fold_prediction(pred::PredictionResult, test_idx::Colon, kept::Bool)
pipeline_fold_prediction(pred::PredictionResult, test_idx::VecInt, kept::Bool)

Record the rows of a pipeline fold on its prediction, when the fitted steps kept them.

The weight-level predict of the optimisation result receives the window after the fitted steps, so it cannot know the rows of the window and records idx = nothing. When every step kept the observations, the rows of the window are test_idx, and the method records them. A realised factor_attribution of the cross-validation then finds the block rows of each fold by position. A whole-sample prediction, test_idx = :, records no rows, as the whole-sample predict of an optimisation result does.

Arguments

  • pred: The prediction on the changed window.
  • test_idx: The rows of the input data in the window, or :.
  • kept: Whether the fitted steps kept every observation of the window, from apply_fitted_steps_keeping.

Validation

  • When kept is true, the prediction has one observation for each entry of test_idx. Raises a DimensionMismatch, because a step answered keeps_observations with true and changed the number of observations.

Returns

  • pred::PredictionResult: pred with idx = test_idx when kept is true, and pred itself otherwise.
