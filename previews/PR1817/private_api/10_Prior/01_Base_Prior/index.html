An estimator whose pe field is typed AbstractLowOrderPriorEstimator_F_AF admits the AbstractLowOrderPriorEstimator_AF part of that union. A member of that part reads factor returns only when the caller gives them. The type limits the returns that the estimator reads, and does not tell whether its result carries a regression. An estimator that projects factor moments through the loadings needs the regression, and must check for it.

A prior has pr.rr === nothing for one cause: no estimator in the chain computed a regression, as in EntropyPoolingPrior(; pe = EmpiricalPrior()). PortfolioOptimisers.prior_regression_remedy — Constant
prior_regression_remedy

The cause and the remedy of every error that says that a prior carries no factor block.

The string is written once, so the two kinds of consumer give the same cause and remedy. The consumers need the loadings for different purposes. Some project factor moments through the loadings, and some plot them. Each consumer gives its own first sentence in the lead of assert_prior_regression. No consumer writes the cause again. A prior has rr === nothing for one cause, and one remedy corrects it. Both follow from the rule that every wrapper estimator passes on rr and the factor block fpr.

Which errors carry it

Two errors carry it. They are the two ways in which a caller can ask for loadings that no estimator computed.

  • The IsNothingError that assert_prior_regression raises. An estimator raises it when its pe field returns a prior with rr === nothing. A plotting function in the factor space raises it when it receives such a prior. Each caller gives its own lead, and adds this string unchanged after it.
  • The IsNothingError that constraint_space_basis raises when a factor exposure constraint has no basis for its loadings. The space states no basis, and the prior carries no loadings. That message starts with its own sentences about the space, and then adds this string, because the remedy for the prior is the same.

Derive the Investable Mask of a prior result, which is true at every asset whose moments are finite.

A Prior Estimator fits on the coverage universe and returns a result on the full asset universe. An asset that it could not estimate carries NaN in mu and on the diagonal of sigma. This function derives the mask, and no prior result stores it in a field. A caller that needs the mask calls this function. A caller that reduces a result keeps the mask that it received. A reduced result cannot give the mask again, because its mu is finite at every asset.

When every asset is investable, the function returns nothing, and not a mask of true values. With nothing, a universe with no asset to exclude takes the same path as before the mask existed. That path has no reduction, no expansion and no allocation.

The function does not read the entries of sigma outside the diagonal. A non-investable asset can carry NaN in all of its row and its column. The diagonal alone decides, so the mask costs one pass over two vectors.

Algorithm

  1. Take the elementwise conjunction of isfinite.(pr.mu) and isfinite.(diag(pr.sigma)).
  2. Raise an IsEmptyError when the conjunction holds no true. An optimisation over no asset has no answer. A problem with no asset that goes further fails at a point far from its cause.
  3. Return nothing when the conjunction holds no false.
  4. Otherwise, return the conjunction.

Arguments

  • pr: Prior result.

Validation

  • At least one asset must be investable.

Returns

  • imsk::Option{BitVector}: true at every investable asset, or nothing when every asset is investable.

PortfolioOptimisers.investable_views — Function
investable_views(pr::AbstractPriorResult, sets::Nothing) -> Tuple
investable_views(pr::AbstractPriorResult, sets::UniverseSets) -> Tuple

Derive the Investable Mask of a fitted prior, and give a view builder the universe on which it can write rows.

A view is a dense linear form over the asset axis. A departed asset carries NaN in mu and on the diagonal of sigma. A[i] == 0 does not remove the NaN from a row, because 0 * NaN is NaN. A view that names only active assets gets a NaN row, the same as a view that names the departed asset. The solver receives a row of NaN, and the fit fails with an error that names a wrong cause. The fix is to build the row on the investable columns only. Every optimiser takes the same reduction at its entry, port_opt_view of the prior result at findall(imsk). That reduction gives the same bits as a prior reduced by hand.

The two prior families that take views both reduce here. Each does its own work after the reduction. A row of entropy pooling is over the observations, so its solved probabilities have no asset axis, and nothing expands back. The moments come from the wrapped prior after its new fit, which already holds the NaN values of the full universe. A Black-Litterman posterior is a pair of moments over the reduced assets. The estimator must write it back into a NaN frame of the full width with expand_moment before it returns. For this difference, this function returns the index to the caller.

This function also adds the Non-Investable Axis to the sets that it gives the builders, with non_investable_sets after port_opt_view. The order matters, because the view drops the axis, so that a subproblem does not get the departures of its parent. With the axis, a builder can tell a departed name from a wrong name. It drops the row of a departed name with no message. For a wrong name, the strict_diagnostic rule applies.

The method selects on sets by dispatch, and on the mask by a condition, for these reasons:

  • sets is a field of a @concrete estimator. Whether it is nothing is a fact of its type, fixed for each instance. Two methods let the compiler select at no cost, and keep the returned sets a concrete UniverseSets. One method over Option{<:UniverseSets} returns a Union of values. The view builders declare sets::UniverseSets, so JET reports a missing method for the Nothing part at every builder call site, though no call reaches it.
  • investable_mask returns a Union{Nothing, BitVector} that the data decides. Julia splits a Union of two types and compiles the two cases in this branch. A dispatch on it gives nothing more, and adds a unit to the file.

When sets is nothing, the method returns at once, whatever the mask. There is nothing to build and nothing to reduce, because the constructor of an estimator that takes views refuses nothing sets when it holds a view. When every asset is investable, the method returns its arguments unchanged. A fit with no gap then reads two vectors once and allocates nothing.

Algorithm

  1. When sets is nothing, return nothing, sets and no departed names. The field type of the estimator selects this method.
  2. Otherwise, derive the Investable Mask from the fitted prior with investable_mask. When it is nothing, return nothing, sets and no departed names.
  3. Read the asset universe from sets.dict[sets.xkey], and check it against the mask.
  4. Read the departed names with non_investable_names.
  5. Take a port_opt_view of sets at findall(imsk), and add the Non-Investable Axis to it with non_investable_sets. Return the mask, the new sets and the departed names.

Arguments

  • pr: Prior result.
  • sets: The UniverseSets of the estimator, or nothing.

Validation

  • length(sets.dict[sets.xkey]) == length(imsk). Otherwise, raises a DimensionMismatch that names both counts, in place of the BoundsError that the complement raises.

Returns

  • (imsk, sets, ni): The Investable Mask or nothing, the reduced sets that carry the Non-Investable Axis, and the departed names. investable_prior takes its view at the mask, and expand_moment writes back through it. A caller that reduces and expands needs nothing more.

Record on a prior the observations of the returns data that its fit kept after a Shared Series cut.

A fit drops each observation with a Shared Series gap before it starts, see shared_series_view and shared_series_buffer. After the cut, no part of the prior states which observation of the data each of its rows is. The function writes two records:

  • ss_gaps, the marks of the dropped observations, one for each of the T observations of the data. A reader that holds the data pairs the rows of X with its own rows through the marks, see shared_series_kept_rows.
  • The row key of the factor model block. The batch verb counts the position of each row among the observations that it kept, and kept row k is observation rows[k] of the data. The function replaces each position with its observation, so that a realised factor_attribution of a cross-validation over the same data matches the correct rows. A key of positions matches each row after a gap to the next row, and raises no error. The timestamps come from the kept rows, so they need no change.

prior calls it after it fits on the returns data, and after it reads out a sample buffer. An optimiser calls it on the prior that it fits after its own cut, see shared_series_solve.

Algorithm

Julia selects the method by the types of the arguments. With rows, the method does these steps:

  1. Mark every one of the T observations as dropped. Call the marks ss_gaps.
  2. Remove the mark from the observations that the fit kept. A prior that an optimiser fits on its cut data can already hold marks of the length(rows) kept observations. Then remove the mark only from the rows at the positions that those marks keep, so that the two cuts combine.
  3. Map the row key of the factor model block through rows with map_row_positions. Forward the key and ss_gaps onto pr with forward_prior. A HighOrderPrior forwards the record of the LowOrderPrior that it wraps.

Arguments

  • pr: The prior that the fit returned.
  • rows: The observations that the fit kept, from shared_series_rows, or nothing when it kept every observation.
  • T: The number of observations of the data that the fit received.
  • state: The sample buffer that a new fit read. Its kept rows are those of buffer_kept_rows, and its observations are its n rows.

Validation

  • The rules of assert_shared_series_gaps on the marks.

Returns

  • pr::AbstractPriorResult: pr itself when the fit kept every observation, and otherwise pr with the marks and with the positions of its block mapped through rows.

PortfolioOptimisers.shared_series_kept_rows — Function
shared_series_kept_rows(pr, T::Integer) -> Option{Vector{Int}}

Return the observations that a prior kept after a Shared Series cut, when the returns data of a reader is the data that the prior read.

A reader holds T observations of the returns data. When T equals the number of marks in pr.ss_gaps, the reader holds the data that the prior read. The rows of pr.X are then the last of the observations that the marks keep. Otherwise, the reader holds the data after the same cut, or data with no record. The rows of pr.X are then its last observations, which was the rule of every reader before the record existed. The marks are nothing when the prior dropped no observation, so the cut data never has as many observations as the marks.

Arguments

  • pr: The prior result, the returns data, a prior estimator, or nothing. Only a prior result holds marks: a LowOrderPrior in its field ss_gaps, and a HighOrderPrior in the low order prior that it wraps.
  • T: The number of observations of the returns data that the reader holds.

Returns

  • rows::Option{Vector{Int}}: The positions of the kept observations in the data of the reader, or nothing when the reader pairs the last rows.
