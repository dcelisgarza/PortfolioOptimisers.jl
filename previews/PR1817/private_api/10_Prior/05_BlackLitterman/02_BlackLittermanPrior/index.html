PortfolioOptimisers.calc_omega — Function
calc_omega(::Nothing, P::MatNum, sigma::MatNum) -> LinearAlgebra.Diagonal
calc_omega(views_conf::Number, P::MatNum, sigma::MatNum) -> LinearAlgebra.Diagonal
calc_omega(views_conf::VecNum, P::MatNum, sigma::MatNum) -> LinearAlgebra.Diagonal

Compute the Black-Litterman view uncertainty matrix Ω.

Each method selects one shape of views_conf and computes one branch of the closed forms below. ::Nothing gives the diagonal with no scale, ::Number gives the same diagonal with one scale for all the views, and ::VecNum gives the same diagonal with one scale for each view.

Mathematical definition

Let $\mathbf{P}$ be the $K \times N$ view matrix and $\mathbf{\Sigma}$ the $N \times N$ prior covariance matrix. The view uncertainty matrix $\mathbf{\Omega}$ for each views_conf variant is:

\[\begin{align} \mathbf{\Omega} &= \mathrm{Diag}(\mathbf{P} \mathbf{\Sigma} \mathbf{P}^\intercal) \quad (\text{no confidence})\,. \end{align}\]

\[\begin{align} \mathbf{\Omega} &= \left(\frac{1}{v} - 1\right) \mathrm{Diag}(\mathbf{P} \mathbf{\Sigma} \mathbf{P}^\intercal) \quad (\text{scalar confidence } v)\,. \end{align}\]

\[\begin{align} \mathbf{\Omega} &= \mathrm{Diag}\!\left(\left(\frac{1}{\boldsymbol{v}} - \boldsymbol{1}\right) \odot \mathrm{diag}(\mathbf{P} \mathbf{\Sigma} \mathbf{P}^\intercal)\right) \quad (\text{vector confidence } \boldsymbol{v})\,. \end{align}\]

Where:

  • $\mathbf{\Omega}$: $K \times K$ diagonal view uncertainty matrix.
  • $\mathbf{P}$: $K \times N$ views matrix.
  • $\mathbf{\Sigma}$: $N \times N$ prior covariance matrix.
  • $v$: Scalar view confidence level.
  • $\boldsymbol{v}$: $K \times 1$ vector of view confidence levels.
  • $\odot$: Element-wise multiplication.

The branch with no confidence is the diagonal uncertainty of the view creation model. bl_preroll multiplies the result by $\tau$, so the two functions together return $\mathrm{Diag}(\mathbf{P}(\tau\mathbf{\Sigma})\mathbf{P}^\intercal)$.

A confidence $v$ scales that diagonal by $1/v - 1$. This is the method of Idzorek in the closed form of Walters. A high confidence makes the view uncertainty smaller, and a low confidence makes it larger. The scale is negative for each $v$ outside $(0, 1)$, and assert_bl_views_conf refuses such a value.

A scalar $v$ gives the same $\mathbf{\Omega}$ as the constant vector of $v$, to the last bit. The two shapes are two forms of one input, and assert_bl_views_conf counts only the vector against the views.

The bound is strict, and it also refuses the two endpoints. $v = 1$ gives $\mathbf{\Omega} = \mathbf{0}$, a view with no uncertainty. Then $\mathbf{P}\tau\mathbf{\Sigma}\mathbf{P}^\intercal + \mathbf{\Omega}$ is singular when $\mathbf{P}$ is rank-deficient. Two identical views over a sample of three assets give a $\mathbf{P}$ of rank one. At $v = 1$ the sum is the constant matrix 1.0021e-6, its determinant is 0.0 and its rank is 1, and the solve raises SingularException. Near the bound the sum is ill-conditioned but not singular: at $v = 1 - 10^{-8}$ the condition number is 2.0e8, and at $v = 0.99$ it is 199. $v = 0$ gives an infinite uncertainty, which has the same effect as no view.

Arguments

  • views_conf:

    • ::Nothing: No confidence. Ω = Diag(P * sigma * P').
    • ::Number: One confidence v for all the views. Ω = (1/v - 1) * Diag(P * sigma * P').
    • ::VecNum: One confidence for each view, the vector v. Ω = Diag((1 ./ v .- 1) .* diag(P * sigma * P')).

  • P: Views matrix, views × n, with one column for each name of the axis that the views update.

  • sigma: Covariance matrix assets × assets.

Returns

  • omega::LinearAlgebra.Diagonal: Diagonal view uncertainty matrix views × views.

Assemble the views, tau and the view uncertainty that the Black-Litterman members share.

axis names the declared axis of the distribution that the views update. Each caller knows it from its own type, not from the views. BlackLittermanPrior uses the default :xkey, the asset axis. A member whose views update the factor distribution passes :tfkey or :cfkey. axis is the last positional argument, because a caller on the asset axis never gives it.

UniverseSets declares two factor axes, so the function accepts three symbols. Each member of the library that updates a factor distribution reads the columns of F, and passes :tfkey. The function accepts :cfkey because the axis exists and a view can update it. No member passes :cfkey now.

axis is the name of a field of UniverseSets, not a key, so a caller states its axis and nothing more. This function reads the key, and only when sets is not nothing. To read sets.tfkey when there is no universe is the same error as to read the universe. A precomputed BlackLittermanViews is the one shape of views that can come with no sets. It resolves no names, and it ignores the sets and the axis.

This function is also where P meets the distribution that it updates, so it checks that their widths agree. A P assembled from names has the correct width. A precomputed BlackLittermanViews resolves no names, and no other site checks its width.

When no view is left, the function returns nothing, for each cause. get_black_litterman_views drops a row that it cannot assemble, and it does not fit the row without the term. Thus a set of views can lose all its rows for different causes:

  • A departure removed the last row.
  • The fit uses a sub-universe that does not hold the names, such as a cluster of a nested optimisation or a subset of a resampling.
  • The caller wrote a typo.

No cause changes the data that is left for the update, so no cause changes the result. The fit continues as if the caller stated no view. Each member states what that means for it through bl_posteriors or bl_view_block.

strict_diagnostic still reports each name that resolves against neither axis, at the site where the assembly reads it. It raises an ArgumentError under strict = true and warns otherwise, and the message names the name and the universe that it failed against. That report names the cause. A refusal here can only name the result, and it cannot tell a typo from a correct name that is outside a sub-universe. The ledger keeps the two cases apart for the report: only a departed name writes into it, and announce_bl_departures reads it to say which case happened.

The returned omega includes $\tau$, so a caller passes it to vanilla_posteriors with no change. calc_omega is homogeneous of degree one in the covariance that it reads. Thus $\tau$ multiplies $\mathbf{P}\tau\mathbf{\Sigma}\mathbf{P}^\intercal$ and $\mathbf{\Omega}$, and it cancels from the posterior mean on each confidence branch. It does not cancel from the posterior covariance. vanilla_posteriors gives the measurement.

Algorithm

  1. Check that axis names a declared axis that a view can update.
  2. Read the universe key from the field axis of sets. When sets is nothing, the key is nothing, because a precomputed views object resolves no name.
  3. Assemble the views with black_litterman_views under that key. The result is blv.
  4. When no view is left, return nothing. The caller decides what a fit with no view gives.
  5. Read P, Q and excl from blv.
  6. Check that the number of columns of P is equal to the number of rows of prior_sigma.
  7. Set tau to pe_tau when it is not nothing, and to 1/T otherwise.
  8. Remove the confidences of the views that step 3 dropped, with remove_excl_views.
  9. Make the view uncertainty matrix from the remaining confidences with calc_omega, and multiply it by tau. Return it as omega, with P, Q and tau.

Validation

  • axis in (:xkey, :tfkey, :cfkey). Raises a DomainError.
  • size(P, 2) == size(prior_sigma, 1), when a view is left. Raises a DimensionMismatch.

Arguments

  • views: The views, a LinearConstraintEstimator of view equations or a precomputed BlackLittermanViews.
  • sets: Sets used to map estimator values to assets.
  • views_conf: The confidence of the views, in (0, 1), or nothing. A number is one confidence for all the views, and a vector holds one confidence for each view that the caller wrote. If nothing, the view uncertainty has no confidence scale, see calc_omega.
  • prior_sigma::MatNum: The prior covariance matrix of the distribution that the views update, n × n over that axis.
  • pe_tau::Option{<:Number}: The tau of the estimator, or nothing. If nothing, the function uses 1/T.
  • T::Real: The effective number of observations of the prior mean, for the default tau = 1/T.
  • datatype: Data type of the result when val is nothing.
  • strict: Whether to throw an error if sets does not contain the desired value in sets.dict[key].
  • axis: The field of sets that names the declared axis that the views resolve against: :xkey for the asset axis, :tfkey for the time-series factor axis, :cfkey for the cross-sectional factor axis. The function reads the key from sets, and only when sets is not nothing.
  • ledger: The Departure Ledger of the entry of the fit, or nothing when no caller collects the drops. The function passes it to black_litterman_views. The ledger tells a set of views that a departure emptied from a set that another cause emptied. Only the report uses this difference, and the result does not.

Returns

  • (; P, Q, tau, omega): A named tuple of:

    • P::MatNum: The view matrix, views × n.
    • Q::VecNum: The view returns, views × 1.
    • tau::Number: The value of tau that the function used.
    • omega::LinearAlgebra.Diagonal: The view uncertainty matrix, multiplied by tau.

  • nothing: The function dropped every view, so the fit continues with no view.

PortfolioOptimisers.bl_posteriors — Function
bl_posteriors(::Nothing, prior_mu::VecNum, prior_sigma::MatNum) -> Tuple
bl_posteriors(blp::NamedTuple, prior_mu::VecNum, prior_sigma::MatNum) -> Tuple

Run the master equations, or return the prior pair when no view is left.

bl_preroll returns nothing when no view row is left. The fit continues and does not refuse. A Black-Litterman posterior with no view is the distribution that the views were to update, so this function returns that distribution.

The function returns the prior pair, not the result of the master equations with an empty $\mathbf{P}$. The difference is not a rounding error. vanilla_posteriors adds the term of estimation error $[(\tau\mathbf{\Sigma})^{-1}]^{-1} = \tau\mathbf{\Sigma}$ to the covariance. With an empty $\mathbf{P}$ it gives $(1 + \tau)\mathbf{\Sigma}$, a covariance wider than the prior, from views that do not exist. With the prior pair, the caller loses the views and nothing more.

BayesianBlackLittermanPrior does not use this function. Its update is a sum of precisions, $\hat{\mathbf{\Sigma}}^{-1} = \mathbf{\Sigma}_f^{-1} + \mathbf{P}^\intercal\mathbf{\Omega}^{-1}\mathbf{P}$, so an empty $\mathbf{P}$ adds zero, and there is no $\tau\mathbf{\Sigma}$ term to widen the covariance. Its result with no view is thus the algebra of an empty block from bl_view_block. That result is not its wrapped prior. By Woodbury, it is $\mathbf{\Sigma}_a + \mathbf{M}\mathbf{\Sigma}_f\mathbf{M}^\intercal$ and $\mathbf{M}\boldsymbol{\mu}_f + \mathbf{b}$, the moments that the factor model gives. That member has no unchanged prior to return, because it changes its wrapped prior with or without views.

The function copies the covariance. Each caller passes the result to matrix_processing!, which writes in place, and the function must not change a prior result that a caller still holds.

The two methods split by dispatch. The result of bl_preroll is nothing or one concrete NamedTuple, so the compiler splits that small union at the call.

Arguments

  • blp: The result of bl_preroll, or nothing.
  • prior_mu: The prior mean of the distribution the views update.
  • prior_sigma: The prior covariance of that distribution.

Returns

  • (posterior_mu, posterior_sigma)::Tuple{VecNum, MatNum}: The posterior pair, or the prior pair when there is no view.

bl_view_block(blp::NamedTuple, ::Integer, ::DataType) -> Tuple

Return the P, Q and omega of a view system, or a block with no row when the system has no view left.

Two members use this function and not bl_posteriors, for two different reasons.

AugmentedBlackLittermanPrior puts a block of asset views above a block of factor views, and each half can become empty alone. An empty half adds no row, and the stack does not change to the prior. The other half still holds views that the caller stated and that resolve, so the joint posterior still uses them. The prior stack discards those views. Only when both halves are empty is no view left, and that member then reads the two results itself and takes the prior stack. The empty block is 0 × n and not a row of zeros, so the stack holds no false view, and aug_Q has one entry less, not an entry of zero.

BayesianBlackLittermanPrior has one view system and no stack. It uses an empty block because, for it, the algebra of an empty block is the result with no view. Its update is a sum of precisions, $\hat{\mathbf{\Sigma}}^{-1} = \mathbf{\Sigma}_f^{-1} + \mathbf{P}^\intercal\mathbf{\Omega}^{-1}\mathbf{P}$, so a 0 × n $\mathbf{P}$ adds zero, and there is no term of estimation error $\tau\mathbf{\Sigma}$ to widen the covariance. The members that run vanilla_posteriors have that term, and that is why they use bl_posteriors. The result is not the wrapped prior of that member but $\mathbf{\Sigma}_a + \mathbf{M}\mathbf{\Sigma}_f\mathbf{M}^\intercal$, the moments that its factor model gives, and the member has no unchanged prior to return.

Arguments

  • n: The width of the axis of this system, for the empty P.
  • datatype: The numeric type of the block.

Returns

  • (P, Q, omega)::Tuple: The view matrix, the view returns and the view uncertainty, with no row when the system has no view left.

The reduction resolves the view names of the caller against the universe that remains. PortfolioOptimisers.vanilla_posteriors — Function
vanilla_posteriors(tau::Number, prior_mu::VecNum, prior_sigma::MatNum,
                   omega::MatNum, P::MatNum, Q::VecNum)

Compute the Black-Litterman posterior mean and covariance.

The function does not add a risk-free rate. Each Black-Litterman prior estimator adds its own rf once, through apply_rf, which states where each member adds it.

The two equations below are the inverse-free form of the master equations. They are algebraically equal to the form on prior: the covariance term is the Woodbury expansion of $\left[(\tau\mathbf{\Sigma})^{-1} + \mathbf{P}^\intercal\mathbf{\Omega}^{-1}\mathbf{P}\right]^{-1}$. The function uses this form because it solves against one $K \times K$ matrix, and the other form inverts three $N \times N$ matrices.

Mathematical definition

Let $\boldsymbol{\Pi}$ be the prior mean, $\mathbf{\Sigma}$ the prior covariance, $\tau$ the scaling parameter, $\mathbf{P}$ the view matrix, $\boldsymbol{q}$ the view vector, and $\mathbf{\Omega}$ the view uncertainty matrix:

\[\begin{align} \hat{\boldsymbol{\mu}}_{BL} &= \boldsymbol{\Pi} + \tau\mathbf{\Sigma}\mathbf{P}^\intercal \left(\mathbf{P}\tau\mathbf{\Sigma}\mathbf{P}^\intercal + \mathbf{\Omega}\right)^{-1} (\boldsymbol{q} - \mathbf{P}\boldsymbol{\Pi})\,. \end{align}\]

\[\begin{align} \hat{\mathbf{\Sigma}}_{BL} &= \mathbf{\Sigma} + \tau\mathbf{\Sigma} - \tau\mathbf{\Sigma}\mathbf{P}^\intercal \left(\mathbf{P}\tau\mathbf{\Sigma}\mathbf{P}^\intercal + \mathbf{\Omega}\right)^{-1} \mathbf{P}\tau\mathbf{\Sigma}\,. \end{align}\]

Where:

  • $\hat{\boldsymbol{\mu}}_{BL}$: Black-Litterman posterior mean vector.
  • $\hat{\mathbf{\Sigma}}_{BL}$: Black-Litterman posterior covariance matrix.
  • $\boldsymbol{\Pi}$: $N \times 1$ prior (equilibrium) expected returns.
  • $\mathbf{\Sigma}$: $N \times N$ prior covariance matrix.
  • $\tau$: Scaling parameter for the uncertainty in the prior.
  • $\mathbf{P}$: $K \times N$ views matrix.
  • $\boldsymbol{q}$: $K \times 1$ views vector.
  • $\mathbf{\Omega}$: $K \times K$ view uncertainty matrix.

$\tau$ occurs in both equations, but it does not move the posterior mean when $\mathbf{\Omega}$ comes from bl_preroll. calc_omega is homogeneous of degree one in the covariance that it reads, and bl_preroll multiplies its result by $\tau$. Thus the gain $\tau\mathbf{\Sigma}\mathbf{P}^\intercal(\mathbf{P}\tau\mathbf{\Sigma}\mathbf{P}^\intercal + \mathbf{\Omega})^{-1}$ has one $\tau$ outside the inverse and one inside it, and the two cancel. On a $200 \times 3$ sample with two views, over $\tau \in \{1/200, 0.05, 0.5\}$, the posterior mean moves by at most 3.3e-19 on each confidence branch: no confidence, the scalar 0.4, and the vector [0.25, 0.75]. The posterior covariance does move, because $\mathbf{\Sigma} + \tau\mathbf{\Sigma} - \ldots$ holds a $\tau$ that does not cancel. Its excess over $\mathbf{\Sigma}$ has trace 2.013e-7, 2.013e-6 and 2.013e-5 at $\tau = 0.001$, 0.01 and 0.1, which is linear in $\tau$ to three figures.

A view that repeats the prior changes nothing. With $\boldsymbol{q} = \mathbf{P}\boldsymbol{\Pi}$ the residual $\boldsymbol{q} - \mathbf{P}\boldsymbol{\Pi}$ is zero, so the posterior mean is equal to the prior mean. On the same sample the difference is 0.0.

Algorithm

  1. Multiply the prior covariance by tau and by the transpose of P. The result is v1, the $N \times K$ matrix $\tau\mathbf{\Sigma}\mathbf{P}^\intercal$.
  2. Multiply P by v1, and add the view uncertainty. The result is v2, the $K \times K$ matrix $\mathbf{P}\tau\mathbf{\Sigma}\mathbf{P}^\intercal + \mathbf{\Omega}$. This is the only matrix that the function solves against.
  3. Subtract P * prior_mu from Q. The result is the view residual v3.
  4. Solve v2 against v3, multiply the solution by v1, and add it to prior_mu. The result is posterior_mu.
  5. Solve v2 against the transpose of v1, multiply the solution by v1, and subtract it from prior_sigma + tau * prior_sigma. The result is posterior_sigma.

Arguments

  • tau: The scale of the uncertainty of the prior mean.
  • prior_mu: The prior mean of the distribution that the views update.
  • prior_sigma: The prior covariance of that distribution.
  • omega: The view uncertainty matrix, multiplied by tau.
  • P: The view matrix, views × n.
  • Q: The view returns, one for each view.

Returns

  • posterior_mu::VecNum: The posterior mean.
  • posterior_sigma::Matrix{<:Number}: The posterior covariance matrix.

PortfolioOptimisers.apply_rf — Function
apply_rf(rf::Number, mu::VecNum)

Add the risk-free rate to a Black-Litterman mean.

apply_rf is the one site that reads the rf field of a Black-Litterman prior estimator. Each of the four members, BlackLittermanPrior, BayesianBlackLittermanPrior, FactorBlackLittermanPrior and AugmentedBlackLittermanPrior, calls it once. No function subtracts the rate.

The four members keep three rules:

  • The estimator adds the rate once. No method adds it twice.
  • The update uses the scale of the views. The update forms the residual Q - P * mu, so the prior mean must have the scale of Q, which is a total return. A mean from a wrapped prior estimator has that scale, and it goes to the update with no change. The equilibrium mean of equilibrium_mu is only a risk premium. Thus the two members that can make one add the rate to it before the update, on the axis of that mean. If the prior mean has no rate, the update compares the views with the wrong level, so these members add the rate first and not last.
  • The wrapped prior does not change. The estimator does not fit a wrapped prior again and does not scale its mean, so a risk-free rate that a wrapped prior applied stays in its mean.

Each member calls it at one site:

  • BlackLittermanPrior and BayesianBlackLittermanPrior have no equilibrium branch, so they have no mean to convert. They add the rate to the posterior asset mean as the last step, and rf shifts the result.
  • FactorBlackLittermanPrior and AugmentedBlackLittermanPrior call it on the equilibrium mean, and only when l is not nothing. When l is nothing, they do not read rf, and it has no effect on the result.

A measurement shows that the estimator adds the rate once. Two BlackLittermanPrior fits over one $200 \times 3$ sample, with different rf and no other difference, give posterior means whose difference is rf in each entry, to the last bit. At rf = 0.03 the difference is [0.03, 0.03, 0.03], and max|diff - rf| is 0.0.

Algorithm

  1. Add rf to every entry of mu, and return the result. The input is not modified.

Arguments

  • rf: Risk-free rate.
  • mu: Expected returns vector. It is a posterior asset mean for the two members with no equilibrium branch, and a prior equilibrium mean for the two members that have one.

Returns

  • mu::VecNum: mu shifted by rf.

PortfolioOptimisers.bl_posterior — Function
bl_posterior(
    pe::BlackLittermanPrior,
    prior_model::AbstractPriorResult,
    strict::Bool;
    kwargs...
) -> Union{HighOrderPrior, LowOrderPrior}

Update the result of the wrapped prior of a BlackLittermanPrior with the views of the estimator.

This function holds each step of the estimator after the wrapped prior gives its result. The batch method calls it with the result of a fit over the matrix of the caller. prior(pe) with no data calls it with the result of the fold of the wrapped prior. The function reads no returns matrix that the result does not hold: T, the axis and the matrix for the processing all come from prior_model. Both routes use this one body, so they cannot become different.

Algorithm

  1. Derive the Investable Mask and the reduced view universe with investable_views. A view is a dense linear form over the asset axis, so one departed asset makes each entry of omega NaN.
  2. Refuse a precomputed view matrix over a universe with a departed asset, with assert_bl_precomputed_universe.
  3. View the prior result at the mask with investable_prior, and read posterior_X, prior_mu and prior_sigma from it.
  4. Assemble P, Q, tau and omega with bl_preroll. Its T is the number of rows of prior_model.X.
  5. Run the update with bl_posteriors, and add pe.rf once with apply_rf.
  6. Process the reduced covariance with sample_matrix_processing!, at the count of the covariance of the wrapped prior, before the expansion, because a frame with NaN entries has no factorisation.
  7. Report the departures once with announce_bl_departures.
  8. Expand both moments to the universe of the caller with expand_moment.
  9. Forward each field of the wrapped result with forward_prior, and drop only chol.

Arguments

  • pe: Black-Litterman prior estimator.
  • prior_model: The result of the wrapped prior.
  • strict: If true, a view name that does not resolve raises an error. If false, it warns.
  • kwargs...: More keyword arguments, for the matrix processing.

Returns

  • pr::AbstractPriorResult: The wrapped result, with the posteriors in place of its two moments.

PortfolioOptimisers.fold_prior_step — Method
fold_prior_step(pe::BlackLittermanPrior, rd::ReturnsResult,

Fold the observations of a ReturnsResult into a BlackLittermanPrior. The function forwards rd and its marks to the wrapped prior.

This is the forwarding form of fold_prior_step, the fold that partial_fit! uses for each prior over a ReturnsResult. The outer prior keeps no rows. The wrapped prior keeps them, so the route of the wrapped prior decides what the step uses. The estimation mask and the Panel Fields reach it with no change, and it refuses what its route cannot use.

Arguments

  • pe: The Black-Litterman prior estimator.
  • rd: The returns result to use.
  • gaps: One mark for each observation of rd, true at an observation with a Shared Series gap, or nothing.

Validation

  • Each condition that the fold of pe.pe over rd checks.

Returns

  • pe: A new estimator, with the folded wrapped prior.
