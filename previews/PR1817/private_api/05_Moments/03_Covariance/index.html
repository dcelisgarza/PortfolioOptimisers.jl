Covariance: private API

The weights of a portfolio and the covariance matrix of its assets give the portfolio variance, which the classic Markowitz portfolio [32] uses as its measure of risk. The entries below support the two sample estimators of the covariance and the correlation, GeneralCovariance and Covariance.

General covariance

GeneralCovariance calls a StatsBase covariance estimator through the functions below. They retry a call without the keywords that the estimator does not take, and they make a lazy observation matrix dense before a weighted call.

PortfolioOptimisers.densify — Function
densify(X::MatNum) -> MatNum

Materialise a lazy or sparse observation matrix as a dense Matrix.

The weighted moment methods of StatsBase take a DenseMatrix. A Transpose, an Adjoint, a SubArray or a sparse matrix does not match them. Without a mean, the call raises a MethodError, and the caller can recover from it. With a mean, the caller cannot recover. cov(::SimpleCovariance, X, w; mean = mu) forwards four positional arguments as covm(X, mu, w, dims). When the DenseMatrix method does not match, that call resolves to Statistics.covm(x, xmean, y, ymean, vardim), which is the cross-covariance of X and the weight vector. It returns an N × 1 matrix in place of an N × N matrix, and raises no error. robust_cov and robust_cor densify X before every weighted call, so neither failure can happen.

Algorithm

  1. When X is a DenseMatrix of numbers or of JuMP scalars, return it unchanged.
  2. Otherwise return Matrix(X), a dense copy.

Arguments

  • X: Data matrix observations × assets if the dims keyword does not exist or dims = 1, assets × observations when dims = 2.

Returns

  • X::MatNum: X itself when it is already a dense Matrix, and Matrix(X) otherwise.

PortfolioOptimisers.library_covariance_estimator — Function
library_covariance_estimator(ce::AbstractCovarianceEstimator) -> AbstractCovarianceEstimator
library_covariance_estimator(ce::StatsBase.CovarianceEstimator) -> GeneralCovariance

Returns a nested covariance estimator in a form that accepts all the calls that the library makes to a nested estimator.

A field bound to StatsBase.CovarianceEstimator accepts an estimator that the library does not own, such as StatsBase.SimpleCovariance(). The library calls a nested estimator in these three ways, and StatsBase has no method for any of them:

  • With its own keywords, such as iv, ivpa and active_mask.
  • With an Asset Panel argument.
  • Through Statistics.var and Statistics.std.

Thus a verb that passes a call to a nested estimator calls it through this function. The two methods select one branch each:

  • The function returns an AbstractCovarianceEstimator without change, so it still gets all the keywords.
  • The function wraps all other StatsBase.CovarianceEstimator types in a GeneralCovariance without weights. The wrapper is an AbstractCovarianceEstimator, so the Asset Panel methods and the diagonal methods of var and std accept it. Its cov and cor go through robust_cov and robust_cor. These call the wrapped estimator with only dims and mean when its method does not take the other keywords. The wrapper returns what the bare estimator returns for the same dims and mean.

Arguments

  • ce: Covariance estimator.

Returns

  • ce: ce without change, or GeneralCovariance(; ce = ce).

PortfolioOptimisers.covariance_centre_and_estimator — Function

    dims,

Get the centring vector and the inner covariance estimator for a Covariance method.

The four methods of Statistics.cov and Statistics.cor that take a Covariance get one centre and one inner estimator from this function, so one rule applies ce.w to the centre and to the deviations.

Algorithm

  1. Get the centre mu from ce.me and ce.w with weighted_centre. It uses mean if the caller gave one. ce.w gets to ce.me through factory, so the centre has the weights of the deviations.
  2. If ce.w is nothing, take ce.ce without change.
  3. If ce.w is not nothing, send ce.ce through factory_child with ce.w. An estimator of the library takes the weights. A StatsBase.CovarianceEstimator that the library does not own does not change, because no verb of the library reads its weights.

Step 2 is for performance and is not a second contract. ce.w is a field, so its type decides the branch. The step stops a windowed loop from a rebuild of the estimator tree of ce in each window. A ce.ce with its own weights keeps them when ce.w is nothing, and ce.w replaces them when it is not. factory does the same on all other paths.

Incremental fit

The full-moment sample covariance can also take the observations one at a time. Both estimators use one state type, because they update the same three quantities: the observation count, the mean, and the sum of the outer products of the deviations from the mean. partial_fit! returns a new estimator whose cache field holds that state, and cov(ce) computes the estimate from it, with no data.

PortfolioOptimisers.CovarianceState — Type
struct CovarianceState{__T_n, __T_mu, __T_M, __T_cvg} <: AbstractPartialFitState

Holds the observation count, the running mean and the co-moment accumulator of an incremental covariance fit.

It is the state of GeneralCovariance and of Covariance{<:Any, <:Any, <:FullMoment} under partial_fit!. One struct serves both, because the two estimators run the same recursion over the same three quantities. M is the accumulator $\sum_t (\boldsymbol{r}_t - \hat{\boldsymbol{\mu}}) (\boldsymbol{r}_t - \hat{\boldsymbol{\mu}})^{\intercal}$ and not the covariance, so cov(ce::GeneralCovariance, state::CovarianceState) divides it by the count, or by the count less one when the inner StatsBase.SimpleCovariance is corrected.

Fields

  • n: Number of observations folded into the state.
  • mu: Running mean of the observations folded into the state, assets × 1.
  • M: Running second-moment accumulator of the observations folded into the state, about mu.
  • cvg: Optional CoverageCounts, the per-cell denominators and the per-asset records of an available-case fold. It is nothing when the estimator holds no CoveragePolicy, so the plain state costs nothing.

Constructors

CovarianceState(;    n::Integer = 0,    mu::VecNum,    M::MatNum = zeros(eltype(mu), length(mu), length(mu)),    cvg::Option{<:CoverageCounts} = nothing) -> CovarianceState

Keywords correspond to the struct's fields. A state seeded for N assets is CovarianceState(; mu = zeros(N)), which partial_fit! builds when the cache field of the estimator holds nothing.

Validation

  • n >= 0. A DomainError is thrown otherwise.
  • !isempty(mu). An IsEmptyError is thrown otherwise.
  • Every entry of mu and of M is finite. An IsNonFiniteError is thrown otherwise.
  • size(M) == (length(mu), length(mu)). A DimensionMismatch is thrown otherwise.

View parameters

  • mu: Sliced to the selected indices through port_opt_view.
  • M: Sliced to the selected indices on both axes through port_opt_view.

Available-case fit

With a CoveragePolicy in its cvg field, the estimator computes the covariance of each pair of assets from the rows that the pair shares, where both returns are finite and both assets are active. Without a policy, it computes the ordinary sample covariance over the assets that have no gap in the window. PortfolioOptimisers.coverage_covariance selects one of the two fits from the type of the cvg field.

coverage_covariance(
    f,
    ce::Covariance{<:Any, <:Any, <:SemiMoment},
    cvg::CoveragePolicy,
    X::AbstractMatrix{<:Union{Number, AbstractJuMPScalar}};
    dims,
    mean,

    strict,
    kwargs...
) -> Any

The CoveragePolicy method of the SemiMoment arm of coverage_covariance is the available-case arm. It makes two passes over the block and does not fold, because a semi-covariance has no incremental recursion. The clip is about a centre that the whole window sets, so a new observation changes all the past terms.

The centre is the available-case mean of each asset, over only the finite and active observations of that asset. It is not the mean of the pair, which the FullMoment arm uses. The plain path has the same asymmetry. It takes the clip about a centre, and the co-moment about zero.

Algorithm

  1. Check dims. Refuse a ce.me or a ce.w that holds observation weights, with assert_partial_fittable. Refuse a mean from the caller.
  2. Read the valid entries of the block with coverage_valid_block.
  3. Centre each asset on its available-case mean. Clip the deviations at zero, and set the invalid entries to zero.
  4. Take the numerator as the cross product of the clipped block, and the denominator as the cross product of the valid mask, which counts the observations of each pair.
  5. Admit the assets with coverage_admission. Then peel the assets of the undetermined pairs with coverage_peel, which gives a warning, or refuses them under strict.
  6. Divide and put the result in a frame with coverage_divide. Rescale the result to a unit diagonal when the verb is Statistics.cor.

PortfolioOptimisers.gap_fill_value — Method
gap_fill_value(ce::Covariance{<:Any, <:Any, <:Any, <:Any, <:CoveragePolicy}) -> Float64

Return NaN, so that a gapped sample gets to the available-case arm of a Covariance with its gaps.

A Covariance with a CoveragePolicy fits each pair on the observations at which its two assets are finite and active. coverage_covariance states this. A finite fill value makes a gapped cell into an observation, and the pair then reads a return that the asset did not have. The consumer passes the sample without change, together with the active mask that explains each gap. A Covariance with no policy refuses a gap itself, so it keeps the fallback of zero.

A wrapper that passes the sample on, such as PortfolioOptimisersCovariance, returns the same value as this method, so the wrapper reads a gapped sample when the Covariance in it holds a policy.

Arguments

  • ce: The covariance estimator, with a CoveragePolicy in its cvg field.

Returns

  • fv::Float64: NaN.
