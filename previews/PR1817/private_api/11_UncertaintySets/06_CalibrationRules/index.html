PortfolioOptimisers.AbstractDrawdownSeries — Type
abstract type AbstractDrawdownSeries <: AbstractCalibrationSeries

Names a drawdown series, the quantity that a drawdown measure prices.

A drawdown is a function of the path of one series, so a rule makes it per column and never per row. The two members use different compounding of the path. They are the series that absolute_drawdown_vec and relative_drawdown_vec make.

A drawdown series is not positive, so it has one end. So a rule that answers per end refuses a head key under this family. The refusal is a fact about the quantity and not about the sample.

The tail of a drawdown series depends on the record. A drawdown is a running function of the path, so its law over a finite record is not the law of one step. So a rule that reads the shape of a series reads a different shape here. A sample with a strong drift lets the drawdown process become stationary, and its drawdown series has a heavier tail than its returns. A sample with a weak drift gives the range of the path over the record, and that range has a thinner tail than the law of one step. Both are properties of the series that the measure prices over its record. So a rule describes the sample, and not drawdowns in general.

PortfolioOptimisers.resolve_calibration_slot — Function
resolve_calibration_slot(slot, key::Symbol, pr::AbstractPriorResult, w, slv = nothing,
                         ctx::CalibrationContext = CalibrationContext())

Resolves one calibration slot against the prior result pr, the effective observation weights w, the effective solver slv and the context ctx of the site, and returns a plain number.

The function calls a rule in a slot as alg(key, pr, w, slv, ctx). So a callable rule and a plain function are the same here. It returns every other occupant, such as a stated number, unchanged.

A rule gets no portfolio. A prior result holds no portfolio weight vector, so no rule can measure the loss series of a portfolio. A rule can measure the series of each column of the sample, and ctx.series tells it which series the slot owner prices. A rule gets the solver on both routes that resolve a measure, so it can call ERM or RRM:

  • On the factory route, @propagatable runs the @cprop selection before the resolution, so the struct holds the solver.
  • On the JuMP route, no selection runs. set_risk_constraints! passes the solver to resolve_deferred_quantities, and the owner selects it as sel(x.slv, slv).

The context holds all the facts of the site, and this function rebuilds nothing. key names the slot and not the quantity. So a rule reads from ctx the shape of a series, the significance level of a sibling slot, the norm order of its constraint, or the count of the scenarios that the site prices. No rule has a field for these facts, so the function rebuilds no occupant and overwrites nothing that a caller stated. CalibrationContext states which rule reads which field.

This function checks the value of a ceiling rule and of a radius rule, and of no other family. AbstractNormCeilingCalibrationAlgorithm and AbstractAmbiguityRadiusCalibrationAlgorithm share one method. It runs assert_nonempty_gt0_finite_val on the number that the rule returned, under the key of the slot. Both quantities reach a JuMP model from a field of JuMPOptimiser: the ceiling from l2c and linfc, and the radius from l1 and linf. No term is rebuilt on that route, so nothing later checks the range. The three other families are only in slots that their owner rebuilds. The rebuild runs the constructor of the owner on the calibrated number, and that constructor checks the range. Only the calibrated path pays for the check, because a stated number takes the first method.

The site checks a rule that is a plain function. A function has no family, so no method here can know the quantity that it computes. assemble_jump_model! is the one site that reads a calibrated number and rebuilds no term, and it checks the range of each of its four norm slots.

This function is the counterpart of resolve_slot. It is a second function, and not a wider method of the first, for two reasons. The body of resolve_slot is deferred_quantity(fit_deferred_quantity(dq, pr), key), a fit and then an extraction, and a rule fits nothing. Also, resolve_slot takes neither w nor slv, and a rule needs both. So the rule families are not members of the DeferredQuantity union.

The caller computes w as sel(r.w, pr.w), and passes it with the slv of the measure. A parent that has no observation weights passes pr.w. A parent that has no solver leaves slv at its default.

A TimeDependent reaches the estimator that holds the slot, and does not go further. A schedule changes a field of an estimator, and update_time_dependent_fields applies it before the fit of a prior. A rule is always in a slot of an estimator, so a schedule replaces that estimator. If the estimator is a JuMPOptimiser, its four norm fields can each have a schedule, and the schedule selects a rule for each fold. If the estimator is a risk measure, the bound of the slot admits no schedule. The caller then changes the whole measure through the risk-measure field of the optimiser, which can have a schedule. On both routes the selection runs first, and the rule then resolves against the prior of the selected period. So a rule needs no schedule of its own. A schedule in a rule names a fold that the rule cannot see, and it repeats the schedule of the estimator.

Algorithm

  1. Return slot unchanged when is_calibration_rule returns false for it. A stated number takes this branch.
  2. Call the rule as slot(key, pr, w, slv, ctx), and return the number that it gives.
  3. A norm-ceiling rule or an ambiguity-radius rule takes a more specific method. That method checks the number before it returns it.

Arguments

  • slot: The occupant of the slot: a number or a rule.
  • key: Name of the slot that the call resolves.
  • pr: Prior result that the rule reads.
  • w: Effective observation weights, or nothing.
  • slv: Effective solver, or nothing when the measure has none.
  • ctx: The facts that the site knows and key does not give, as a CalibrationContext. The default has no sibling significance level, no norm order, and the returns series.

Validation

  • A norm-ceiling rule or an ambiguity-radius rule must return a number that is > 0 and finite. assert_nonempty_gt0_finite_val checks it under key. The function returns every other occupant with no check, and the owner of its slot checks the range when it rebuilds.

Returns

  • val::Number: The calibrated quantity, or the stated value unchanged.

PortfolioOptimisers.calibration_series_dispersion — Function
calibration_series_dispersion(series::AbstractCalibrationSeries, pr::AbstractPriorResult)

Returns the per-asset dispersion of the series that series names, one entry for each column of the sample.

A ReturnsSeries reads it from pr.sigma, as the square root of the diagonal of that matrix. So the dispersion of a prior that states a shrunk or a robust covariance matrix comes from that matrix.

A drawdown series reads it from the drawdown sample, because a prior result states no moment of a drawdown. calibration_series_matrix makes the sample, and the dispersion is the sample standard deviation of each of its columns. radial_series_inputs reads its centre and its whitening factor from the drawdown sample for the same reason. pr.sigma is a moment of the returns, and no scaling of it gives a moment of a drawdown.

A radius is a distance in the space of the scenarios that the model prices, so this vector gives the radius its units. ConcentrationRadius and DimensionalRateRadius average it into one scale. DualNormRadius divides it by the square root of the count that the site prices and takes a norm of the result.

Mathematical definition

\[\begin{align} \hat{s}_{i} &= \begin{cases} \sqrt{\hat{\mathbf{\Sigma}}_{ii}} & \textrm{for the returns series}\\ \sqrt{\dfrac{1}{T - 1} \sum\limits_{t=1}^{T} \left(y_{ti} - \bar{y}_{i}\right)^{2}} & \textrm{for a drawdown series} \end{cases}\,. \end{align}\]

Where:

  • $\hat{s}_{i}$: Sample dispersion of the series the slot owner prices, over column $i$. It is $\sqrt{\hat{\mathbf{\Sigma}}_{ii}}$ under a ReturnsSeries, and the dispersion of column $i$ of the drawdown sample under a drawdown marker.
  • $\hat{\mathbf{\Sigma}}_{ii}$: $i$-th diagonal entry of $\hat{\mathbf{\Sigma}}$.
  • $y_{ti}$: Entry $t$ of the drawdown series of column $i$.
  • $\bar{y}_{i}$: Sample mean of the drawdown series of column $i$.
  • $T$: Number of observations.

Arguments

  • series: The series that the slot owner prices.
  • pr: Prior result. A returns series reads its covariance matrix, and a drawdown series reads its sample.

Returns

  • s::AbstractVector: The per-asset dispersion of that series, N × 1.

PortfolioOptimisers.effective_sample_size — Function
effective_sample_size(pr::AbstractPriorResult, w::Option{<:ObsWeights})

Returns the number of observations behind the moments of pr, weighted by w.

A calibration rule that prices the sample size of the moments divides by this count, so those rules use one definition of it. The function reads three sources in order, and the first that gives a count wins:

  1. With weights, it is the effective sample size of [297]. That is the number of equally weighted observations that gives the precision of the weighted sample.
  2. With no weights, it is the count that the result states in ens, when the result states one and has no weights of its own. A Scenario Cap states there the number of observations over which it fitted the moments. The result then holds fewer rows than the observations behind its moments.
  3. Otherwise, it is the row count of pr.X, which is then the sample.

This function does not read an ens that is next to a w. That ens is a diagnostic of w, because an entropy-pooling prior writes exp(entropy(w)) there. So a rule that reads no weights reads no diagnostic of them either. Only a cap writes an ens with no w.

A rule that prices a property of the scenarios of the measure does not read this count. ScenarioCount and EntropyBudget read the rows that the measure holds when no weights are stated. A distributionally robust measure states the count of its rows, from scenario_sample_size, in the n of its CalibrationContext, and a radius rule reads that count in place of this one.

The function reads the weights through get_observation_weights, so it accepts all of the ObsWeights union that the w field of a rule admits. A DynamicAbstractWeights that has no method for a column of the sample raises ObservationWeightsError, which names the two signatures to write.

Mathematical definition

\[T_{e} = \begin{cases} \dfrac{\left(\sum\limits_{t=1}^{T} w_{t}\right)^{2}}{\sum\limits_{t=1}^{T} w_{t}^{2}} & \textrm{if } w \textrm{ is given}\\ T_{\mathrm{ens}} & \textrm{if } w \textrm{ is } \texttt{nothing} \textrm{ and the result states } T_{\mathrm{ens}} \textrm{ beside no weighting}\\ T & \textrm{otherwise} \end{cases}\,.\]

Where:

  • $T$: Number of observations.
  • $T_{e}$: Effective sample size, which is Kish's when the observation weights are stated.
  • $w_{t}$: Observation weight of observation $t$.
  • $T_{\mathrm{ens}}$: The effective sample size that the result states in ens.

Algorithm

  1. Resolve w against the first column of pr.X through get_observation_weights, which gives ws.
  2. When ws is not nothing, return the count of Kish for it.
  3. Otherwise, return stated_sample_size of the w, the ens and the X of the result. That is pr.ens when the result states it next to no pr.w, and size(pr.X, 1) otherwise.

Arguments

  • pr: Prior result from which the function reads the sample length.
  • w: Effective observation weights, or nothing.

Validation

  • w resolves through get_observation_weights. That function raises ObservationWeightsError for a DynamicAbstractWeights that has no method for a column of pr.X.

Returns

  • T_e::Number: The effective sample size.

scenario_sample_size(pr::AbstractPriorResult, w::Option{<:ObsWeights})

Returns the count of the empirical measure of the rows that pr holds, weighted by w.

A risk measure prices the rows of pr.X, and not the observations behind the moments. With weights, the measure is the weighted empirical measure of those rows, so the count is the effective sample size of [297], as in effective_sample_size. With no weights, the measure gives each row the same mass, so the count is the row count of pr.X.

The two counts differ only under a Scenario Cap. A cap fits the moments over every observation, states that number in ens, and holds fewer rows. effective_sample_size reads ens there, and this function reads the rows. The ens that an entropy-pooling prior writes is next to a w, so neither count reads it.

The function resolves w through get_observation_weights, as the programme of a measure does. So a DynamicAbstractWeights that resolves to nothing gives the row count, which is the count of the measure that the programme then prices.

Mathematical definition

\[T_{n} = \begin{cases} \dfrac{\left(\sum\limits_{t=1}^{T} w_{t}\right)^{2}}{\sum\limits_{t=1}^{T} w_{t}^{2}} & \textrm{if } w \textrm{ is given}\\ T & \textrm{otherwise} \end{cases}\,.\]

Where:

  • $T$: Number of observations. It is the row count of the sample that the result holds.
  • $w_{t}$: Observation weight of observation $t$.
  • $T_{n}$: Scenario count of the measure, the number of scenarios that it prices.

Algorithm

  1. Resolve w against the first column of pr.X through get_observation_weights, which gives ws.
  2. When ws is nothing, return size(pr.X, 1).
  3. Otherwise, return the count of Kish for ws, through effective_sample_size.

Arguments

  • pr: Prior result whose rows the measure prices.
  • w: Effective observation weights, or nothing.

Returns

  • T_n::Number: The count of the scenarios.

PortfolioOptimisers.hill_tail_index — Function
hill_tail_index(
    series::AbstractCalibrationSeries,
    X::AbstractArray{E<:Number, 2},
    s::Integer,
    k::Integer
) -> Any

Estimates the tail index of the pool of standardised values of X, over the k most extreme order statistics of the pool.

series names the series of each column, and calibration_series_vec makes it. The function centres each series and divides it by its sample standard deviation, and s names the end. The estimator of [172] reads the k of the T N standardised values that are furthest into that end. HillTailDecay states the assumptions of the pool. This function makes the estimate alone.

The pool holds T values for each column under every marker, because a drawdown series has one entry for each observation. So the function reads the count k that the caller made, for every series.

The signature binds the element type, so the pool and its sum have concrete types. A rule reads pr.X from an AbstractPriorResult, whose field types no signature states, and this function is the boundary where the type becomes concrete.

Algorithm

  1. Read the shape of X into T and N, and allocate the pool pool of T * N values.
  2. Walk the columns of X. Make the series of each column with calibration_series_vec, take its sample mean mu and its sample standard deviation sd, and write -s * (col[t] - mu) / sd into pool.
  3. Partially sort pool, so that its k + 1 smallest values are in order at the start, and read the last of them into vkp1. partialsort! with one index puts only that index in place, so the range is necessary to put the k entries of the estimate before vkp1. The sign of step 2 puts the end that the caller prices in the lower tail of the pool.
  4. Return k divided by the sum of log(pool[i] / vkp1) over those k entries. Both terms of each ratio are negative, so the ratio is a ratio of magnitudes, and the sum needs no change of sign.

Arguments

  • series: The series of each column.
  • X: Returns matrix, T × N.
  • s: Sign of the end that the estimate reads. 1 reads the gain tail, and -1 reads the loss tail.
  • k: Number of order statistics that the estimate reads. The caller states it and checks its floor.

Validation

  • The k + 1-th largest pooled value must be positive.

Returns

  • a::Number: The Hill estimate of the tail index of the pool.

PortfolioOptimisers.whitening_factor — Function
whitening_factor(pr::AbstractPriorResult) -> Any

Returns an upper triangular square factor of the covariance matrix of pr, so that the transpose of the factor whitens a centred observation.

The factor $\mathbf{U}$ satisfies $\mathbf{U}^{\top} \mathbf{U} = \hat{\mathbf{\Sigma}}$. That is the convention of the chol field of a prior result, and the variance constraint layer uses it too. chol has precedence over sigma, as the chol field states. So the function whitens a prior that has a factor with that factor, and never with a factorisation of sigma. chol is optional, so usually the function factorises sigma.

The library checks chol only against the length of mu, so it can be $K \times N$ and not square, and a square chol need not be triangular. The function needs a triangular factor, because only the diagonal of a triangular factor gives its rank:

  • A chol of type LinearAlgebra.UpperTriangular is the factor.
  • Every other chol with $K \geq N$ gives the $\mathbf{R}$ factor of its QR factorisation. $\mathbf{R}^{\top} \mathbf{R} = \mathbf{F}^{\top} \mathbf{F}$, so $\mathbf{R}$ is a triangular factor of the same covariance matrix. This includes a tall factor, and a square factor that is not triangular, such as a symmetric square root.
  • A wide chol, with $K < N$, gives a singular covariance matrix, and no whitening exists for it.

RadialTailDecay calls this function. The function is separate because the precedence rule and its refusals are facts about a prior result and not about a tail index.

Algorithm

  1. Read pr.chol into F.
  2. When F is nothing, factorise pr.sigma with a Cholesky factorisation that reports a failure and does not raise it, and return its upper factor.
  3. Otherwise, refuse a wide F. Take F when it is an UpperTriangular, and the R factor of its QR factorisation otherwise.
  4. Refuse a zero on the diagonal of that triangular factor, because it gives a singular covariance matrix, and return the factor.

Arguments

  • pr: Prior result from which the function reads the covariance matrix.

Validation

  • pr.sigma must be positive definite, when pr.chol is nothing.
  • pr.chol must have at least as many rows as columns.
  • The diagonal of the triangular factor must have no zero.

Returns

  • U::AbstractMatrix: Upper triangular square factor of the covariance matrix.

PortfolioOptimisers.radial_tail_index — Function
radial_tail_index(
    X::AbstractArray{E<:Number, 2},
    mu::AbstractVector,
    U::AbstractMatrix,
    k::Integer
) -> Any

Estimates the tail index of the radial series of X, over the k largest order statistics of that series.

The function centres each row on mu and whitens it with U. The norm of the whitened row is one entry of the radial series. The estimator of [172] then reads the k entries that are furthest out. RadialTailDecay states what the series measures. This function makes the estimate alone.

The signature binds the element type, so the series and its sum have concrete types. A rule reads pr.X from an AbstractPriorResult, whose field types no signature states, and this function is the boundary where the type becomes concrete.

Algorithm

  1. Solve transpose(U) \ transpose(X .- transpose(mu)). The columns of the result Z are the whitened observations.
  2. Walk the columns of Z, and write the negative Euclidean norm of each column into the series d.
  3. Partially sort d, so that its k + 1 smallest values are in order at the start, and read the last of them into vkp1. partialsort! with one index puts only that index in place, so the range is necessary to put the k entries of the estimate before vkp1. The negative sign of step 2 puts the largest distances at the start.
  4. Return k divided by the sum of log(d[i] / vkp1) over those k entries. Both terms of each ratio are negative, so the ratio is a ratio of magnitudes, and the sum needs no change of sign.

Arguments

  • X: Returns matrix, T × N.
  • mu: Expected returns vector, N × 1. The function centres the rows on it.
  • U: Upper triangular square factor of the covariance matrix, which whitening_factor returns.
  • k: Number of order statistics that the estimate reads. The caller states it and checks its floor.

Validation

  • The k + 1-th largest radial distance must be positive.

Returns

  • a::Number: The Hill estimate of the tail index of the radial series.
