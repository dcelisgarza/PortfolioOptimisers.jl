PortfolioOptimisers.step_active_mask — Function

Reads the active mask of the Asset Panel that a step carries to an exact fold that is not a prior, and refuses what that fold cannot carry.

The step of a covariance estimator in covariance_forecast_evaluation and the step of an online portfolio selection read the mask through this function. Each caller decides on the implied volatilities itself: the head of an online portfolio selection records them with its rows, and the covariance step gives them to a buffer and nothing to an exact fold. A prior does not: it folds through partial_fit! over the ReturnsResult, whose route decides what the step honours. A ReturnsResult with no panel, or with a static one, gives no mask, because the fold context pins a static panel. A time-varying panel that holds masks alone, which is the shape the ingestion layer writes, gives its active mask, and the fold records the mask beside the rows. This function refuses a time-varying panel that holds Panel Fields, because these folds read none and hold numbers alone.

The estimation mask does not travel these folds. The exact folds of the moment layer take an active mask and no estimation mask, so a step whose estimation universe is narrower than its active universe would fit the wrong universe without a word. The function refuses such a panel with an ArgumentError.

Algorithm

  1. Refuse rd without returns with assert_prior_fold_returns.
  2. Return nothing when rd holds no panel, or when its panel is static.
  3. Refuse a time-varying panel that holds a Panel Field.
  4. Refuse a time-varying panel whose estimation mask differs from its active mask.
  5. Return the active mask pnl.amsk.

Arguments

  • rd: The returns data to fold.

Validation

  • The rules of assert_prior_fold_returns.
  • A time-varying rd.pnl holds no Panel Field. An ArgumentError is thrown otherwise.
  • A time-varying rd.pnl has an estimation mask equal to its active mask. An ArgumentError is thrown otherwise.

Forwards the observations of rd to the prior, in the arity of the prior's own step.

This is the one forward that the step of an optimiser makes. An optimiser forwards each observation to its prior and to nothing else. optimise(opt) with no returns fits every other member in batch, from the fold context it rebuilds. The step folds rd through fold_prior_step, the verb of partial_fit! over the ReturnsResult, which reads it as prior reads it in batch. The route of the prior decides what the step honours. A refit honours the estimation mask and records the Panel Fields of a prior that reads them. The carry of EmpiricalPrior refuses an estimation mask that differs from the active mask, and each route refuses a Panel Field that its prior does not read. The tree of the prior decides what to do with F, as its batch function does.

A prior that is already an AbstractPriorResult has no state to fold into. It is batch configuration, and an optimiser that holds one runs optimise(opt, rd). This function also refuses a TimeDependent schedule on the prior. A schedule swaps the estimator that carries the state, and a member that never saw the folded rows cannot take them over.

The prior folds the returns that its batch fit reads, in the frame that its own x_src states. Under ExcessSource these are the returns in excess of the benchmark, as prior reads them, so prior_step_returns gives the prior the observations of rd with X - B in place of X.

A batch fit drops an observation with a gap in a Shared Series that it reads, see shared_series_view. The step cannot drop the row, because the buffer of the prior and the Fold Context hold one row each for every observation, and optimise(opt) with no returns rebuilds the returns data from both. The prior cannot find a gap of the benchmark, because in the Excess Frame it reads X - B and not B, so this function finds the marks and hands them to the prior. A gap of a vector benchmark follows the group of the head, gsrc, and not the prior alone: a head drops it when any reader of its group states ExcessSource(), so a raw prior beside an excess reader marks it too. optimise(opt) with no returns cuts the rebuilt returns data by the same rule, see batch_from_state.

Takes the step of an optimiser that holds a prior and a fold context. It forwards the observations to the prior, then records rd in the context.

The prior folds first, because the context takes its cap from the buffer of the prior. The max_history of an Online wrapper caps the rows of the prior, and the context must drop the same rows at the same step, so the ReturnsResult that optimise(opt) with no returns rebuilds matches the rows of the prior.

The prior folds the returns in the frame that its own x_src states. Under ExcessSource the buffer of the prior holds the returns in excess of the benchmark, and the context keeps the raw returns beside them. Under nothing or DataSource the buffer holds the raw returns, and the context keeps no copy. So the ReturnsResult that optimise(opt) with no returns rebuilds holds the raw X and B, as the batch path reads them, and optimise(opt) with no returns equals optimise(opt, rd[1:t]) in every frame. The marks of a gap of a vector benchmark follow the group of the head, gsrc.

One place holds F. The context keeps the factor column only when the tree of the prior never reads it, that is, when needs_factor_returns answers false. Otherwise the buffer of the prior records it, and optimise(opt) with no returns reads it back through prior_returns_buffer, as it reads the returns. One place holds the Exogenous Series on the same terms. The context keeps it only when reads_exogenous_series answers false, and the buffer of the prior records it otherwise.

Algorithm

  1. Fold rd into opt.pe with fold_prior under the source of the group gsrc, giving the folded prior pe.

  4. Fold rd into opt.cache with fold_context, under the cap rows.max_history, giving cache. The context keeps the raw returns when the prior states a source other than nothing and DataSource, because the buffer of the prior then holds another matrix. Otherwise it keeps no returns.
  5. Rebuild opt with pe and cache.

  • opt: An estimator that holds pe and cache.

Turns a folded optimiser into the batch call that reads it out, an estimator and a ReturnsResult.

optimise(opt) with no returns rebuilds the ReturnsResult and calls the ordinary batch path, so no member above the prior needs a method of its own. The prior becomes prior(pe), a prior result, which the batch path does not refit, so the solve reads the folded prior.

The rebuilt ReturnsResult holds every observation that the step folded, and the folded prior drops the observations of a Shared Series gap, see shared_series_buffer. The folded prior records the observations that it dropped in its ss_gaps, see shared_series_record, so the function returns the whole ReturnsResult. The head then drops the marked observations itself, see prior_shared_series_rows, and the prior and every reader that pairs its observations with the last observations of the returns data read the same observations, as in the batch fit. Each fallback receives the whole ReturnsResult and drops by its own rule, as in the batch fit. This function drops the context, because the estimator it returns is a batch configuration over the rebuilt ReturnsResult. It never writes the state, so two calls on one estimator give the same answer.

The cache of the optimiser selects the branch. An optimiser whose cache is nothing has taken no step, and batch_without_state answers for it. This function returns any other optimiser with an empty ReturnsResult, and its batch function decides whether it answers without returns. optimise(opt) with no returns does not reach this function for a PreviousWeights, because that head has its own method of optimise(opt) with no data.

Algorithm

  1. A JuMP head or a hierarchical head reads out the bundle it holds in opt, and rebuilds itself around the bundle.
  2. An optimiser with no state goes to batch_without_state.
  3. Rebuild rd with returns_result.
  4. Rebuild the optimiser with cache = nothing. An optimiser that holds a prior also replaces pe with prior(pe), the result of the folded prior.
  5. Return the optimiser and rd.

Arguments

  • opt: The optimiser to read out.

Validation

  • opt is not a finite allocation. An ArgumentError is thrown otherwise, because a finite allocation has no step.
  • Everything batch_without_state and returns_result refuse.
