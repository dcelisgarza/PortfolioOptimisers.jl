PortfolioOptimisers.held_path_turnover — Function
held_path_turnover(pred::PredictionResult, j::Integer = 1)
held_path_turnover(pred::MultiPeriodPredictionResult, j::Integer = 1)

Compute the mean turnover for each rebalance of the held path of member j of a prediction result, as performance_summary gives it.

A fold trades from the weights that the previous fold held after its last observation, and not from the target of that fold. Under a Held Weights record the two are different, so the turnover of a drifted path is not the turnover of its targets. The closed form is the turnover row of the # Mathematical definition of performance_summary. A prediction whose optimiser gives many portfolios holds one path for each member, and j names the member.

Algorithm

  1. Stack the weights of member j at the start of every fold, to get W0 with one row for each fold. fold_target reads the weights, and stacked_fold_weights puts them on the union of the universes of the folds, by asset name.
  2. Stack the weights of member j of every fold after its last observation on the same axis, to get W1. fold_held reads these weights.
  3. Take F, the number of folds. When F < 2, the result records no rebalance, and the answer is nothing.
  4. Average the trade from row f - 1 of W1 to row f of W0 over the F - 1 rebalances, to get the turnover.

Arguments

  • pred: The prediction result.
  • j: The index of the member.

Returns

  • tn::Option{<:Number}: The mean turnover for each rebalance. It is nothing when the result records no rebalance, that is for a single prediction result and for a multi-period result of one fold. The summary writes nothing as NaN.

summary_measures(measures::Tuple{})
summary_measures(measures::Union{Tuple, AbstractVector})

Check the extra risk measures of a performance_summary call, and key them by name.

The check runs before any figure is computed, so a call with a measure that cannot read a series computes nothing. It collects every such measure, and the error names all of them.

Algorithm

  1. For each entry, check that it is a pair name::Symbol => r::AbstractBaseRiskMeasure, that its name is new, and that its name is not a column of performance_summary_columns.
  2. Collect each measure whose supports_precomputed_returns is false. When there is one, raise an error that names each by its name and its type.
  3. Key the measures by their names, in the order of measures.

Arguments

  • measures: A vector or a tuple of pairs name::Symbol => r::AbstractBaseRiskMeasure.

Validation

  • Each entry is a pair of a Symbol and an AbstractBaseRiskMeasure, no name repeats, and no name is a column of the table. Otherwise the function raises an ArgumentError.
  • Each measure reads a series. Otherwise the function raises an ArgumentError.

Returns

  • ms::NamedTuple: The measures, keyed by name. It is empty when measures is empty.

PortfolioOptimisers.candidate_summary — Function
candidate_summary(kwargs, names, xs::AbstractVector, args...) -> PerformanceSummaryResult

Summarise a vector of candidates of performance_summary, one candidate after the other.

Algorithm

  1. Check that xs is not empty, and check the keywords with summary_options.
  2. Resolve one name for each candidate with forecast_summary_names, with the default "Portfolio k".
  3. Make the entries of each candidate with input_entries, each with the name of its candidate, and join them in the order of xs.
  4. Summarise the entries with summarise_entries, which gives one vector entry for each.

Arguments

  • kwargs: The keywords of the call.
  • names: One name for each candidate, or nothing.
  • xs: The candidates.
  • args...: The arguments that each candidate shares, such as the rd of a vector of OptimisationResult.

Validation

  • !isempty(xs). Otherwise the function raises an IsEmptyError.
  • The rules of forecast_summary_names.

Returns

  • summary::PerformanceSummaryResult: The summary, with one vector entry for each series.
