Step execution: private API

A run_step method is the only code that connects an estimator family to a pipeline. It reads the slots of the PipelineContext that its estimator needs, and calls the function that the family uses outside a pipeline: prior for a prior estimator, clusterise for a clustering estimator, optimise for an optimiser, and fit_preprocessing and apply_preprocessing for a preprocessing estimator. It then writes the slot that the family produces.

The estimators do not depend on the pipeline code, and their docstrings are with their own families. The preprocessing estimators, for example, are on the preprocessing page.

PortfolioOptimisers.run_step — Function
run_step(est, ctx::PipelineContext) -> (fitted, ctx′)

Execute one pipeline step: fit est on the PipelineContext slots it reads and return the fitted object together with a new context whose written slot is updated.

Each estimator family dispatches to its native verb — prior for prior estimators, clusterise/phylogeny_matrix for phylogeny estimators, optimise for optimisation estimators, fit_preprocessing/apply_preprocessing for preprocessing estimators. The fitted object is what apply_preprocessing later uses to transform unseen data windows; for non-preprocessing steps it is the step's ordinary result.

Estimators whose family is not steppable throw an ArgumentError directing the caller to PipelineStep.

A step that reads the returns reads them from the source that its own reader states in its x_src field, as the same reader does in the slot of an optimiser. A PipelineStep wrapper holds no source.

PortfolioOptimisers.run_uncertainty_step — Function
run_uncertainty_step(
    ue::AbstractUncertaintySetEstimator,
    target::Union{Nothing, Symbol},
    ctx::PipelineContext
) -> Tuple{Any, PipelineContext}

Execute an uncertainty-set step pinned to a target and merge its result into the uncertainty slot.

The target comes from the PipelineStep wrapper:

  • :mu computes mu_ucs and fills the mean half.
  • :sigma computes sigma_ucs and fills the covariance half.
  • :both computes ucs, which derives both halves from one fit — sharing the prior and, for the sampling algorithms, the simulation draws — and is therefore cheaper than the two narrowed calls.

A narrowed step fills its half of the PipelineUncertaintySets pair and leaves the other untouched, so separate :mu and :sigma steps compose. Every populated half must reach the optimiser: each becomes its own routing target — :mu_ucs and :sigma_ucs — and neither is optional, so a set that cannot be routed is rejected rather than dropped and :both requires an optimiser with an ArithmeticReturn and an UncertaintySetVariance risk measure.

Which slot the step reads is decided by reads_prior_result. An estimator with a prior of its own is fitted from the returns slot. One that reads a prior result — an AbstractPriorUncertaintySetEstimator, or a returns-data estimator with pe = nothing — is fitted from the prior slot instead, so a prior step must come earlier; the returns are not read at all, so a pipeline that writes :prior from a precomputed result needs no :returns slot for such a step.

Arguments

  • ue: The uncertainty-set estimator.
  • target: :mu, :sigma, or :both; anything else throws an ArgumentError.
  • ctx: The pipeline context; requires the returns slot, or the prior slot for an estimator that reads a prior result.

Returns

  • (res, ctx′): The computed result and the updated context. For :both, res is the (mu, sigma) PipelineUncertaintySets pair; otherwise it is the single AbstractUncertaintySetResult.

The frame of a step

A step that reads the returns reads them from the source that its own reader states in its x_src field. A PipelineStep holds no source. The steps whose values the last optimiser receives join the group of that optimiser, and the readers that those values replace leave it. The Pipeline constructor warns on that group, and it refuses a prior step that fits on the excess returns and feeds an optimiser with a data benchmark.

PortfolioOptimisers.pipeline_frames — Function
pipeline_frames(ests) -> ReturnsFrames

Return the frames of the group that the steps of a Pipeline join: the group of its last optimiser.

inject_context puts the value of each step into a slot of the last optimiser, so the step reads the returns for that optimiser. The steps whose values the optimiser receives join its group, and the readers that those values replace leave it. A network step writes a phylogeny matrix that no slot receives, so it stays out. A prior step decides refit for the optimiser when the optimiser receives its value, because that prior then replaces the prior of the optimiser. A step reads the prior slot, so the last prior step decides refit for the steps. With no prior step a step reads a Prior Result that the input gave, which reads as raw. group_frames of a Pipeline calls this function.

Internal machinery — not part of the user-facing API.

  3. Find refit for the steps and for opt with pipeline_refits.
  4. Walk each step that opt receives with reader_frames, at the path "steps[i]".
  5. Walk opt without the slots that the steps replace with terminal_frames, and join every part with merge_frames.

Arguments

  • ests: The step estimators, with the optimisation step last, see assert_opt_last.

Returns

pipeline_refits(ests, received, opt) -> Tuple{Bool, Bool}

Return refit for the steps of a Pipeline and refit for its last optimiser, see refits_regression.

A step reads the prior slot, so the last prior step decides refit for the steps. With no prior step a step reads a Prior Result that the input gave, which reads as raw. A prior step decides refit for the optimiser when the optimiser receives its value, because that prior then replaces the prior of the optimiser.

Internal machinery — not part of the user-facing API.

Algorithm

  1. Find the last prior step with step_prior. refit for the steps is refits_regression of its prior, or false when there is none.
  2. Find the last step whose targets in received hold :pe. refit for opt is refits_regression of its prior, or of the prior of opt (pipe_prior_estimator) when there is none.

Arguments

  • ests: The step estimators, with the optimisation step last.
  • received: The routing targets that opt receives from each earlier step.
  • opt: The optimiser of the last step.

Returns

  • (step_refit, opt_refit)::Tuple{Bool, Bool}: refit for the steps and for opt.

PortfolioOptimisers.pipe_data_benchmark_path — Function
pipe_data_benchmark_path(x) -> Option{<:String}

Return the path of the first DataBenchmarkTracking in a measure that reads the prior of the optimiser x, or nothing.

Every tracking form compares pr.X * w with its benchmark series, so the prior that the measure reads decides its frame. The measures that read the prior of a head are the tracking errors tr of its configuration and the risk measures r, ri and ro of the head. The walk follows the path of the :pe routing target through pipe_config_field, so it reads the fields that hold the prior and the fields beside them. It does not enter an inner optimiser or a fallback, because each one checks its own prior.

Internal machinery — not part of the user-facing API.

Algorithm

  1. For each of the fields tr, r, ri and ro of x, in order, return the path that data_benchmark_path finds below it, after the name of the field.
  2. Otherwise return the answer for the configuration of x, after the name of its field. An x with no configuration answers for nothing, which is nothing.

Arguments

  • x: The optimiser or the optimiser configuration.

Returns

  • path::Option{<:String}: The path of the data benchmark from x, or nothing.

PortfolioOptimisers.assert_pipeline_data_benchmark — Function
assert_pipeline_data_benchmark(ests) -> Nothing

Refuse at construction a Pipeline whose prior step states x_src = ExcessSource() when the optimiser that receives the prior tracks a DataBenchmarkTracking.

The optimiser receives the Prior Result of the step in its field pe. In the Excess Frame pr.X holds X - B, so a data benchmark gives the series (X - B) * w - B, and the benchmark is subtracted two times. The constructor of the optimiser refuses this pair for its own prior. It cannot see the source of the step, because the step value replaces its prior only when the pipeline runs. So the Pipeline constructor refuses it. The configuration alone decides the refusal. A prior step that holds a precomputed Prior Result, or a callable, states no source, so it reads as raw and passes.

Internal machinery — not part of the user-facing API.

Algorithm

  1. Read the optimiser opt of the last step with pipe_terminal_optimiser. Stop when there is none, or when it has no field for the :pe routing target.
  2. Find the last prior step, whose Prior Result the prior slot holds when opt runs, with step_prior. Stop when there is none, or when its source is not ExcessSource().
  3. Find a data benchmark in a measure of opt that reads its prior with pipe_data_benchmark_path.

Arguments

  • ests: The step estimators, with the optimisation step last, see assert_opt_last.

Validation

  • The last prior step does not state x_src = ExcessSource(), or the optimiser holds no DataBenchmarkTracking in a measure that reads its prior. An ArgumentError that names the step, the field and the two remedies is thrown otherwise.

Returns

  • nothing.
