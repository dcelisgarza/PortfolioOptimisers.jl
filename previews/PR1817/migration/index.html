Migration guide

This page lists every change that can break code written against an earlier release, and the code to write instead. Each version has its own section. Read the section for the version you upgrade from, and every section after it.

From v0.30 to v0.31

v0.31 is a large release. The changes fall into seven groups, and most code needs at most the first three.

  1. Names that were removed, and what replaces each.
  2. Loading prices. prices_to_returns now converts prices and nothing else. Joining, filling and filtering are separate steps.
  3. Asset features. An asset panel, one object that holds every feature of every asset, replaces the feature matrix Z.
  4. Fees. The fixed fees are charged once per holding period, and calc_fees returns a pair.
  5. Renamed keywords and changed defaults.
  6. Calls that now raise an error where they used to return a value.
  7. Results that move. These are the configurations whose numbers differ from v0.30, and the reason for each.

Two more sections cover code that extends the library with its own estimators, and links into the documentation.

v0.31 supports Julia 1.11, 1.12 and 1.13.

Loading prices

prices_to_returns used to do five jobs with one keyword list: join the factor and benchmark tables onto the assets, collapse to a lower frequency, impute or delete gaps, apply a function, and compute returns. It now computes returns, and each of the other jobs is a named step you compose. The keywords that remain are ret_method and padding, plus a new gap_return_alg.

In v0.30:

rd = prices_to_returns(X, F; B = B, iv = iv, ivpa = ivpa,                       join_method = :outer, collapse_args = (week, last),                       missing_col_percent = 0.9, missing_row_percent = 0.9,                       impute_method = Impute.Interpolate(), map_func = f)

In v0.31:

pr = price_ingestion(PriceIngestion(; join_method = :outer, collapse_args = (week, last)), X;                     F = F, B = B, iv = iv, ivpa = ivpa)#! Keep one of the next two lines: the first drops the assets and rows with too many gaps, the second fills the gaps.mdf = fit_preprocessing(MissingDataFilter(; col_thr = 0.9, row_thr = 0.9), pr)mdf = fit_preprocessing(PriceGapFill(; fill = CarriedPrice()), pr)rd = prices_to_returns(apply_preprocessing(mdf, pr))

The one-line form prices_to_returns(X; kwargs...) still works. It ingests the prices with the default PriceIngestion() and passes kwargs to the conversion. The factor, benchmark and implied-volatility tables now go through price_ingestion.

These are the changes to the conversion, and what each one does to a result.

  • Gaps are no longer deleted. An asset that lists late, delists, or is suspended stays in the table, with NaN where it had no price. The ReturnsResult holds an AssetPanel whose two masks say which assets are in the universe at each date, and which of them can be estimated. Every optimiser reads those masks, fits on the assets it can trade, and gives the other assets a weight of exactly zero. So a walk-forward over such a table runs each fold on the assets listed in that fold. v0.30 either dropped the asset from the whole run, or held it after it delisted. On a table with no gaps, nothing changes.
  • The join is :left by default, where it was :outer. A factor or benchmark table with more dates than the assets no longer adds dates to the observations. The ingestion pads it onto the asset dates and reports the padding. Pass PriceIngestion(; join_method = :outer) for the old dates.
  • missing_row_percent = nothing has no counterpart. It kept the columns whose count of missing rows equalled the most common count. MissingDataFilter(; col_thr = 0.0) states the condition that it approximated.
  • map_func has no counterpart. Apply the function to the TimeArray before the ingestion.
  • nan_to_missing is gone, because the ingestion writes every missing price as NaN.
  • A price of Inf raises an error at the ingestion. In v0.30 it reached the conversion and gave a -100 % return.
  • A column name that two tables share, or that a table shares with the timestamp column, raises an error. v0.30 matched such columns by position.

If you build a PricesResult or a ReturnsResult by hand, the pnl keyword replaces the nz and Z keywords. PricesResult also gains span, a Boolean matrix that says which assets are listed at each observation, and the conversion reads it.

Asset features

In v0.30 a feature reached a clustering optimiser as a matrix Z and its labels nz, stored on the returns. The z_src keyword of the optimiser chose between the data and a FeaturePrior that made the features. One object replaces all of that. The asset panel is stored on the returns as rd.pnl, and it holds each feature as a named field. A field is numeric, categorical, or a tensor with its own labels.

In v0.30:

rd  = prices_to_returns(X; nz = ["nx_sector"], Z = Z)pe  = FeaturePrior(; pe = EmpiricalPrior(), ze = AssetSetsFeatures(; vals = ["nx_sector"]),                   sets = sets)opt = HierarchicalOptimiser(; pe = pe, cle = ClustersEstimator(; de = FeatureDistance()),                            z_src = :prior)

In v0.31:

rd  = ReturnsResult(; nx = rd.nx, X = rd.X, ts = rd.ts,                    pnl = asset_panel([panel_input(sets, "nx_sector")]))opt = HierarchicalOptimiser(; pe = EmpiricalPrior(),                            cle = ClustersEstimator(; de = FeatureDistance(; sel = ["sector"])))

The name of a field built from UniverseSets is the key without its prefix, so "nx_sector" becomes "sector". A numeric feature that you hold as a vector or a matrix is a NumericPanelInput(; name, vals). A graded classification with its own column labels is a TensorPanelInput(; name, vals, axis, labels).

  • FeatureDistance() with no sel stacks every field of the panel. sel takes field names, name => [levels], name => level or name => :observed. It no longer takes an integer column index, so sel = [3] becomes the name of the column.
  • The ape keyword replaces the two feature producers. FeatureDistance(; ape = RegressionPanel()) clusters on the factor loadings of the prior's regression. FeatureDistance(; ape = PhylogenyPanel(; pl, alg)) clusters on a phylogeny that PhylogenyPanel builds when the distance is computed.
  • A blank in a feature is missing, nothing or NaN. The field's fill policy fills it, so no blank reaches the code that reads the panel. The policies are NoPanelFill, ConstantPanelFill, ForwardPanelFill and BackwardPanelFill. The fill policy of a categorical field must name a level. CategoricalPanelInput(; alg = ForwardPanelFill()) without a value raises an error. The table of calls that now raise gives the v0.30 behaviour.
  • feature_matrix(pnl) stacks a panel, and feature_labels(pnl) names its columns. The labels are also a selector, so feature_matrix(pnl, feature_labels(pnl)) builds the same matrix again.

Fees

v0.31 changes when each fee is charged. The proportional fees l and s and the turnover fee tn are charged on every observation. The fixed fees fl and fs are charged once for the holding period. v0.30 charged the fixed fees on every observation and the turnover fee once, so a fold of T rows paid a fixed fee T times. Any backtest with a fixed fee reports a different net return.

  • calc_fees(w, fees) is now calc_fees(w, T, fees), and it returns the pair (periodic, one_off). The one number that a caller used to read is calc_total_fees(w, T, fees), the cost of the whole holding period. calc_total_asset_fees gives the same cost per asset. On one observation, calc_total_fees(w, 1, fees) gives the old sum when fees.fa is nothing.
  • Fees(; fa = AmortisedFees()) spreads the one-off charge over the period instead. FirstObservationFees() and nothing charge it on the first observation. A cross-validation scheme's own fa overrides the fee's fa on each fold's return series.
  • Fees and FeesEstimator gain lq and flq, a proportional and a fixed charge on the position of an asset that leaves the universe during a fold. Each one is a Turnover stated over the full universe. A walk-forward over a delisting reports a return that is lower by the liquidation charge of each exit.
  • The finite allocations, DiscreteAllocation and GreedyAllocation, price their fees on the shares they buy, inside their own models. The calc_fees(w, p, …) methods that took prices are deleted, and the fees field of the result holds the charge.

Results that move

A result from v0.30 is approximate where a correction moved a number, and wrong where the old answer did not follow the configuration. Recompute any of the following.

These results were wrong in v0.30:

  • AugmentedBlackLittermanPrior in any configuration, because the prior added the regression intercept twice. FactorBlackLittermanPrior and AugmentedBlackLittermanPrior with a non-zero rf are approximate.
  • An entropy-pooling value-at-risk view whose coefficient is not one selected the wrong tail. A view with a target of 0 was dropped with no warning. OptimEntropyPooling ignored a sc1 other than the default.
  • WeightBounds with an infinite scalar bound, or a vector bound shorter than the universe (now an error, see the table above).
  • A weighted pipeline holding ImpliedVolatilityRegression computed the realised volatility unweighted.
  • A hyperparameter search over "opti[1].opt.l2". The penalty never entered the model, and the search reported success.
  • The effective-asset norm ceiling at any p != 2. The ceiling was weaker than asked.
  • distance_wei, the private shortest-path function of DBHT, returned a wrong edge count for each path in B, its second output. DBHT uses only the path lengths, and this defect moved no cluster. Three more DBHT defects moved clusters on a tie and on a repeated call.
  • A KFold run through the Pipeline passed the weights of the previous fold to the next fold, where a run of the optimiser alone did not. FeesEstimator.tn passed the turnover through unchanged, so every fold charged the turnover fee against old reference weights.
  • MultipleRandomised with a seed draws different subsets, because it now draws from the assets listed in each window.

These results were approximate in v0.30:

  • A moment estimator with observation weights (SimpleVariance, Covariance, Coskewness, Cokurtosis) now weights its centre as well as its spread.
  • A co-movement matrix of the Gerber or Smyth-Broby kind has a diagonal of ones, and a return of exactly zero at a zero band edge is neutral rather than a crossing.
  • GerberIQCovariance under Gerber2 now reads the bound for each pair.
  • The library widens a histogram edge by one ulp rather than by eps. So mutual information, and every caller of calc_hist_data on standardised data, prices or levels, moves in the last digits.
  • cor on an implied-volatility estimator, collapse_features with MedianCollapse over a narrow element type, and the output element type of pre_order with a custom traversal strategy.
  • A weighted RelativisticValueatRisk, its range, and the two relativistic drawdown measures.
  • A Fees resolved from a FeesEstimator carrying a non-default kwargs.
  • An upper-bound GridRelativisticValueatRiskView.
  • An EntropyPoolingPrior over a FactorPrior with a StepwiseRegression. The nested prior now fits first, so it selects the same factors as the FactorPrior alone.
  • Every backtest with a fixed fee, a turnover fee, or a delisting. See Fees.
  • A walk-forward search (GridSearchCrossValidation, RandomisedSearchCrossValidation) over an optimiser with a TimeDependent schedule, or with a Turnover, tracking or fee term that reads the previous weights. The search now scores each candidate with one run of its folds in order, and no longer fits each fold on its own.
  • A walk-forward in which a fold failed and a later fold read the previous weights. The later fold now reads the last solved fold's weights instead of raising an error.

These results keep their numbers, but their meaning changed:

  • The Max and log-sum-exp scalarisers put an upper bound on model[:risk], so model[:risk] is not the aggregate. Read the exact value with expected_risk.
  • The order-p effective number of assets behind an lpc ceiling is (sum_i |w_i|^p)^(1/(1 - p)), where v0.30 used 1 / sum_i |w_i|^p. To ask for at least m such assets, set val = m^(1/p - 1), not m^(-1/p).
  • res.fb on an optimisation result holds the fallbacks that failed before the answer, as (estimator, result) pairs. In v0.30 it was always nothing.
  • Every optimisation result has imsk, the assets it was allowed to trade. On a table with no gaps it is all true.

If you extend the library

  • A prior estimator's method on a returns matrix takes the asset panel as its third positional argument. The signature is prior(pe, X, F = nothing, pnl = nothing; kwargs...). When you pass a ReturnsResult, the library calls this method with all three arguments. A method that takes only two arguments raises a MethodError. Give it a third argument, even one it ignores.
  • An uncertainty-set estimator for which reads_prior_result returns true receives an rd keyword, which it can ignore.
  • LowOrderPrior.rr now takes an AbstractLoadingsRegressionResult. A regression result that is an AbstractRegressionResult but not a loadings result raises a MethodError when you store it there.
  • Regression gains a fourth field, esigma, the idiosyncratic variances, when the regression is fitted with rsd = true. Code that constructs or compares it by position must handle the extra field.
  • SubsetResamplingResult, NestedClusteredResult and StackingResult have imsk before fb. Keyword construction is unaffected.
  • Weight bounds are validated against the stated asset count with DimensionMismatch, so a constraint generator outside the library that relied on truncation now raises an error.

These results were wrong in v0.31:

  • An LInfNorm tracking error divided the largest difference by T - ddof. With 252 rows, err = 2e-2 let one day differ by 5.04, so the bound did not bind. The error is now the largest difference, and err is the bound on one period.
  • MonotonicSchurComplement returned the weights of a gamma other than the one it reported. The difference reached 8e-6 in a weight. The bisection also returned the weights of a midpoint that it rejected.
  • SchurComplementHierarchicalRiskParity dropped its fee. The result had no fees field, so calc_net_returns gave the gross return, and a fold charged no forced exit. The result now carries the fee.
  • After factory, the skewness term of a VarianceSkewKurtosis had scale 1 and no floor, so expected_risk of the stored measure did not match the model. The weights did not move.
  • IntegerConditionalValueatRiskView did not reach the posterior of least divergence. On a 60-row example, the divergence falls from 0.0189 to 0.0175 for an upper bound, and from 0.0858 to 0.0415 for an equality. The view now warns when its window of sbar losses binds.
  • An IterativeWeightFinaliser that stalled or diverged reported success with weights that broke the bounds. It now returns the Euclidean projection of its input. A bound set that cannot hold the budget now fails, so the fallback chain runs.
  • A walk-forward that charged a turnover fee on a naive optimiser priced the fee against the reference weights w of its Turnover on every fold, never against the weights that the fold held. Buy-and-hold paid the most, and a constant rebalanced portfolio paid nothing. The fee is now charged against the previous weights that the fold loop passes on. The first fold's fee is the trade from those reference weights.
  • optimise(opt, rd; dims = 2) on MeanRisk, InverseVolatility or another optimiser that fits a prior fitted the prior on the transpose, and gave one weight per observation. prior(pe, rd; dims = 2) and the clustering calls on a prior result also read the transpose. Now dims has no effect.
  • Under MaximumRatio, the squared L2 penalty of RSOCRiskExpr, SquaredSOCRiskExpr and QuadRiskExpr scaled as k^2 ‖w‖^2, so its strength moved with ohf. The weights moved by 0.25 between ohf and 10 ohf. The penalty is now k ‖w‖^2, of degree one, as every other penalty is.
  • With a fee, a moment risk measure whose target is per asset centred the net returns on the gross mean, so each deviation carried the mean fee. A target is per asset when you state a mu vector, or when factory fills the prior mean. The target now subtracts the mean fee of each period, in the model and in the functor. This covers the low- and high-order moments, Kurtosis, MedianAbsoluteDeviation, the third central moment and the skewness.
  • LowOrderMoment(; w, alg = SecondMoment()), HighOrderMoment with a standardised algorithm and Skewness(; w) did not pass w to their variance estimator. So the functor ignored the weights in the variance. On one example it gave 2.7574, and the optimiser gave 2.9726.
  • expected_risk of a RiskTrackingRiskMeasure with IndependentVariableTracking and a fee charged the fee of w - wb, which is zero at wb, while the model charged the fee of w. With Fees(; l = 0.002) and a CVaR at w = wb, the functor gave about 0 and the model 0.002. The functor now reads the series of the model. The weights do not move.
  • A SemiDefinitePhylogeny dropped its penalty p tr(W) when any variance was in the model. It now drops the penalty only when the objective minimises that variance: MinimumRisk, MaximumUtility with l > 0, and the return form of MaximumRatio. A variance ceiling, MaximumReturn, MaximumUtility with l = 0 and the risk form of MaximumRatio keep the penalty, so their weights move. The same rule now holds for a SemiDefinitePhylogeny in the frc_ple of FactorRiskContribution, which v0.31 always penalised.
  • A RiskTrackingRiskMeasure with DependentVariableTracking of a semidefinite Variance, and a dependent RiskTrackingError, built the tracking variance on a second lifted matrix, which the rows of a SemiDefinitePhylogeny did not bind. The tracking variance now reads the lifted matrix of the optimiser.
  • An IntegerPhylogeny in the frc_ple of FactorRiskContribution had no effect. It now binds the factor weights.
  • Under FactorRiskContribution(; flag = true), the variance read the factor part b1 * w1 alone and omitted the off-factor weights. On one example the model value was 43 % below the variance of the returned weights. The variance now covers the whole decision vector.
  • Under RelaxedRiskBudgeting with FactorRiskBudgeting(; flag = true), the relaxed risk priced b1 * w1 alone. On one example psi was 0.219, and the standard deviation of the weights was 1.88. The marginal risks now read the asset weights.

Results that move

  • A clustering, phylogeny or centrality estimator at the default reads the returns data rd.X. v0.32 read the X of the prior, x_src = :prior. The two differ when the prior changes its returns: a factor prior gives a reconstruction of rank equal to the number of factors, a prior with a scenario cap keeps fewer rows, and a prior that fills a gap writes a value where the returns data holds none. State x_src = PriorSource() on the graph reader to keep the v0.32 numbers. Under a prior whose moment estimators carry a CoveragePolicy, an asset that has a gap in the rows that the graph reader reads now gets a zero weight, and the optimiser warns once and names the asset, because the default ce of a graph reader has no CoveragePolicy. State the same CoveragePolicy on the ce of the graph reader, or x_src = PriorSource(), to keep the asset.
  • Every regime statistic of RegimeAdjustedExpWeightedVariance and RegimeAdjustedExpWeightedCovariance divided a realised square by an estimated variance, and the inverse of an estimate is too large on average. So under a correctly calibrated model the regime multiplier read the risk too large. Under the default method the variance was 1.3 % too large at the default half-life of 40, and 5 % too large at a half-life of 10. A MahalanobisTarget block with fewer observations than assets gave a statistic of about 1e12. The statistic now divides by the exact bias that its method reads. Every default fit of a CrossSectionalFactorPrior moves, because its ve is a regime-adjusted variance and its pe holds a regime-adjusted covariance.
  • The default location of ExpWeightedVariance, ExpWeightedCovariance and the two regime-adjusted estimators started at zero and was not divided by the sum of its weights, so it estimated (1 - λ^k) times the mean, and its deviations kept part of the mean. The variance was 2.4 % to 36 % too large in the warm-up, and 3.5 % too large at a half-life of 10 after it. The default EstimatedCentring() takes the normalised exponentially weighted mean, and divides each squared deviation, or product of a pair, by its exact factor 1 + 1 / n_eff, or 1 + c_ij. The estimate is unbiased from the second valid return, and the first return of an asset gives no term, so an asset needs two valid returns. Under HAC the factor also reads the mean of each lagged product. ZeroStartCentring() gives the v0.32 location and its numbers. PreCentred() does not move. The defaults of ce, ve and pe of CrossSectionalFactorPrior use it now, but in v0.32 only ce did. The bullet on CrossSectionalFactorPrior below gives the v0.32 defaults.
  • ExpWeightedCovariance and RegimeAdjustedExpWeightedCovariance divide each pair by its own weight. On a holiday, v0.32 shrank each correlation that met the holiday towards zero, and on the separate correlation path a late listing shrank each correlation of the late asset towards zero. A sample with no holiday and no late listing keeps its numbers.
  • The two regime-adjusted estimators clamp the multiplier of an estimate only. v0.32 also clamped the multiplier of one before regime_min_obs, and the multiplier of regime_method = nothing, so a clamp with a lower bound above one inflated a variance that had no regime estimate.
  • RegimeAdjustedExpWeightedCovariance with a separate cor_decay reports the variance 0 for a constant asset, where v0.32 reported min_val.
  • Every default fit of a CrossSectionalFactorPrior moves. On one panel of 60 assets and 300 observations, mu moved by 82 % of its largest entry and sigma by 16 %. The new defaults that Renamed keywords and changed defaults lists cause most of it. These corrections also move a fit, and no keyword undoes them:
    • The idiosyncratic variance and the regime statistic read the active mask and the estimation mask. An asset that delisted and listed again kept its variance over the inactive stretch in v0.32, and the regime statistic read active assets outside the estimation universe.
    • The prior divides the weights of the scenarios of its factor prior by their sum.
    • Each asset reads the factor moments only on the support of its loadings, so a factor with no moment changes no asset with a zero loading on it, and the investable set holds each asset whose loadings read only factors with moments. The fit refuses only when no asset has such loadings.
    • An asset in the warm-up of its variance has a finite mean and finite systematic covariances. v0.32 wrote NaN over its whole mean, row and column. The asset is still not investable, because its variance is not finite.
    • The idiosyncratic correlation under a threshold th above zero reads the residuals with no fill. v0.32 read the residuals that the scenarios read, which fill a holiday or a late listing with the mean of the other assets, and so correlated the asset with each of them.
    • A return forecast with min_obs = 1 gives a forecast earlier in the history, and TargetReturnForecast calibrates prequentially. See the two bullets on them above.
  • An unseen member of a constrained factor family has a return of zero. The exposures lag the returns, so the zero-sum condition of an observation reads the benchmark weights of the observation before it. When the last asset of a member leaves the sample, the condition still weights the member, and the design is rank deficient. In v0.32 the solve algorithm of cre then gave the member a return that depended on the dropped member of the family. Under unseen = ZeroUnseenMember() the member has a return of zero at that observation, and the condition holds over the other members. The factor returns, mu and sigma move only on a panel with such an observation. State unseen = SolvedUnseenMember() to keep the v0.32 numbers.
  • A CrossSectionalFactorPrior reads the residual of an asset that is alone in its level as a gap. When an asset is the only member of its level of a one-hot factor at an observation, the regression fits its return exactly, so its residual is zero whatever the return. v0.32 divided that zero by the variance of the asset, so an asset with a positive variance got a scaled residual of zero, and an asset with a zero variance got the mean scaled residual of its observation. v0.33 gives every such asset that mean in the scenarios X, and the idiosyncratic correlation leaves it out, so sigma moves under a threshold th above zero. A design in which every such asset has a zero variance keeps its numbers, and so does a design with no such asset. State l1mask = UnmaskedLeverageOne() to keep the v0.32 numbers.
  • The chi-squared radius of a full covariance set reads N(N + 1) / 2 degrees of freedom, the free entries of a symmetric matrix. This moves the Normal ellipsoid, the Normal norm ball and the bootstrap ellipsoid under diagonal = false. v0.32 read N², so the set was too large for its level: at N = 5 and q = 0.05 the radius was 6.136 and now is 5.000, and the old set covered 0.999 of the errors at a stated 0.95. A bootstrap ellipsoid with M resamples reads at most M - 1 degrees of freedom, on both axes. State ChiSqKUncertaintyAlgorithm(; ambient = true) to keep the v0.32 numbers. The default diagonal = true and the bootstrap norm ball do not move.
  • The view of a CompactCovarianceUncertaintySet is the projection of the set. A hierarchical or clustered optimiser takes this view of a set that you fit before. v0.32 fitted the basis again on the view, so a cluster portfolio paid less than the full set charges it, by 6.9 % and 14.9 % of the penalty on two examples. Now it pays what the full set charges it. An OrthogonalUncertaintySet estimator inside the optimiser still fits on the data of the cluster.
  • A covariance or a correlation with a CoveragePolicy peels the assets of an undetermined pair. v0.32 wrote NaN at the cell of a pair whose assets share too few observations, and kept both assets. v0.33 removes the assets that the peel rule chooses, writes NaN across the row and the column of each, and warns with their indices. The mean and the variance do not move. A call with no such pair keeps its numbers. On a fold, the peel runs each time the folded estimator answers, on the counts folded so far, so a walk-forward warns at each step that has such a pair, and the removed set can change from one step to the next. State peel = NoPeel() to keep the v0.32 numbers.
  • The default leaf order is the exact optimal order. clusterise, the phylogeny estimators, DBHT and every hierarchical and meta-optimiser at the default branchorder = :optimal can give another order of the leaves. The order is the input of the recursive bisection, so the weights of HierarchicalRiskParity and of the Schur complement optimiser can move. The clusters and every cut do not move. State branchorder = :barjoseph to keep the v0.32 numbers.
  • An empirical Value at Risk reads the upper alpha-quantile of the returns. ValueatRisk and ValueatRiskRange under the default MIPValueatRisk(), DrawdownatRisk and RelativeDrawdownatRisk take the order statistic at position floor(alpha T) + 1, the definition of Equation 7.50 of [12]. v0.32 took the position floor((alpha - s) T) + 1 with the slack s = 1e-5. The two positions differ when alpha T is an integer, for example at the default alpha = 0.05 on 100, 200 or 1000 observations, where the value moves by one order statistic: on 100 normal returns from 1.727 to 1.596. They also differ when the fractional part of alpha T is below 1e-5 T, so on 100 000 observations or more the value moves at every alpha. The risk of the MIP model moves in the same way, so the weights of an optimiser that reads one of these measures can move. With observation weights, the position is the first one whose cumulative weight exceeds alpha times the total weight, where v0.32 took the first one that reached it. The default s is now 1e-9, and the cardinality row of the MIP adds it to alpha, where v0.32 subtracted it. The conditional measures do not move. No keyword gives the v0.32 position.
  • MaximumRatio with a variance on the lifted weight matrix maximises the Sharpe ratio. This is a Variance that the model states on the lifted matrix W, or a box, ellipsoid or norm-ball UncertaintySetVariance. v0.32 divided the excess return by the variance, not by its square root, so the weights moved. Risk contribution rows rc under MaximumRatio now relax as they do under MinimumRisk. State ratio_alg = LinearRatio() to keep the v0.32 ratio. It gives the v0.32 weights to about 2e-4.
  • A weighted LinearModel or GeneralisedLinearModel scales its weights to their Kish count. GLM reads weights as frequencies, so v0.32 read probability weights that sum to one as one observation: every p-value was 1, and the AIC and the BIC read n = 1. A StepwiseRegression inside an entropy pooling or opinion pooling prior then kept one factor for each asset. The coefficients do not move, but the selected factor sets, the p-values, the AIC and the BIC do. FrequencyWeights keep the v0.32 numbers.
  • CombinatorialCrossValidation puts every trailing row in the last fold. When mod(T, n_folds) >= div(T, n_folds), v0.32 put a trailing row in no fold, so the row was in every training set and in no test set: row 13 of 13 at n_folds = 5. The splits move in that case only.
  • The factor attribution of a held asset in the warm-up of its variance. Under the default unknown = EntrywiseUnknown() its exposures and its systematic numbers stay, and each number that reads the unknown variance is NaN, where v0.32 set the whole row to zero. The split and the standard error of a pair of leverage one are NaN, and a pair with no idiosyncratic return adds nothing to any component. A static loadings matrix reads every observation at any lag, and trim = true cuts it. A held asset with no return on an active cell is a holiday. A held asset that is not active warns, or raises under strict = true. The predicted totals set to zero the row of an asset that is not investable. No keyword gives the v0.32 numbers.
  • The readers of an asset panel read only the active, observed cells. FeatureDistance reads each asset and each pair at its own active rows, and an asset that it cannot read leaves the investable set at a fit. The panel collapse of NestedClustered and Stacking weighs only the members that are active at each observation, under pcol = RenormaliseActive(). A panel with no inactive and no unobserved cell keeps its numbers.
  • A RiskLoss reads the last window rows when its head holds more rows. A tracking or turnover ceiling in a ProgrammeAllocationSet with fixed = false follows the allocation of each step, where v0.32 held the weights that you passed.
  • A forecast evaluation keeps the weights of its book after a date with no asset that it can score, so the turnover of the book moves.
  • ForwardPanelFill and BackwardPanelFill stop at the edge of a stretch in which the asset is not active. v0.32 walked each column over the whole axis, so an asset that delisted and listed again took, at a blank first cell of its second listing, the last value of its first listing, and lim counted the inactive cells as part of the run. A column with one stretch of activity keeps its numbers.
  • opt_weight_bounds with a JuMPWeightFinaliser leaves your weight vector unchanged. Under the two relative formulations v0.32 wrote eps into each zero entry of the vector that you passed: [0.7, 0.3, 0.0] became [0.7, 0.3, 2.2e-16].
  • The cross-sectional diagnostics return a FactorDiagnosticResult. exposure_coverage and the other diagnostic verbs over a CrossSectionalFactorModel returned a Vector in v0.32. The vector is now the field X of the result, which also holds the names and the families of the factors.
  • prices_to_returns computes each return from the change in price, (p_t - p_{t-1}) / p_{t-1}, and the log return as log1p of it. v0.32 took the simple return through a logarithm and lost about three bits, and its log return cancelled. Each return can move in its last bits, and so can each value computed from it.
  • MaximumRatio with an ℓ1 constraint set or a fee takes the risk form. Both forms state one optimum, so a problem that solved in v0.32 keeps its ratio, and its weights can move within the tolerance of the solver.
  • MaximumRatio with BudgetCosts or BudgetMarketImpact solves for weights that no longer move with ohf. v0.32 gave sum(w) + cost of 0.877 at ohf = 2.5e-4 and 0.970 at ohf = 1e-3, where the budget states 1.
  • BudgetMarketImpact under a constraint scale sc other than one. The power cone of the charge did not scale its middle entry, so the charge grew by sc^((1 - beta) / beta), and the weights stayed near the start portfolio w. At the default sc nothing moves.
  • The mean of BodnarOkhrinParolya divides its beta by the quadratic form of the target, as equation 7 of [58] states, where v0.32 divided by that of the sample mean. Every target of the library is a multiple of the vector of ones, so the three targets now give the same estimate.
  • The monotonic search of the Schur complement optimiser refines below tol and reaches the boundary where the augmented block stops being positive definite, so its gamma can move to a value of lower variance. A repaired block is written back after the repair, so a later split augments the repaired block.
  • UlcerIndex and RelativeUlcerIndex read the weights of the prior, as every other drawdown measure does. Under a weighted prior the index moves. Under no weights it does not.
  • The blended inverse-variance weights of a CrossSectionalFactorPrior with zero variances take the limit as those variances go to zero. With half or more of the variances of an observation zero, v0.32 dropped the inverse-variance part of the row, so the row summed to 1 - lambda, and with every variance zero it took the cap weights alone. A quantile level of the clamp that lands on an order statistic beside a zero variance gave no bound, and now gives that order statistic.
  • MultipleRandomised draws each start of a window, the last one included. A seeded draw can move.
  • An entropy pooling prior over a factor prior keeps the model of the fit that its views read. EntropyPoolingPrior and MeucciEntropyPoolingPrior over a FactorPrior or a FactorBlackLittermanPrior fitted the regression again under the posterior weights, so the scenarios moved, and a mean view missed mu: a view of 0.004 read 0.0040224 on one example. The posterior now weighs the same scenarios and keeps the loadings, the intercepts and the residual variances, so each mean view holds on mu.   • A high order prior fits its coskewness and cokurtosis under the weights of the prior that it wraps.   • A prior(...) reference in a skewness or kurtosis view reads the weights of the prior. In EntropyPoolingPrior and MeucciEntropyPoolingPrior, v0.32 read the skewness or the kurtosis of the reference from the scenarios with no weights.   • The covariance of an entropy pooling or opinion pooling posterior takes the correction of reliability weights, 1 / (1 - sum(p .^ 2)), where v0.32 took T / (T - 1). Under a view, sigma grows by the factor (n_eff / (n_eff - 1)) / (T / (T - 1)), with n_eff = 1 / sum(p .^ 2): by 2.2e-3 with one mean view on 60 observations.   • AdaptiveSubgradient takes the step of a zero gradient in its own norm. A RiskLoss gives a zero gradient while the head holds fewer than two rows. v0.32 took the Euclidean projection of the weights at such a step. v0.33 projects in diag(delta + s).   • A projection in the entropic, Tsallis or log-barrier geometry on a ProgrammeAllocationSet sets each weight at or below sqrt(eps) to its floor, zero unless the set states a positive floor. v0.32 raised only a negative weight to zero, so the sign of the rounding of the solver decided whether a weight that the set forces to zero could recover.
