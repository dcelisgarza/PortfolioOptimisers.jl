Distance

PortfolioOptimisers.Distance — Type
struct Distance{__T_power, __T_alg} <: AbstractDistanceEstimator

Pairs a distance algorithm with an optional integer power, and applies it to a correlation matrix or to the data.

Every clustering, network and phylogeny routine uses this estimator to get a distance matrix. alg selects the transform. power raises the input of that transform to the integer power $p$.

Note

power = 1 gives the base distance exactly, for every algorithm. Only $p \geq 2$ changes the result. power = nothing and power = 1 select different methods, so the base case never raises a matrix to a power.

Mathematical definition

The four correlation-based algorithms of RhoDistanceAlgorithm raise the correlation to $p$ inside their base formula.

\[\begin{align} _{g}d_{i,\,j}^{\mathrm{S}} &= \sqrt{\mathrm{clamp}\left(s\left(1 - \rho_{i,\,j}^{p}\right),\, 0,\, 1\right)}\\ _{g}d_{i,\,j}^{\mathrm{SA}} &= \sqrt{\mathrm{clamp}\left(1 - \lvert\rho_{i,\,j}\rvert^{p},\, 0,\, 1\right)}\\ _{g}d_{i,\,j}^{\mathrm{L}} &= \max\left(-\log{\lvert\rho_{i,\,j}\rvert^{p}},\, 0\right)\\ _{g}d_{i,\,j}^{\mathrm{C}} &= \sqrt{\mathrm{clamp}\left(1 - \rho_{i,\,j}^{p},\, 0,\, 1\right)}\\ s &= \begin{cases} 1/2 & \text{if } p \mod 2 \neq 0\\ 1 & \text{otherwise} \end{cases}\,, \end{align}\]

VariationInfoDistance has no correlation to raise, so it raises the distance itself.

\[\begin{align} _{g}d_{i,\,j}^{\mathrm{VI}} &= \left(d_{i,\,j}^{\mathrm{VI}}\right)^{p}\,, \end{align}\]

Where:

  • $_{g}d_{i,\,j}$: Generalised distance between assets $i$ and $j$. The superscript names the algorithm: S for SimpleDistance, SA for SimpleAbsoluteDistance, L for LogDistance, C for CorrelationDistance and VI for VariationInfoDistance.
  • $d_{i,\,j}$: Base distance of the algorithm.
  • $\rho_{i,\,j}$: Pairwise correlation coefficient between assets $i$ and $j$.
  • $p$: Integer power.
  • $s$: Scale factor of SimpleDistance only. $s = 1/2$ for an odd $p$, and $s = 1$ for an even $p$.

The two values of $s$ come from the range of $\rho_{i,\,j}^{p}$. $s$ keeps the radicand inside $[0,\,1]$, so $s = 1 / (1 - m)$, where $m$ is the smallest value that $\rho_{i,\,j}^{p}$ can take. An odd $p$ keeps the sign, so $m = -1$ and $s = 1/2$. At an even $p$, $\rho_{i,\,j}^{p}$ cannot be negative, so $m = 0$ and $s = 1$.

The clamp has no effect on the first two algorithms at any $p$, because $s(1 - \rho_{i,\,j}^{p})$ and $1 - \lvert\rho_{i,\,j}\rvert^{p}$ never leave $[0,\,1]$. It binds for CorrelationDistance at every odd $p$. There, $\rho_{i,\,j}^{p}$ keeps its sign and the radicand runs over $[0,\,2]$. The docstring of CorrelationDistance shows the truncation.

CanonicalDistance is a redirect and has no formula. It gives power to the algorithm that it selects.

`power` raises two different quantities

power is one field with two meanings. For a correlation-based algorithm, it raises the correlation inside the transform. For VariationInfoDistance, it raises the distance that the algorithm returns, because there is no correlation. So at $p = 2$, $_{g}d^{\mathrm{S}}$ is not $\left(d^{\mathrm{S}}\right)^{2}$, but $_{g}d^{\mathrm{VI}}$ is $\left(d^{\mathrm{VI}}\right)^{2}$.

The docstring of each algorithm states its base formula and its original source. The $p$ generalisation and the scale factor $s$ are this library's own extension of those formulas.

Fields

  • power: Optional integer exponent, which the distance algorithm applies entry by entry. Distance states which quantity it raises. nothing and 1 both give the base distance, so only power >= 2 changes the result.
  • alg: The distance algorithm.

Constructors

Distance(;    power::Option{<:Integer} = nothing,    alg::AbstractDistanceAlgorithm = SimpleDistance()) -> Distance

Keywords correspond to the struct's fields.

Why the default `alg` is `SimpleDistance`

CanonicalDistance selects an algorithm from the covariance estimator. It uses SimpleDistance for every estimator outside its table. A bare Distance() also works at the matrix entry point distance(de, rho), which has no estimator to select from. So the two defaults agree, except on the estimators in the table of CanonicalDistance. A library entry point that always has a covariance estimator uses Distance(; alg = CanonicalDistance()) as its default, so that each estimator in the table gets its own algorithm.

Validation

  • If power is not nothing, power >= 1.

Examples

julia> Distance()Distance  power ┼ nothing    alg ┴ SimpleDistance()

Compute the distance matrix from a feature matrix.

The 2-D method collapses nothing. A static feature matrix has no observation axis, so the collapse algorithm reads its one row. Its amsk is 1 × assets. The mask marks the assets whose every value column holds data, and the method refuses an asset that the mask marks false. The 3-D method dispatches on the collapse algorithm. An asset whose feature vector is all zero takes the convention that patch_zero_feature_vectors! states.

The 3-D method reads the mask amsk of the window. A collapse then reads each asset, or each pair of assets, at its own active rows, as each member of AbstractFeatureCollapseAlgorithm states. A window with no inactive cell gives the same result as no mask. The checks read the same cells as the collapse, so the value of a cell that amsk marks false changes neither the distance nor a refusal.

Algorithm

  1. Check dims with assert_dims.
  2. On the 2-D method, check the one-row mask with static_window and assert_feature_readable. Validate Z with assert_feature_matrix, and pass de.metric and Z to the kernel.
  3. On the 3-D method, check the mask with active_window, and check that the collapse can read each asset with assert_feature_readable.
  4. With no inactive cell, validate Z with assert_feature_matrix. Pass de and Z to feature_distance, which selects the method that de.alg names.
  5. Otherwise, put a zero at each inactive cell of a copy of Z with blank_unreadable. Validate the copy with assert_feature_matrix, and pass it to active_feature_distance.

Arguments

  • de: Feature distance estimator.
  • Z: Feature matrix, assets × features when dims = 1 and features × assets when dims = 2. It can also be a 3-D array of time-varying features, whose first axis is always the observation axis: observations × assets × features when dims = 1, and observations × features × assets when dims = 2.
  • dims: Dimension along which the computation runs.
  • amsk: The mask of readable cells of the window, observations × assets on the 3-D method and 1 × assets on the 2-D method, or nothing when every cell is readable.
  • nx: The asset names that a refusal quotes, or nothing to quote positions.
  • kwargs...: Additional keyword arguments (ignored).

Validation

  • dims in (1, 2).
  • amsk is observations × assets on the 3-D method and 1 × assets on the 2-D method, and the collapse can read each asset. See assert_feature_readable.
  • !isempty(Z).
  • Each cell of Z that amsk marks readable is finite and lies in the domain of de.metric. See assert_metric_domain. The check reads no cell that amsk marks false.
  • On the 3-D method, a pair of assets with no shared active row takes the rule of the pair field of AggregateDistances and StackObservations.

Returns

  • D::MatNum: Distance matrix assets x assets, in the units the distance algorithm defines.

cor_and_dist(de::FeatureDistance, ::Any, X; pr = nothing, rd = nothing, kwargs...)

Compute the similarity and distance matrices of the Feature Matrix that feature_matrix stacks from pr and rd, for the clustering and network estimators.

clusterise and the network estimators call this method. It reads its arguments as the three-argument distance method does. It ignores the second positional argument and dims, it passes X to a producer, and it resolves the panel from pr and rd.

Algorithm

  1. Stack the Feature Matrix with feature_window, which resolves the panel and cuts it to de.sel and to the observation rows that de.alg reads. It also returns the mask of the readable cells of those rows. A cell is readable when the asset is active and every value column of de.sel holds data, observed or filled.
  2. Compute the similarity matrix S and the distance matrix D of that stack with the two-argument method at dims = 1, with that mask and the asset names from feature_asset_names.

Arguments

  • de: Feature distance estimator.
  • The second positional argument: ignored. It exists so that this method matches the signature that every consumer calls.
  • X: Returns matrix of the subproblem, observations × assets. A producer reads it.
  • pr: Prior result or returns result. Both carry the asset returns matrix X, so either can supply it.
  • rd: The returns result to use.
  • kwargs...: Additional keyword arguments (ignored), dims among them.

Validation

  • The panel resolves. asset_panel raises an IsNothingError that names the site when it does not.
  • Under de.strict = true, every entry of de.sel names a Panel Field, a level, a label or a group that the panel holds. Raises an ArgumentError. Under de.strict = false, such an entry warns, and the estimator drops it.
  • The stacked Feature Matrix passes assert_feature_matrix at dims = 1 at its readable cells. It is not empty, and each cell that the mask marks readable is finite and lies in the domain of de.metric. The value of an unreadable cell causes no refusal.
  • The collapse can read each asset at the readable rows of the window. See assert_feature_readable. A pair with no shared readable row takes the pair rule of its collapse. A fit drops an unreadable asset at its entry with feature_readable_mask, and this call refuses it.

Returns

  • S::Matrix{<:Number}: Similarity matrix, assets × assets, derived from D under de.sim.
  • D::MatNum: Distance matrix assets x assets, in the units the distance algorithm defines.
