Asset scorers

An asset scorer gives one score to each asset from the whole returns data. ScoreSelector and RedundancySelector take a scorer in their score field, in the place of a risk measure. A risk measure scores each asset on the whole training window. A scorer can score each asset over the folds of a cross-validation scheme, inside the training window of the selector.

Scores over the test windows

FoldRiskScorer evaluates a risk measure on each test window of a cross-validation scheme, and aggregates the values over the windows. One window of bad luck then does not decide the rank of an asset. Each window scores only the assets that it covers, so an asset with a gap in one window keeps its score from the other windows.

The aggregation sets the rule, and its statistic sets what the rule reduces. Value keeps the raw value of the measure, so a window of high volatility weighs more in a mean. Rank replaces each value with the rank of the asset in its window, so each window weighs the same.

PortfolioOptimisers.FoldRiskScorer — Type
struct FoldRiskScorer{__T_r, __T_cv, __T_agg, __T_min_folds} <: AbstractAssetScorer

Scores each asset with a risk measure on each test window of a cross-validation scheme, and aggregates the values over the windows.

One window of bad luck then does not decide the rank of an asset. The score of an asset reads its own column alone, so the training rows do not change it. The scheme gives the windows only. agg sets the rule of the aggregation, and its alg sets whether it reduces the raw values with Value or the ranks with Rank.

Mathematical definition

\[\begin{align} v_{i k} &= r\left(\boldsymbol{x}_{T_{k},\, i}\right)\,, \\ s_{i} &= A\left(\left\{ g_{i k} : k \in \mathcal{F}_{i} \right\}\right)\,. \end{align}\]

Where:

  • $v_{i k}$: The value of the risk measure on the returns of asset $i$ over the test window $T_{k}$.
  • $r$: The risk measure r.
  • $\boldsymbol{x}_{T_{k},\, i}$: The returns of asset $i$ at the rows of the test window $T_{k}$.
  • $T_{k}$: The $k$-th distinct test window of split(cv, rd).
  • $g_{i k}$: The statistic of asset $i$ on window $T_{k}$. It is $v_{i k}$ under Value, and the rank of $v_{i k}$ among the covered assets of the window under Rank.
  • $\mathcal{F}_{i}$: The windows whose Coverage Universe holds asset $i$.
  • $A$: The aggregation agg.
  • $s_{i}$: The score of asset $i$.

The scorer evaluates each distinct window once. A CombinatorialCrossValidation split puts each test block in many splits. A count of each split weighs some blocks more than others. A MultipleRandomised split draws asset subsets. The scorer ignores them, because the score of an asset does not depend on the other assets.

A window scores only the assets of its own Coverage Universe, the assets whose return is finite and active at every row of the window. An asset with a gap in one window keeps its score from the other windows. Under Rank, a window ranks only the assets that it covers.

An asset that fewer than min_folds windows cover has the score NaN. Every selection rule and every redundancy algorithm drops a NaN score, so a selector drops that asset and the run does not stop. Inside a selector the training window is already reduced to its Coverage Universe, so the case occurs on a direct call, or with a min_folds above one.

Algorithm

  1. Read the orientation bib of r with bigger_is_better.
  2. Take the distinct test windows of split(cv, rd) with distinct_test_windows.
  3. For each window, find the positions live of the covered assets with cv_live_assets.
  4. Evaluate r on the covered columns of the window with asset_scores, and turn the values into statistics with fold_statistic.
  5. Collect the statistics of each asset over the windows that cover it into stats.
  6. Reduce the statistics of each asset that at least min_folds windows cover with fold_aggregate, under the orientation from statistic_bigger_is_better. Write NaN at every other asset. min_folds_scores does this step.

Fields

  • r: The AbstractBaseRiskMeasure that scores the returns of each asset on each test window.
  • cv: Cross-validation estimator.
  • agg: The AbstractFoldAggregation that reduces the statistics of each asset over the windows.
  • min_folds: The smallest number of test windows that must cover an asset. An asset that fewer windows cover has the score NaN.

Constructors

PortfolioOptimisers.Rank — Type
struct Rank <: AbstractFoldStatistic

Replaces the value of the risk measure on each test window with the percentile rank of the asset in that window.

The rank reads the orientation of the measure, so the best asset of a window takes the lowest rank, whether the measure is a risk or a reward. The rank is free of the scale of the window, so a window of high volatility weighs no more than a calm one. It is also free of the number of assets, so two windows that cover different assets give comparable ranks.

Mathematical definition

\[\begin{align} p_{i} &= \frac{n^{<}_{i} + n^{\leq}_{i}}{2 n}\,. \end{align}\]

Where:

  • $p_{i}$: The rank of asset $i$ in the window, strictly inside the open unit interval.
  • $n$: The number of assets that the window covers.
  • $n^{<}_{i}$: The number of covered assets that are strictly better than asset $i$ under the orientation of the measure.
  • $n^{\leq}_{i}$: The number of covered assets that are better than asset $i$ or equal to it, asset $i$ included.

A tie shares the average of the ranks that its members take with no tie. The best asset of a window with no tie has the rank $1 / (2 n)$, and the worst has $1 - 1 / (2 n)$. A lower rank is better, so the statistic has the orientation false.

Rank() -> Rank

Examples

Scores from the weights of an optimiser

WeightMassScorer runs an optimiser or a pipeline through a cross-validation scheme, and scores each asset by its mean weight or by how often it gets a weight. The score needs the whole cross-section of each fold, so no risk measure on one asset can state it.

PortfolioOptimisers.WeightMassScorer — Type
struct WeightMassScorer{__T_opt, __T_p, __T_cv, __T_tol, __T_min_folds, __T_ex} <: AbstractAssetScorer

Scores each asset by the mean weight, or by the selection frequency, that an optimiser gives it over the splits of a cross-validation scheme.

The score reads the whole cross-section of each fold, so no risk measure on one asset column can state it. opt is an optimisation estimator or a Pipeline. p is an optional grid of configurations, in the form that GridSearchCrossValidation takes, and the scorer pools the folds of every configuration.

Mathematical definition

\[\begin{align} m_{i} &= \frac{1}{\lvert \mathcal{K}_{i} \rvert} \sum_{(c, k) \in \mathcal{K}_{i}} w^{(c, k)}_{i}\,, \\ f_{i} &= \frac{1}{\lvert \mathcal{K}_{i} \rvert} \sum_{(c, k) \in \mathcal{K}_{i}} \mathbf{1}\left\{ \left\lvert w^{(c, k)}_{i} \right\rvert > \tau \right\}\,. \end{align}\]

Where:

  • $m_{i}$: The mean weight of asset $i$, the score when tol is nothing.
  • $f_{i}$: The selection frequency of asset $i$, the score when tol is a number.
  • $\mathcal{K}_{i}$: The pairs of a configuration $c$ and a split $k$ whose optimisation succeeded and whose split offered asset $i$.
  • $w^{(c, k)}_{i}$: The weight of asset $i$ in the portfolio that configuration $c$ fits on the training window of split $k$.
  • $\tau$: The tolerance tol.

A split offers the assets of the Coverage Universe of its training window, and also every asset that the fold made investable. A MultipleRandomised split offers only the assets of the subset that it drew. An asset that a selector inside opt drops was offered, so it counts with weight zero. An asset outside the drawn subset was not offered, so it does not count. Without this rule, an asset that a random draw seldom picks gets a low score by chance.

The scorer reads the result of each split once. Under CombinatorialCrossValidation, cross_val_predict gives a population of paths, and one split is in many paths. A failed split counts in neither the sum nor the count. The mean weight is signed, so a short position lowers it, and the frequency reads the absolute weight. A bigger score is better for both.

Warning

The scorer runs $C K$ optimisations, for $C$ configurations and $K$ splits. Inside a Pipeline under search_cross_validation, the cost multiplies again by the outer folds and the outer candidates. The scorer keeps no cache.

Warning

An asset that fewer than min_folds successful splits offered has the score NaN, and every selection rule drops it. Under MultipleRandomised, a draw of asset subsets can miss an asset completely. A selector then drops that asset only because the random draw did not offer it, and not because of its weight. More subsets in the draw make this less probable.

Algorithm

  1. Fix the random draw of cv with pin_draw, so that the split and the predictions use the same splits.
  2. Split rd once, and find the assets that each split offers with split_offered.
  3. Build the candidates of the grid with weight_mass_candidates.
  4. Run cross_val_predict on each candidate, and find the prediction of each split with split_prediction.
  5. Keep each prediction whose optimisation succeeded, and turn it into the record of the split with split_weight_record.
  6. Count the records that offered each asset.
  7. Return the mean of the record values of each asset that at least min_folds records offered, over those records, and NaN at every other asset. min_folds_scores does this step.

Fields

  • opt: The optimisation estimator or the Pipeline whose weights score the assets.
  • p: The grid of configurations of opt, in the form that GridSearchCrossValidation takes. nothing scores opt alone.
  • cv: Cross-validation estimator.
  • tol: The tolerance of the selection frequency. A number scores the share of the splits in which the absolute weight of the asset exceeds it, and nothing scores the mean weight.
  • min_folds: The smallest number of successful splits that must offer an asset. An asset that fewer splits offered has the score NaN.
  • ex: Parallel execution strategy.

Constructors

fold_statistic(alg::Rank, v::VecNum, bib::Bool) -> VecNum

Turn the values of a risk measure on one test window into one statistic for each covered asset.

The Value method returns v. The Rank method returns the percentile rank that the docstring of Rank defines.

Algorithm

The Rank method runs these steps:

  1. Orient the values with drop_scores, so that a bigger entry of u is a worse asset.
  2. Sort u into s.
  3. For each entry of u, count with cross_sectional_rank_counts the entries of s strictly below it and those at or below it.
  4. Divide the sum of the two counts by 2n, and return the ranks.

Arguments

  • alg: The statistic.
  • v: The values of the risk measure on one test window, one entry for each covered asset.
  • bib: The bigger_is_better flag of the risk measure.

Returns

  • stat::VecNum: One statistic for each entry of v, in the same order.
