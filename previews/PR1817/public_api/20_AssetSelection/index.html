Asset selection

An asset selector removes assets from the returns data. It can drop constant columns, keep the best or worst assets by a risk measure, or remove redundant assets. A selector is an ordinary preprocessing estimator of returns, and it does not depend on a pipeline. A Pipeline calls fit_preprocessing and apply_preprocessing on it, as on any other step.

A selector chooses its assets on the training window, and that choice is its fitted result. Applied to a later window, the fitted result keeps the same assets and does not choose again. The test window never changes the choice, so you can use a selector inside cross-validation.

Every selector subtypes PortfolioOptimisers.AbstractAssetSelector.

Scoring assets with a risk measure

A ScoreSelector computes a risk measure on the returns of each asset alone, and passes the scores to a rule. It accepts any risk measure whose supports_precomputed_returns is true, which includes the quantile and drawdown measures, the moment measures and MeanReturn. bigger_is_better tells the ordinal rules which end of the order is the best.

Variance and StandardDeviation do not work here. They are WeightsInput measures, which take portfolio weights and not a series of returns, so they cannot score one asset, and the constructor throws an error for them. Use SCM(), which computes the same quantity from a series of returns. ZeroVarianceFilter builds that selector for you.

Selection rules

A rule turns the scores into a mask of the assets to keep. ThresholdRule compares the raw scores with fixed bounds, and ignores which end is better, because a zero-variance filter must drop the assets with low variance. RankRule and QuantileRule read bigger_is_better, and take a count or a fraction of the assets from each end.

An ordinal rule drops every asset of a tie at its cut, so it can keep fewer assets than you ask for. If the 20th and 21st assets have the same score, RankRule(; best = 20) keeps 19. The rule drops both tied assets, because it has no reason to keep one of them and not the other.

PortfolioOptimisers.AbstractSelectionRule — Type
abstract type AbstractSelectionRule <: AbstractAlgorithm

Abstract supertype for the rules that turn the scores of the assets into a keep-mask.

A selection rule is an AbstractAlgorithm. A ScoreSelector uses it, and it has no use on its own. There are two kinds of rule.

  • Literal. ThresholdRule compares a score with absolute bounds, and it ignores bigger_is_better. A threshold on a variance is the variance that it states. The rule does not read it as "keep the better assets". That change inverts the purpose of a ZeroVarianceFilter.
  • Ordinal. RankRule and QuantileRule sort the assets from the best to the worst, and take a count or a fraction from each end. bigger_is_better sets the order, so :best is the lowest risk for a risk measure and the highest value for a return measure.

PortfolioOptimisers.ThresholdRule — Type
struct ThresholdRule{__T_lo, __T_hi} <: AbstractSelectionRule

Keep the assets whose score is strictly inside the band (lo, hi).

Both bounds are optional, and both are literal. The rule compares lo and hi with the raw score, and bigger_is_better does not change them. A bound that the caller omits sets no limit on that side.

Mathematical definition

\[\begin{align} \mathcal{K} &= \left\{ i : l < s_{i} < u \right\}\,. \end{align}\]

Where:

  • $\mathcal{K}$: The set of the assets that a selector keeps.
  • $s_{i}$: The score of asset $i$. It is the value of the risk measure on the return series of asset $i$ alone.
  • $l$: lo, the lower bound. An omitted bound is $-\infty$.
  • $u$: hi, the upper bound. An omitted bound is $+\infty$.

Both comparisons are strict, so the band is open. The rule drops an asset whose score is equal to $l$ or to $u$.

  • hi: The exclusive upper bound on the score. nothing sets no upper bound.

PortfolioOptimisers.RankRule — Type
struct RankRule{__T_best, __T_worst, __T_action} <: AbstractSelectionRule

Take a number of assets from each end of the order of the scores, then keep them or drop them.

best and worst are counts that the rule takes from each end, not positions. best = 20 means twenty assets, not the asset at rank twenty. bigger_is_better of the score sets which end is the best. For a risk measure, RankRule(; best = 20) keeps the twenty assets with the lowest risk. For MeanReturn, it keeps the twenty with the highest return. A rule with both counts takes both ends. action = :drop takes the complement of the selection. With it, a rule can drop the five worst assets with no knowledge of the size of the universe.

A count saturates at the number of assets. On a window of 30 assets, best = 50 keeps all 30 and does not throw. A hyperparameter search over best then does not fail at its largest value.

Warning

The rule excludes every asset of a tied block at the cut, so it can return fewer assets than the count. If the 20th and the 21st assets have equal scores, RankRule(; best = 20) keeps 19. The rule drops the tied block, and it does not split the block arbitrarily.

This is the tie policy of the library: if the library cannot tell two assets apart, it keeps neither of them. find_uncorrelated_indices has the same policy. It removes both assets of a correlated pair whose drop scores are equal. A window whose scores are all equal selects no asset, and fit_preprocessing throws.

Mathematical definition

\[\begin{align} \mathcal{T}(k) &= \left\{ i : a_{i} + e_{i} \leq k \right\}\,, \\ \mathcal{S} &= \mathcal{T}_{\mathrm{best}}(k_{b}) \cup \mathcal{T}_{\mathrm{worst}}(k_{w})\,, \\ \mathcal{K} &= \begin{cases} \mathcal{S} & \text{keep} \\ \left\{ 1,\, \dots,\, N \right\} \setminus \mathcal{S} & \text{drop} \end{cases}\,. \end{align}\]

Where:

  • $\mathcal{K}$: The set of the assets that a selector keeps.
  • $s_{i}$: The score of asset $i$. It is the value of the risk measure on the return series of asset $i$ alone.
  • $N$: Number of assets.
  • $k$: The number of assets that a rule takes from one end of the order of the scores.
  • $\mathcal{T}(k)$: The tail of size $k$, at the end that the subscript names.
  • $a_{i}$: The number of assets whose score is strictly better than $s_{i}$. At the best end, a larger score is better when bigger_is_better is true, and a smaller score is better when it is false. The worst end reverses this order.
  • $e_{i}$: The number of assets whose score is equal to $s_{i}$. The number includes asset $i$, so $e_{i} \geq 1$.
  • $k_{b}$, $k_{w}$: The counts best and worst, each saturated to $[0,\, N]$. An omitted count is $0$.
  • $\mathcal{S}$: The union of the two tails, before the rule applies action.

Two facts follow from this definition. A tail admits asset $i$ only when the whole tied block of $i$ fits in $k$. A tail excludes a block that crosses the cut, so $\left| \mathcal{T}(k) \right| \leq k$. If all the scores are equal, $a_{i} + e_{i} = N$ for every asset, so every tail of size $k < N$ is empty.

Fields

  • best: The number of assets to take from the best end. nothing takes no asset.
  • worst: The number of assets to take from the worst end. nothing takes no asset.
  • action: :keep keeps the assets that the rule takes, and :drop keeps all the other assets.

Constructors

PortfolioOptimisers.QuantileRule — Type
struct QuantileRule{__T_best, __T_worst, __T_action} <: AbstractSelectionRule

A RankRule whose tail sizes are fractions of the asset universe.

best and worst are fractions in (0, 1). The rule converts each fraction to a count with round(Int, fraction * n, RoundNearestTiesUp) on the window that it fits. An exact half rounds up. For example, best = 0.625 on a window of 4 assets takes 3 assets, and not the 2 that the default RoundNearest of Julia gives.

The other behaviour is the same as for RankRule. bigger_is_better sets the order, action = :drop takes the complement, a count saturates, and the rule excludes a tied block that crosses the cut.

Fractions and counts have separate types on purpose. If one rule took both, best = 1 is one asset and best = 1.0 is the whole universe. Only the type of the literal tells the two apart.

Mathematical definition

\[\begin{align} k &= \left\lfloor f N + \frac{1}{2} \right\rfloor\,. \end{align}\]

Where:

  • $k$: The number of assets that a rule takes from one end of the order of the scores.
  • $N$: Number of assets.
  • $f$: The fraction best or worst, in $(0,\, 1)$.

The floor of $f N + 1/2$ is the rounding mode RoundNearestTiesUp. An exact half rounds up, and not to the even neighbour that the default RoundNearest of Julia selects. The two counts are then the $k_{b}$ and the $k_{w}$ of RankRule, which states the admitted set.

  • worst: The fraction of the universe to take from the worst end. nothing takes no asset.
  • action: :keep keeps the assets that the rule takes, and :drop keeps all the other assets.

Discarding redundant assets

A RedundancySelector removes assets whose returns carry the same information as the returns of other assets. Its alg field decides what counts as redundant, and its score field decides which asset of a redundant group stays.

PairwiseCorrelation removes one asset at a time until no remaining pair has a correlation above the threshold, and it does not follow chains. CorrelationComponents follows chains of the same correlations. If A is close to B and B is close to C, it puts A, B and C in one group and keeps one of them. It removes more assets than PairwiseCorrelation, and on the same data it can keep a different set. ClusterGroups groups the assets with clusterise and keeps one asset per cluster.

If you leave score as nothing, the two correlation algorithms keep the asset with the lowest summary correlation to the rest of the universe. ClusterGroups has no such default, and it needs a score.

ClusterGroups is also the only redundancy algorithm that takes a distance estimator, and so the only one that can group assets by a feature matrix in place of their returns. The other two take a StatsBase.CovarianceEstimator. Give its cle field a FeatureDistance, and the groups come from data outside the returns. For example, a sector classification, held as a categorical field of the asset panel through panel_input, leaves one asset per sector, not one per group of correlated assets. The selector reads the panel directly from the ReturnsResult, because asset selection runs before a prior exists. An asset panel estimator that reads a prior throws an error here, and PhylogenyPanel, which reads none, works.

PortfolioOptimisers.AbstractRedundancyAlgorithm — Type
abstract type AbstractRedundancyAlgorithm <: AbstractAlgorithm

Abstract supertype for the algorithms that select which assets a RedundancySelector drops as redundant.

Each algorithm takes the data, and a score for each asset when the selector has one. It returns a keep-mask of the columns that survive. The interface returns a keep-mask, not a partition into groups. PairwiseCorrelation drops one asset at a time, and it can keep two members of one correlated group. A partition with one survivor for each group cannot show that selection.

Two algorithms do make a partition, and both use groups_argbest:

  • CorrelationComponents makes a group of each connected component of the graph whose edges are the correlations at or above the threshold.
  • ClusterGroups makes a group of each cluster that clusterise assigns.

PortfolioOptimisers.PairwiseCorrelation — Type
struct PairwiseCorrelation{__T_ce, __T_t, __T_absolute, __T_measure} <: AbstractRedundancyAlgorithm

Greedy removal of correlated assets. The algorithm drops assets until no pair of the kept assets has a correlation of t or more.

The algorithm reads the correlated pairs from the most to the least correlated, and it removes the worse asset of each pair. The worse asset has the higher drop score. The drop score comes from the score of the RedundancySelector when it has one. Otherwise it is the summary of the correlation of each asset with the rest of the universe. Then the asset that is redundant with most of the universe goes first.

This algorithm does not chain. Take t = 0.7, and a universe with ρ(A, B) = 0.80, ρ(B, C) = 0.81 and ρ(A, C) = 0.32. With the default drop score, the algorithm removes B and keeps both A and C, because their correlation is below t. CorrelationComponents reads the same three correlations as one chain, and keeps only A.

The two edges of a chain set a lower bound on the correlation of its end points. Two edges at ρ give the end points a correlation of ρ² - (1 - ρ²) or more. Thus a chain of two edges at 0.97 cannot have end points with a correlation below 0.88. A chain whose end points have a low correlation needs weak edges, and the two algorithms differ most when t is just below those edges.

The algorithm calls find_uncorrelated_indices.

Mathematical definition

\[\begin{align} \rho_{i,\,j} &< t \quad \forall\, i \neq j \in \mathcal{K}\,. \end{align}\]

Where:

  • $\rho_{i,\,j}$: Pairwise correlation coefficient between assets $i$ and $j$. The algorithm reads the absolute value $\left| \rho_{i,\,j} \right|$ when absolute is true.
  • $t$: The correlation at or above which two assets are redundant.
  • $\mathcal{K}$: The set of the assets that a selector keeps.

The condition is about the pairs of kept assets, and about nothing else. It does not say that $\mathcal{K}$ is the largest such set. It is also not transitive. A chain of two edges at or above the threshold, whose end points are below the threshold, meets the condition with both end points kept.

Fields

  • ce: The covariance estimator that gives the correlation matrix.
  • t: The correlation at or above which two assets are redundant.
  • absolute: If true, the algorithm compares the absolute value of the correlation with t.
  • measure: The measure that collapses each column of the correlation matrix into the fallback drop score. The algorithm ignores it when the selector has a score.

PortfolioOptimisers.CorrelationComponents — Type
struct CorrelationComponents{__T_ce, __T_t, __T_absolute, __T_measure} <: AbstractRedundancyAlgorithm

Group the assets by the connected components of a correlation graph, and keep the member of each group with the best score.

Two assets share an edge when their correlation is at or above t. When absolute is true, the algorithm compares the absolute value of the correlation. A component is transitive, so the algorithm reads a chain A ~ B ~ C as one redundant group, also when A and C are not correlated. It keeps one asset of the group. This claim is stronger than that of PairwiseCorrelation, and it removes more assets. Use it to keep one representative of each correlated group, and not to bound the correlation of the pairs that survive.

A component whose best score is tied keeps no asset. groups_argbest states the tie policy.

Mathematical definition

\[\begin{align} \mathcal{E} &= \left\{ \left\{ i,\, j \right\} : i \neq j\,,\; \rho_{i,\,j} \geq t \right\}\,. \end{align}\]

Where:

  • $\mathcal{E}$: The edge set of the redundancy graph, whose vertices are the assets.
  • $\rho_{i,\,j}$: Pairwise correlation coefficient between assets $i$ and $j$. The algorithm reads the absolute value $\left| \rho_{i,\,j} \right|$ when absolute is true.
  • $t$: The correlation at or above which two assets are redundant.

The groups are the connected components of that graph, and every asset is in exactly one group. An asset with no partner at or above the threshold is a group of one. A component is transitive, but the edge relation is not. This is the difference from PairwiseCorrelation. A chain $i \sim j \sim k$ is one component, whatever the value of $\rho_{i,\,k}$.

Fields

  • ce: The covariance estimator that gives the correlation matrix.
  • t: The correlation at or above which two assets are redundant.
  • absolute: If true, the algorithm compares the absolute value of the correlation with t.
  • measure: The measure that collapses each column of the correlation matrix into the fallback drop score. The algorithm ignores it when the selector has a score. A lower value is better, so the representative that survives is the least redundant member of its component.

struct ClusterGroups{__T_cle} <: AbstractRedundancyAlgorithm

Group the assets into clusters, and keep the member of each cluster with the best score.

clusterise makes the clusters, so every clustering estimator of the library can set what "redundant" means. This includes hierarchical linkage, DBHT, the non-hierarchical algorithms and the estimators of the optimal number of clusters. A cluster whose best score is tied keeps no asset. groups_argbest states the tie policy.

Clusters on a Feature Matrix

A FeatureDistance in the distance field of cle measures a Feature Matrix in place of the returns. It makes that matrix from the AssetPanel on rd, the returns data that the selector fits on.

Preselection runs before the prior, so it gives rd alone. fit_preprocessing fits a selector from the returns data alone, and the selector never gets a prior result. In a Pipeline, the selector writes :returns, and this invalidates a :prior that an earlier step computed. Thus a panel producer that needs a prior raises an error here, and the error names this site. Put an AssetPanel on the ReturnsResult, for example from asset_panel. Otherwise clusterise throws.

The cle reads rd.X, the returns as the selector gets them, because a selector fits before a prior or a benchmark frame exists. For this reason, the cle states no source, and the constructor refuses a cle whose x_src is not nothing.

The algorithm selects on the full universe, and the library slices the columns that survive after the selection. The library measures the Feature Matrix Z over every asset, before the selector drops one.

The Feature Matrix takes its column names from the same panel as its values. Thus a FeatureDistance with a sel selects the same feature columns here as at every other site. Without a sel, the Feature Matrix holds the value columns of every Panel Field, with one column for each level of a categorical field. A redundancy selector on all of these columns can drop assets on a distance that the caller did not intend.

Turn the scores of the assets into a keep-mask under a selection rule.

bib is the bigger_is_better flag of the score that gave scores. ThresholdRule ignores it.

There is one method for each rule. The ThresholdRule method compares each score with the open band, and returns the mask. The RankRule method gives its two counts to tail_action_mask. The QuantileRule method first converts each fraction to a count with round(Int, f * n, RoundNearestTiesUp). Then it gives the two counts to the same function.

Arguments

  • rule: The selection rule.
  • scores: The score vector assets × 1, with one score for each asset.
  • bib: The bigger_is_better flag of the score that gave scores.

Returns

  • keep::BitVector: The mask assets × 1. It is true for every asset that the rule admits.

The method calls find_uncorrelated_indices. A greedy search gives the set of kept assets, so it is not always the largest such set.

    rd::AbstractReturnsResult,
    scores::Union{Nothing, AbstractVector{<:Union{Number, AbstractJuMPScalar}}},
    bib::Bool
) -> BitVector

Keep one representative of each correlated group under CorrelationComponents.

Algorithm

  1. Compute the correlation matrix rho of rd.X with the ce of the algorithm.
  2. When absolute is true, replace each entry of rho with its absolute value. This step comes before the threshold, so a strongly negative correlation is an edge.
  3. When scores is nothing, collapse each column of rho with measure into the fallback score s, and set sbib to false. A lower summary correlation is then better, so the representative that survives is the asset least correlated with the rest of the universe. Otherwise take s from scores and sbib from bib.
  4. Group the assets with correlation_components on rho and t.
  5. Return the mask that groups_argbest admits for those groups under s and sbib.

  • scores: The score vector assets × 1, or nothing.

PortfolioOptimisers.requires_score — Function
requires_score(_::AbstractRedundancyAlgorithm) -> Bool

Return whether a redundancy algorithm needs a score to select the survivor of a redundancy group.

The correlation algorithms return false. With no score, they use a summary of the correlation of each asset with the rest of the universe. ClusterGroups has no such fallback, and it returns true.

The generic method returns true, so a RedundancySelector asks a new algorithm for a score until the algorithm declares otherwise. This is the safe default. Without it, an algorithm with no fallback can get nothing in place of a score vector. It then has no data to select a survivor from.

Arguments

  • The method takes the algorithm by type alone. It reads no field of it.

Returns

  • req::Bool: true when the algorithm cannot select the survivor of a group without a score.
