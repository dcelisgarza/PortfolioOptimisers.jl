PortfolioOptimisers.factory — Method
factory(a::Union{Nothing, AbstractEstimator, AbstractAlgorithm,

factory(a::AbstractVector{<:Union{Nothing, AbstractEstimator, AbstractAlgorithm,
                                  AbstractResult}}, args...; kwargs...) -> Vector

Rebuild an estimator, an algorithm or a result with runtime values. These two methods are the fallbacks of the verb.

factory and port_opt_view are the two propagation mechanisms of this library. factory passes runtime values, such as prior moments, observation weights and previous portfolio weights, down a tree of composed structs. port_opt_view passes an index selection, a subset of the assets, down the same tree.

The vector method is the one forwarding contract for every propagation field that holds a vector. It applies factory to each element, and it forwards args... and kwargs... with no change. A family that accepts a vector of estimators, algorithms or results needs no method of its own. A family that needs more than the forward defines its own, more specific method. A concrete element type, through concrete_typed_array_if_abstract, is an example.

Algorithm

The scalar method:

  1. Return a with no change, and drop args... and kwargs.... This method is the leaf of the recursion. Because of it, a call of the verb on a type with no tags returns the value and raises no error.

The vector method:

  1. For each element ai of a, call factory on ai, and forward args... and kwargs... with no change.
  2. Collect the results into a new vector, in the order of a, and return it.

A @propagatable struct always has a generated method that is more specific than the scalar method. If the struct has at least one @fprop or @wprop field, that method builds the struct again with its keyword constructor. It sends each @fprop field through factory_child and each @wprop field through _wprop. If the struct has no such field, that method returns x.

Arguments

  • a: An estimator, an algorithm, a result or nothing, which the scalar method returns with no change. For the vector method, a vector of them, which it rebuilds one element at a time.
  • args...: Positional arguments. The scalar method ignores them, and the vector method forwards them.
  • kwargs...: Keyword arguments. The scalar method ignores them, and the vector method forwards them.

Returns

  • a: The input with no change, for the scalar method.
  • v::Vector: The rebuilt elements, for the vector method.

Examples

julia> factory(nothing, 1, 2; x = 3)julia> factory(MeanValue())MeanValue  w ┴ nothing

Statistics.cov — Method
Statistics.cov(ce::AbstractCovarianceEstimator, X::MatNum; dims::Int = 1, kwargs...)

Computes the covariance matrix from the correlation matrix of the estimator and the standard deviations of its variance estimator ce.ve.

With this fallback, a covariance estimator that computes a correlation needs only its own Statistics.cor method. The fallback scales the correlation matrix by the standard deviations from std(ce.ve, X). An estimator whose covariance is not a scaled correlation defines its own method. ImpliedVolatility is one such estimator.

Mathematical definition

\[\begin{align} \hat{\mathbf{\Sigma}}_{ij} &= \hat{\rho}_{ij}\,\hat{\sigma}_i\,\hat{\sigma}_j\,. \end{align}\]

Where:

  • $\hat{\mathbf{\Sigma}}$: Estimated covariance matrix.
  • $\hat{\rho}_{ij}$: Correlation between assets $i$ and $j$.
  • $\hat{\sigma}_i$: Standard deviation of asset $i$.

Algorithm

  1. Estimate the correlation matrix with Statistics.cor(ce, X).
  2. Estimate the marginal standard deviations with Statistics.std(ce.ve, X).
  3. Scale the correlation matrix into a covariance matrix with StatsBase.cor2cov!. The call writes in place, over the matrix that step 1 returned.

Arguments

  • ce: Covariance estimator.
  • X: Data matrix observations × assets if the dims keyword does not exist or dims = 1, assets × observations when dims = 2.
  • dims: Dimension along which the computation runs.
  • kwargs...: More keyword arguments, passed to cor and to the variance estimator.

Returns

  • sigma::MatNum: Covariance matrix assets x assets.

A moment other than the expected return can use every deviation from the target, FullMoment, or only the deviations below the target, SemiMoment. An estimator that has both forms takes one of these two types in its alg field.

PortfolioOptimisers.FullMoment — Type
struct FullMoment <: AbstractMomentAlgorithm

Keeps every deviation from the target, so the moment is two-sided.

Mathematical definition

\[\begin{align} \boldsymbol{D} &= \boldsymbol{X} - t \end{align}\]

Where:

  • $\boldsymbol{X}$: Data vector observations × 1.
  • $t$: Target value. It is usually the expected value $E[\boldsymbol{X}]$, weighted or unweighted.

struct SemiMoment <: AbstractMomentAlgorithm

Clips every deviation above the target to zero, so the moment measures only the downside.

Mathematical definition

\[\begin{align} \boldsymbol{D} &= \min\left(\boldsymbol{X} - t,\, 0\right) \end{align}\]

Where:

  • $\boldsymbol{X}$: Data vector observations × 1.
  • $t$: Target value. It is usually the expected value $E[\boldsymbol{X}]$, weighted or unweighted.
