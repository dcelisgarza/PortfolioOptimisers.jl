struct CalibrationContext{__T_alpha, __T_series, __T_p, __T_cs} <: AbstractResult

Holds the facts that a calibration site knows and the key of the slot does not give, from resolve_calibration_slot into the rule that it runs.

The site runs a rule as alg(key, pr, w, slv, ctx). key names the slot and not the quantity. For example, RelativisticValueatRisk and RelativisticDrawdownatRisk both use :kappa, and they price different series. So the quantities below are properties of the site and not of the key, and the site states them in this type.

FieldThe site that states itThe rules that read it
alphathe slot owner, off a sibling slot it resolved firstEntropyBudget, HillTailDecay, RadialTailDecay, TailTermParity
seriesthe slot owner, through calibration_seriesHillTailDecay, RadialTailDecay, ConcentrationRadius, DimensionalRateRadius, DualNormRadius, TailTermParity
pthe constraint or the penalty the quantity stands inEffectiveAssetFloor, DualNormRadius
csa CrossSectionalFactorPrior, after the split of its Return ForecastPrecisionBlend, SteinShrinkage, ForecastCalibrationSlope

No rule has a field for these quantities. Each one belongs to the site, and a rule cannot know which site it reached. So a site overwrites no value of the rule, and no precedence between the two is necessary. A caller who runs a rule outside a measure builds the context that the site builds. That context is the only place where these quantities are written.

Only the Cross-Sectional Factor Prior states cs. Its Spanned Shrinkage lambda and its Orthogonal Forecast Scale c resolve inside prior, after the prior splits the Return Forecast and before it makes the mean. The prior states cs = (; g, ap, csfm, hist, cre). These are the spanned coefficients g, the unscaled orthogonal part ap, the factor-model block csfm, the Return Forecast history hist and the Cross-Sectional Regression Estimator cre of the prior. The block holds the idiosyncratic variance history vs and the regression weights rw, so a rule reads them from csfm. The block holds a zero b and no Return Forecast, because the scale is not resolved yet.

The default is the context of a site that states nothing. It has no sibling significance level, no norm order and no cs. Its series is the ReturnsSeries that calibration_series returns for every owner that names no other series. A rule that needs a field that the default leaves at nothing refuses, and its message names that field.

alpha is available only because the slots of one owner resolve in an order. A deformation rule reads the significance level of a sibling slot. So the resolve_deferred_quantities method of the owner resolves alpha first, and puts the number in the context of the slot that reads it. No derivation can find that order, so each type writes its own resolution.

Fields

  • alpha: Significance level of a sibling slot that the owner resolved first, or nothing when the site gives none. The resolution method of the owner resolves alpha first, and it puts the number in the context of the slot that reads it.
  • series: The series that the slot owner prices: ReturnsSeries, AbsoluteDrawdownSeries or RelativeDrawdownSeries. calibration_series gives it. A drawdown marker replaces each column of pr.X with the drawdown series of that column, and each rule reads the replacement in its own way.
  • p: Norm order against which the rule reads the quantity, or nothing when the site gives none. The order belongs to the constraint or to the penalty and not to the rule, so each site that has an order gives it here.
  • cs: The fit of a CrossSectionalFactorPrior as (; g, ap, csfm, hist, cre), or nothing when the site gives none. g holds the spanned coefficients of the Return Forecast, one per estimated factor. ap holds its unscaled orthogonal part, one per asset. Both are nothing when the prior has no Return Forecast Estimator. csfm is the CrossSectionalFactorModel block, with a zero b and no Return Forecast. It holds the idiosyncratic variance history vs and the regression weights rw. hist is the Return Forecast history from forecast_history, or nothing unless a slot answers true to reads_forecast_history. cre is the Cross-Sectional Regression Estimator of the prior. It splits a row of the history in the same way as the prior splits the latest forecast.

struct ScenarioCount{__T_n} <: AbstractSignificanceCalibrationAlgorithm

Computes a significance level from a count of scenarios, so that the tail keeps the same number of scenarios at every sample length.

A stated alpha fixes the probability of the tail. A fold of half the length then has half the scenarios in its tail, and the measure becomes less accurate as the sample becomes shorter. This rule fixes the count and returns n / T. So alpha * T is n at every sample length, and the tail of the measure holds n scenarios.

T is the row count of pr.X when no observation weights are stated, because the measure prices those rows. Under a Scenario Cap, the rows are fewer than the observations behind the moments, and the rule reads the rows. When weights are stated, T is the effective sample size of the weights. That is the number of equally weighted observations that gives the precision of the weighted sample. So a weighted tail holds n observations in that sense, and not n rows.

The rule does not check the range of its value. It returns the quantity of its slot, so the constructor of the slot owner does all the validation. That constructor refuses a value outside the range of the slot when the fold runs.

Computes a significance level that decreases with the square root of the sample length.

The tail probability is c / sqrt(T), so the expected count of the tail is c * sqrt(T). The count increases with the sample, but more slowly than the sample. The rule does not check the range of its value, for the reason that ScenarioCount states.

struct EntropyBudget{__T_target} <: AbstractDeformationCalibrationAlgorithm

Computes the Kaniadakis deformation parameter that makes a relativistic measure spend a stated entropy budget.

RRM multiplies its dual variable by kappa_log(inv(alpha * T), kappa), where T is the row count of the sample of the measure. So that coefficient is the price that the model pays for the deformation, and target states it. The rule returns the $\kappa$ that gives it. A stated kappa fixes the shape of the deformation and lets the price change with the sample. This rule fixes the price and lets the shape change. The Kaniadakis logarithm is Equation 63 of [169].

The rule reads its sibling alpha from ctx.alpha. So the resolution method of the owner resolves alpha first and puts the number in the context of the slot that reads it. A caller who runs the rule outside a measure states alpha in the context.

The coefficient is monotone in $\kappa$, and the rule inverts it by bisection over $(0, 1)$. Let $l = \ln(u)$. The coefficient is $l \sinh(\kappa l) / (\kappa l)$, and $\sinh(x)/x$ increases with $|x|$. So the coefficient moves once from $l$ at $\kappa \to 0$ to $\sinh(l)$ at $\kappa = 1$. The function $\sinh(x)/x$ has no elementary inverse, so the rule runs a fixed sequence of 64 halvings.

The band that the coefficient reaches changes with the sample, and the rule refuses a target outside the band when the fold runs. This check does not limit the range of the value that the rule returns. The constructor of the slot owner does that, as it does for the two significance rules. The check states that the equation has a root. With no check, a target outside the band stops the bisection at an end of the interval. That $\kappa$ is inside the range that the slot owner accepts, but it does not give the target.

Fields

  • target: Target value of the Kaniadakis logarithm. It is the coefficient by which RRM multiplies its dual variable. The rule returns the deformation parameter that gives this value.

So the default is nothing, which is not a budget, and the constructor refuses EntropyBudget(). The message names the budget and tells why the rule needs it. The keyword admits nothing only for this refusal, and the field never holds it.

Validation

  • target is stated, else an ArgumentError.
  • target is finite. The band of the target changes with the sample, so the rule checks the band when it runs, and not here.

PortfolioOptimisers.HillTailDecay — Type
struct HillTailDecay{__T_kmin} <: AbstractDeformationCalibrationAlgorithm

Computes the Kaniadakis deformation parameter whose tail decays at the rate of the tail of the sample.

The inverse of kappa_log is the $\kappa$-exponential $\exp_{\kappa}(x) = \left(\kappa x + \sqrt{1 + \kappa^{2} x^{2}}\right)^{1/\kappa}$ of Equation 53 of [169]. It approaches $(2 \kappa x)^{1/\kappa}$ for large $x$, as page 20 of [169] states. So a $\kappa$-deformed exponential tail is a power law of index $1/\kappa$, and $\kappa$ is the reciprocal of a tail index. The rule estimates the tail index $\hat{a}$ of the sample and returns $1/\hat{a}$, so the deformation decays at the rate of the sample. The band of the slot, $(0,\, 1)$, is $\hat{a} > 1$, which is the condition for a finite mean. So the rule refuses an estimate outside the band, as EntropyBudget refuses a target outside its band.

The estimator is that of [170], over the k most extreme order statistics of a pool. The rule centres each column of pr.X and divides it by its sample standard deviation. It gives the standardised values the sign of the end that the slot prices, and it pools all T * N of them. The rule reads only pr.X, and never pr.sigma. The dispersion of a column comes from that column. This is the difference from RadialTailDecay. This rule measures how far one end of one column moves, and its sibling measures how far the whole cross-section moves. So this rule keeps the sign of the end and gives one answer for each end. Its sibling reads a distance and gives one answer for both ends.

The pool has two assumptions:

  • The columns have one tail index after standardisation, so one estimate serves the whole sample.
  • The columns are cross-correlated. So the pool holds far fewer than T * N independent points, and the spread of the estimator is wider than the spread for k independent points.

The median of N estimates, one for each asset, needs neither assumption, but it is less accurate. At alpha = 0.05 and T = 250, a column has 13 tail points, and a Hill estimate on 13 points changes from fold to fold with no cause in the data.

alpha fixes the depth of the estimate as well as the count. A Hill estimate reads the tail at the depth that alpha names. If the tail of a sample approaches its power law slowly, the estimate has a bias that decreases as the depth increases. For example, a Student-t sample at a depth of five per cent gives a $\kappa$ above the reciprocal of its degrees of freedom. The same sample at a depth of one per cent gives a $\kappa$ that is nearer to it. The spread of the estimate increases as the count decreases, and kmin is the floor of that count.

key names the end that the slot prices, so the answer can be different for each key. :kappa and :kappa_a read the loss tail, and :kappa_b reads the gain tail. EntropyBudget is different, because its budget is a price that the model pays, so it gives one number for both ends. A tail index is a property of one tail, and a skewed sample has two different tail indices. On a Range measure, the rule gives the two ends two different numbers.

ctx.series names the quantity in the pool, and the slot owner states it. A measure of the return distribution pools the columns of pr.X. A drawdown measure pools the drawdown series of each column of pr.X, because it prices that quantity. The resolution site names the marker in ctx.series. The standardisation, the count and the estimator do not change. The pool then gives the tail index of the drawdown series and not of the returns, and the two numbers are different. AbstractDrawdownSeries states how the length of the record decides the difference.

The drawdown series of the columns stand for the drawdown of the portfolio, under the assumption of the pool. The rule makes no portfolio, so it pools the drawdown series of the columns, as it pools the columns on a returns series. The columns have one tail index after standardisation, and one map takes a column to its drawdown series. So the pool gives the same estimate as the drawdown series of the portfolio. A portfolio drawdown is smaller than the average asset drawdown, but that is a difference of scale, and a tail index does not read the scale.

A drawdown series has one entry for each observation. So the pool holds T N entries under every marker, and the count k = ceil(alpha * T * N) does not change. The change of series drops no observation.

A drawdown measure resolves the significance level of its own drawdown series. So under a drawdown marker, the rule reads its tail at the level of that series.

The pool of a drawdown series has more dependence than the pool of a returns series. A drawdown series is a running function of the path, so consecutive entries move together, and one deep drawdown fills many of the k order statistics of the estimate. So the T N entries hold far fewer independent tail points than the same count of returns, and the spread of the estimate is wider than the count suggests. kmin counts entries and not independent points, so the same floor gives less accuracy here. Use a larger kmin for a drawdown owner.

The rule does not check the range of the parameter that it returns. The constructor of the slot owner does that, as for every calibration rule. The checks of the rule state that the estimate exists.

Fields

  • kmin: Floor under the number of order statistics that the Hill estimate reads. The count is ceil(alpha * T * N) over the pool. The rule refuses a count below this floor, because a Hill estimate over too few order statistics changes from fold to fold with no cause in the data, and the deformation parameter changes with it.

Constructors

Keywords correspond to the fields of the struct. The default kmin = 30 is the floor of the count of order statistics that the estimate reads. The significance level and the series of the estimate are not fields of the rule. Both reach the rule in the CalibrationContext of the site.

Validation

struct RadialTailDecay{__T_kmin} <: AbstractDeformationCalibrationAlgorithm

Computes the Kaniadakis deformation parameter whose tail decays at the rate of the radial series of the sample.

The inverse of kappa_log is the $\kappa$-exponential $\exp_{\kappa}(x) = \left(\kappa x + \sqrt{1 + \kappa^{2} x^{2}}\right)^{1/\kappa}$ of Equation 53 of [169]. It approaches $(2 \kappa x)^{1/\kappa}$ for large $x$, as page 20 of [169] states. So a $\kappa$-deformed exponential tail is a power law of index $1/\kappa$, and $\kappa$ is the reciprocal of a tail index. The rule estimates a tail index $\hat{a}$ and returns $1/\hat{a}$, so the deformation decays at the rate of the sample. The band of the slot, $(0,\, 1)$, is $\hat{a} > 1$, which is the condition for a finite mean. So the rule refuses an estimate outside the band, as EntropyBudget refuses a target outside its band.

The rule reads a radial series. A covariance matrix is a scale and $\kappa$ is a shape. So a rule that gets a shape from a scale needs a second quantity to fix the units, and the sample is the only such quantity in a prior result. The covariance matrix turns the $T \times N$ sample into one univariate series. whitening_factor gives the factor of $\hat{\mathbf{\Sigma}}$, the rule centres and whitens each row, and the Euclidean norm of the whitened row is the Mahalanobis distance of that observation. Under an elliptical scale mixture, that series has the tail index of the mixture, and each entry reads the whole cross-section. A standardisation per column removes every off-diagonal term. So HillTailDecay cannot give this estimate, and this rule cannot give the estimate per column.

The rule reads no direction. A distance has no sign, so one $\kappa$ serves both ends of a Range measure, and the rule does not read key. HillTailDecay gives one answer for each end. A radial series measures how far the cross-section moves, and a series per column measures how far one end of one column moves. A head slot that defaults to its tail slot holds the same rule and gets the same number, and that is correct for a distance.

The series holds T entries, and the pool of HillTailDecay holds T N. So this rule reads fewer tail points from the same sample. At alpha = 0.05 and T = 250, the series has 13 of them. kmin is the floor of that count, in the same units as the floor of the sibling, so this floor refuses more samples. The rule refuses a count below the floor. The series has one point for each observation and not N, so its points have none of the cross-correlation of the pool.

series names the sample of the rows, and the slot owner states it. A measure of the return distribution whitens the rows of pr.X. A drawdown measure whitens the rows of the drawdown sample. calibration_series_matrix turns each column into its drawdown series, and the rule whitens the rows of that sample and takes their norms in the same way. So the radial series is the same function, and only its sample changes. On a drawdown sample, the distance is the depth of the whole cross-section in drawdown at one date. On a returns series, it is the distance that the whole cross-section moved.

A drawdown sample has its own moments, and the prior states none of them. pr.mu and pr.sigma are the moments of the returns, and no scaling of them gives the moments of a drawdown. So under a drawdown marker, the centre is the vector of column means of the drawdown sample. The factor is the Cholesky factor of the covariance matrix of that sample. radial_series_inputs makes this choice, so the precedence of pr.chol over pr.sigma applies to the returns series alone.

The rule does not use a third estimate of $\kappa$. The excess kurtosis $g$ of a Student-t distribution gives $\nu = 4 + 6/g$, and then $\kappa = 1/\nu$. That estimate reads the whole sample and not the tail. So it changes less than a Hill estimate, but it assumes the shape of the whole distribution and not only of its tail.

The rule does not check the range of the parameter that it returns. The constructor of the slot owner does that, as for every calibration rule. The checks of the rule state that the estimate exists. They do not refuse a covariance matrix that is almost singular. The whitening then reads the direction of the smallest eigenvalue of the sample, the radial series follows it, and that is a property of the covariance matrix.

The radial series holds one entry per observation, so this floor refuses a sample that the same floor over a pool accepts.

Computes an ambiguity radius from a chi-squared quantile, so that the ball becomes smaller as the sample becomes longer.

The radius is a scale, in the units of the series that the slot owner prices, times the square root of a chi-squared quantile divided by the sample size. It simplifies Theorem 3 and Equation 22 of [171]. For the estimating equation of the mean, $h(\boldsymbol{x}, \boldsymbol{\theta}) = \boldsymbol{x} - \boldsymbol{\theta}$, under the squared Euclidean cost, $T$ times the robust Wasserstein profile function converges to $\boldsymbol{H}^{\intercal} \boldsymbol{H}$, with $\boldsymbol{H} \sim \mathcal{N}(\boldsymbol{0}, \mathbf{\Sigma})$. The rule replaces $\mathbf{\Sigma}$ with $s^{2} \mathbf{I}$, so the law is $s^{2} \chi^{2}_{N}$. The radius of that work is the quantile of this law divided by $T$, for the squared cost. The rule takes its square root, because its slot multiplies a norm with no square. The isotropic covariance is an assumption of the rule and not of [171].

The chi-squared factor has no units and increases with the number of assets. So at a fixed confidence level, a wider universe gives a wider ball, and a longer sample gives a smaller ball.

scale gives the units. A radius multiplies a norm of the weight vector, so it is in the units of the loss around which the ball is drawn. A caller cannot get that number from the confidence level alone. scale = nothing reads the average per-asset dispersion of the series that the slot owner prices. That scale changes with the sample, as the rest of the rule does.

A drawdown owner gets a drawdown scale. DistributionallyRobustConditionalDrawdownatRisk measures the transport cost of its programme against the per-asset drawdown sample. T is the effective sample size when observation weights are stated, and the count of effective_sample_size with no weights otherwise. The radius prices the estimation error, and the error of a weighted estimate decreases with the effective sample size of the weights and not with the number of rows. RateRadius reads the length of the record and no weights, because its rate is a property of that length.

The rule does not check the range of its value. It returns the quantity of its slot, so the site that receives the number checks the range. resolve_calibration_slot refuses a radius that is not > 0 and finite. struct DimensionalRateRadius{__T_confidence, __T_scale} <: AbstractAmbiguityRadiusCalibrationAlgorithm

Computes an ambiguity radius that decreases at the dimensional rate of a Wasserstein ball, and not at the square-root rate.

The radius is the radius of Equation 8 of [172] with the constants $c_{1} = c_{2} = 1$, times a scale in the units of the series that the slot owner prices. It is the sample factor log(1 / (1 - confidence)) / T to the power 1 / max(N, 2). Equation 8 inverts the concentration bound of Theorem 3.4 of [172], which is Theorem 2 of [173] for the Wasserstein distance of order one. A ball of probability measures must contain the true measure, and not only the true mean, and the concentration bound needs that exponent for a measure.

The constants $c_{1}$ and $c_{2}$ depend on the dimension and on the light-tail condition of the bound. Section 3 of [172] states that the proof of Theorem 2 of [173] gives them, and that the ball that they give is larger than necessary. Neither work states them as numbers. The rule sets both to one. So the radius has the rate of the bound, but it is not a calibrated confidence bound. Theorem 3.4 of [172] excludes $N = 2$. At that dimension, Theorem 2 of [173] has an additional logarithmic factor, and the rule does not apply it. At N = 1 and N = 2, the rule gives the square-root rate of ConcentrationRadius and RateRadius.

The ball becomes only a little smaller over a wide universe. At N = 20 and T = 250, the factor T^(-1/20) is 0.76, and a record ten times longer gives 0.68. This is the curse of dimensionality of the Wasserstein ball. A square-root rate is a rate for the error of a mean, and this rule states a rate for a measure.

In practice the radius is conservative. Section 3 of [172] recommends that the radius come from a bootstrap or a cross-validation, and not from this bound, and Section 7.2 compares a holdout method with a k-fold cross-validation. A portfolio that a ball this wide prices can hold only cash. RateRadius is the form for such a grid. So calibrate the radius with that rule, and use this rule to know the rate.

Equation 8 of [172] has a second branch for a short record. Its exponent is 1 / a and not 1 / max(N, 2). The branch applies when $T < \ln(c_{1} / \beta) / c_{2}$, with $\beta = 1 - q$. With the constants of the rule, that is fewer than 3 rows at confidence = 0.95. The rule does not use this branch.

HillTailDecay does not give the a of that branch. The a of Equation 8 is the exponent of the light-tail condition $\mathbb{E}\left[\exp\left(\lVert \boldsymbol{\xi} \rVert^{a}\right)\right] < \infty$ of Assumption 3.3 of [172]. HillTailDecay estimates the index of a power-law tail, which does not meet that condition. So the two quantities have the same letter and different meanings.

N is the asset count, size(pr.X, 2), because the ball is over the assets. A factor prior has a smaller effective dimension, but the ball is still over the assets, so a factor prior does not change N.

scale gives the units, as for ConcentrationRadius. scale = nothing reads the average per-asset dispersion of the series that the slot owner prices.

DistributionallyRobustConditionalDrawdownatRisk prices a ball around the drawdown scenarios. The dimension of a scenario is still N, so the rate does not change. The site states the marker of the owner in ctx.series, and calibration_series_dispersion then reads the per-asset dispersion from the drawdown sample and not from pr.sigma. A drawdown column is a running function of its returns, so its dispersion is the larger of the two. So with scale = nothing, that owner gets a wider ball than a returns owner of the same sample. A stated scale has precedence, and it is the way to price a ball whose units are neither of the two.

T is the effective sample size when observation weights are stated, and the count of effective_sample_size with no weights otherwise, as for ConcentrationRadius. The rate is a statement of concentration, so it prices the effective sample size of the weights. RateRadius reads the length of the record and no weights, because its rate is a property of that length.

The rule does not check the range of its value, for the reason that ConcentrationRadius states.

  • scale: Scale of the radius, in the units of the series that the slot owner prices, or nothing to read the average per-asset dispersion of that series off the sample. The rate factor has no units, so this field gives the radius all of its units.

struct DualNormRadius{__T_confidence} <: AbstractAmbiguityRadiusCalibrationAlgorithm

Computes an ambiguity radius in the ground metric that its slot names, so that two slots of two different norms get two different numbers.

The eight radius slots of the library do not measure distance in one norm. A radius multiplies a norm of the weight vector, and the ground metric of the ball is the dual of that norm. For a loss that is linear in the sample point, Theorem 6.3 and Proposition 6.5 of [172] give the worst case over the ball as the sample mean of the loss plus the radius times the dual norm of the weights. So the l1 coefficient of JuMPOptimiser is a distance in the ∞-norm, and its linf coefficient is a distance in the 1-norm. This rule reads key, selects the ground metric of that slot, and returns the sampling error of the empirical measure in that metric. ConcentrationRadius and RateRadius return one number for every key. That is correct inside one measure, and not correct across the eight slots.

A linear loss reads the sampling error of the mean vector. The per-asset scale of that error is the dispersion of the series that the slot owner prices, divided by the square root of the effective sample size. The radius is a norm of that error vector, at the confidence level that confidence states.

The vector has no term for the error of the covariance matrix. A radius multiplies a norm of the weight vector, so it prices the part of the loss that is linear in the weights. The loss of a distributionally robust measure is linear in the sample point. The error of the second moment reaches the objective through the tail term and not through the ball. The tail term has its own coefficient, which TailTermParity sets. A radius with both errors prices one error two times.

confidence is a level per coordinate, and the rule does not correct it for the number of assets. The ∞-norm case is a maximum over N coordinates, so a level per coordinate is too low for it. A caller who wants a level over the whole vector states the corrected level, for example 1 - (1 - c) / N.

The rule leaves the correction to the caller, because the correction is large and it is a choice. A Bonferroni correction from 0.95 to 1 - 0.05 / N increases the quantile by about a third at four assets, and by more at twenty. Other corrections exist. A level over the vector for N correlated coordinates and one for N independent coordinates differ by an amount that only the correlation gives. So the rule uses the level per coordinate, and this docstring names the corrected level. A rule that corrects the level with no notice gives a caller a level that the caller did not ask for and cannot see.

The 1-norm case adds the per-asset errors, so it prices them as if they moved together. That is the worst case over the correlations, so it is the conservative choice for a radius. A form that reads the correlations gives a smaller ball, and this rule does not compute it.

A radius must not be too small, so the rule keeps the worst case. A radius that is too small gives a model that is robust to less than the caller asked for. That failure is silent: the optimisation solves, and the weights are not robust. A radius that is too large is visible, because the portfolio moves towards cash. The two errors are not symmetric, so the rule takes the error that a caller can see.

ctx.p serves the :lpreg_val slot alone. The ground metric of LpRegularisation is the metric of order $q$, with $1/p + 1/q = 1$, and key names the slot and not the norm order. The order belongs to the penalty, so that site states it in the CalibrationContext before it resolves the slot. The rule holds no order, so a caller who runs it outside that site states the order in the context. No other key reads it.

series gives the drawdown owner a drawdown scale. DistributionallyRobustConditionalDrawdownatRisk measures the transport cost of its programme against the per-asset drawdown sample. So its ball is a ball over drawdown scenarios, and the ground metric is a distance between two such vectors. Under a drawdown marker, calibration_series_dispersion reads the error scale from that sample. pr.sigma is not read, because it is a moment of the returns, and no scaling of it gives a moment of a drawdown. The ground metric does not change with the series. Only the vector of the norm changes.

The error scale of a drawdown series is too small, because of the record. A drawdown is a running function of the path, so its entries are strongly dependent down a column. $\hat{s}_{i} / \sqrt{T_{e}}$ prices a record of $T_{e}$ independent draws, and a drawdown sample does not have them. The rule does not correct for this, as it does not correct for the number of assets. A correction needs a model of the dependence, and the sample gives none. So the rule uses the scale of the quantity as if the record were independent.

T_e is the effective sample size of the weights when observation weights are stated, and the count of effective_sample_size with no weights otherwise, as for ConcentrationRadius.

The rule does not check the range of its value, for the reason that ConcentrationRadius states.

A sample with no dispersion gives a radius of zero, and the slot accepts it. Every entry of the dispersion vector is zero or more, so the radius is zero or more, and finite, for every admissible input. A sample whose columns never move gives an error vector of zeros, and a ball of no width is correct for it. The empirical measure is the only measure that such a sample supports, and the robust measure becomes the plain measure at the centre of the ball. In floating point, such a sample gives a very small number and not an exact zero. The > 0 check of the slot owner then passes, and the model prices a ball of almost no width. The two results have the same meaning.

struct TailTermParity{__T_ratio} <: AbstractAmbiguityTailWeightCalibrationAlgorithm

Computes the Esfahani-Kuhn tail weight that prices the tail term of the loss at a stated multiple of its mean term.

At $r \to 0$, the loss of DistributionallyRobustConditionalValueatRisk becomes $-\mathbb{E}[\boldsymbol{w}^{\intercal} \boldsymbol{\xi}] + l \, \mathrm{CVaR}_{\alpha}(\boldsymbol{w}^{\intercal} \boldsymbol{\xi})$, the mean-risk objective of Equation 26 of [172], where the tail weight is $\rho$. So l is the exchange rate between one unit of expected return and one unit of tail loss. Both terms have the units of the returns, so l has no units. But l is not independent of the scale of the sample. For returns that are independent over time, the mean of a return column increases with the horizon, and its CVaR increases about as the square root of the horizon. So the ratio of the CVaR to the mean decreases about as the square root of the horizon. A stated l = 1.0 thus prices the tail term at a much larger multiple of the mean term on a daily sample than on a monthly sample. One stated number is a different trade-off at each sampling frequency, and at each fit that changes the record.

The rule reads the units of the sample and nothing else, so the preference stays with the caller. ratio states how many mean terms one tail term is worth. The rule returns the l that gives this ratio on the sample of the prior result. ratio = 1 is parity, and ratio = 2 prices the tail term at two times the mean term on every sample.

A rule reads no portfolio, so it cannot make $\boldsymbol{w}^{\intercal} \boldsymbol{\xi}$. It reads the cross-section of the per-asset losses of the quantity that the slot owner prices. The mean-term scale $m$ is the mean of that pool, and the tail-term scale $c$ is the mean of the $\mathrm{CVaR}_{\alpha}$ of each column. The mean of the values per column is not the pooled $\mathrm{CVaR}_{\alpha}$, and the difference is intentional. A pooled tail comes from the worst columns, so the most volatile assets control it, and it gives a smaller weight. The measure prices a portfolio and not a single asset, so the rule uses the mean over the columns.

A caller cannot state a reference portfolio. The pooled cross-section gives the rate for equal weights, and a reference portfolio gives a more exact rate. But a reference portfolio makes the rule a second place where a portfolio enters the problem. resolve_calibration_slot gives a rule the Prior and nothing else, so a reference vector needs a separate route. The rule must also check the vector against the universe of each fold, and the caller must state it again when a subset view or a cluster changes that universe. The exchange rate is a property of the sample, and the cross-section with equal weights needs no second input. A caller who wants the rate at a portfolio computes l and states the number.

$m$ is negative for a sample with a positive expected return, and the rule takes $\lvert m \rvert$. No field states the sign. The slot does not accept a negative weight, and a sample with a negative expected return does not reverse the trade-off.

The rule reads its sibling alpha, because $c$ is a $\mathrm{CVaR}$ at the significance level of the measure. So the resolution method of the owner resolves alpha first and puts the number in ctx.alpha, as it does for alpha and kappa. A caller who runs the rule outside a measure states alpha in the context.

Both scales read the observation weights. They are sample statistics and not counts, so the rule reads a weighted sample with its weights. RateRadius and RateSignificance do not read w, because their rates are a property of the length of the record, and a moment is not.

ctx.series names the quantity of both terms, and the slot owner states it. DistributionallyRobustConditionalDrawdownatRisk also has the key :l, and its tail term is a $\mathrm{CDaR}$ of the drawdown series of the portfolio. A rule gets no portfolio, but it can make the drawdown series of each column, and the resolution site names the marker in ctx.series. Both terms then change together. The mean term is the mean drawdown of the pool, and the tail term is the mean of the $\mathrm{CDaR}_{\alpha}$ of each column. The rule computes it with ConditionalValueatRisk, because the tail mean of a drawdown column that is not positive is the $\mathrm{CDaR}$ of that column. So the rule and the measure that it calibrates use one definition.

The rule does not use a second meaning of l. l can be read as a coefficient of risk aversion and mapped from a mean-variance coefficient. But a variance penalty is quadratic in the weight vector, and a $\mathrm{CVaR}$ term is positively homogeneous, so the two objectives cannot be compared term by term. The map is correct at one reference portfolio only, and a rule gets no portfolio.

The rule does not check the range of the weight that it returns, for the reason that RateRadius states. The constructor of the slot owner checks it. The two refusals of the rule state that the ratio exists, as the check of EntropyBudget states that its root exists. A sample whose mean loss is near zero gives a very large weight, and that is correct for such a sample. No threshold separates a small mean loss from a smaller one.

struct EffectiveAssetFloor{__T_fraction} <: AbstractNormCeilingCalibrationAlgorithm

Computes a norm ceiling that keeps a stated fraction of the universe effective, so that the floor changes when the universe changes.

A bound on the norm of the weights is a floor on the effective number of assets. This rule states the floor as a fraction of the universe and not as a count. The asset count comes from the prior result, so a subset view, a cluster and a cross-validation fold each get the floor of their own universe. No count stays fixed to the universe for which a caller wrote it.

ctx.p is the norm order of the ceiling, and it belongs to the constraint. Each of the three constraint sites states it in the CalibrationContext before it resolves the slot. The rule holds no order, so a caller who runs it outside those sites states the order in the context.

The rule does not check the range of its value, for the reason that ConcentrationRadius states. resolve_calibration_slot checks that the ceiling is > 0 and finite.

Mathematical definition

\[\begin{align} m &= f N\,,\\ \mathrm{val} &= \begin{cases} m^{-1} & \textrm{if } p \textrm{ is infinite}\\ m^{1/p - 1} & \textrm{otherwise} \end{cases}\,. \end{align}\]

Where:

  • $\mathrm{val}$: Norm ceiling.
  • $m$: Effective number of assets that the ceiling keeps as a floor.
  • $f$: Fraction of the universe, the fraction field.
  • $N$: Number of assets.
  • $p$: Norm order of the constraint of the ceiling.

The effective number of assets of order $p$ is $N_{\mathrm{eff},\, p}(\boldsymbol{w}) = \left(\sum_{i} \lvert w_{i} \rvert^{p}\right)^{1/(1 - p)}$. So for $p > 1$, $N_{\mathrm{eff},\, p} \geq m$ is $\lVert \boldsymbol{w} \rVert_{p} \leq m^{1/p - 1}$. At $p = 2$, this count is the number that number_effective_assets gives. At every order, a portfolio with equal weights over $m$ assets gives exactly $m$. The exponent is also $-1/q$ for the conjugate order $q$, because $1/p - 1 = -1/q$. At $p = 1$ the ceiling is one for every $m$.

The infinite branch is the limit of the finite branch. $m^{1/p - 1} \to m^{-1}$ as $p$ increases. A cap of $1/m$ on the largest weight of a fully invested portfolio spreads it over at least $m$ assets. So the two branches agree, and as a caller increases $p$, the ceiling moves towards $1/m$.

Fields

  • fraction: Fraction of the universe that must stay effective. The rule multiplies this fraction by the asset count of the prior result, so the floor changes with the universe and not with a count that the caller fixes.
