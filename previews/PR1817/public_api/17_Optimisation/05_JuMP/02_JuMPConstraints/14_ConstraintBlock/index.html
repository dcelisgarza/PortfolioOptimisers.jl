Constraint Block

PortfolioOptimisers.ConstraintBlock — Type
struct ConstraintBlock{__T_wb, __T_sbgt, __T_gbgt, __T_lt, __T_st, __T_lcse, __T_cte, __T_gcarde, __T_sgcarde, __T_smtx, __T_sgmtx, __T_slt, __T_sst, __T_sglt, __T_sgst, __T_tn, __T_sets, __T_tr, __T_ple, __T_ccnt, __T_cobj, __T_ss, __T_card, __T_scard, __T_l2c, __T_lpc, __T_linfc, __T_l1, __T_l2, __T_lp, __T_linf, __T_xbgt} <: AbstractEstimator

Holds the feasible set of the weights of a programme, and the terms that the programme adds to the Objective Penalty.

The block is the Constraint Block of the glossary. It holds the slots that a JuMP optimiser and a programme Allocation Set share: the weight bounds, the leverage caps, the linear, cardinality, threshold and phylogeny constraints, the turnover and tracking constraints, the norm ceilings, the custom constraints and the four regularisation penalties. A slot never writes the objective. The owner of the block holds the net budget, the fees, the return term and the scalariser.

JuMPOptimiser holds a block in its field cbe. Its keyword constructor takes each slot of the block as a flat keyword, and opt.wb reads the slot of the block. So build a block directly only to give one feasible set to more than one optimiser.

Fields

  • wb: Weight bounds estimator or weight bounds.
  • sbgt: Short-side budget, sum(sw). A number pins it, and a BudgetRange bounds it. The realised short exposure is only bounded by default, so sbgt = 0.3 means at most 30% short unless xbgt pins the long/short decomposition. With bgt, it fixes the net and gross exposures only together. To constrain the gross exposure alone, see gbgt.
  • gbgt: Gross budget (leverage) constraint, sum(lw) + sum(sw). A number pins the gross exposure, and a BudgetRange bounds it. For example, BudgetRange(; lb = nothing, ub = 2.0) caps leverage at 2x. bgt and sbgt pin the net and gross exposures only together, but gbgt constrains the gross exposure alone and leaves the net exposure free. It needs weight bounds that admit short positions. The realised gross exposure is only bounded unless xbgt is set.
  • lt: Long-side minimum holding threshold.
  • st: Short-side minimum holding threshold.
  • lcse: Linear constraint set estimator(s). This is the one constraint slot that also admits an ExposureConstraintEstimator, so a row can name the members of another basis, such as factors. The generator writes the row again in asset space through the loadings of the prior. What reaches the model is an ordinary asset-space LinearConstraint either way.
  • cte: Centrality constraint(s). A CentralityConstraint, a vector of them, or an already-generated LinearConstraint. Resolved by centrality_constraints into the ctr slot of ProcessedJuMPOptimiserAttributes.
  • gcarde: Grouped cardinality constraint estimator.
  • sgcarde: Sub-grouped cardinality constraint estimator(s).
  • smtx: Sub-group selection matrix or estimator.
  • sgmtx: Sub-grouped selection matrix or estimator.
  • slt: Sub-group long threshold.
  • sst: Sub-group short threshold.
  • sglt: Sub-grouped long threshold.
  • sgst: Sub-grouped short threshold.
  • tn: Turnover constraint estimator(s).
  • sets: Sets used to map estimator values to assets.
  • tr: Tracking error constraint(s).
  • ple: Phylogeny constraint estimator(s).
  • ccnt: Custom JuMP constraint.
  • cobj: Custom JuMP objective.
  • ss: Optional scalar shrinkage parameter.
  • card: Global cardinality constraint.
  • scard: Sub-group cardinality constraint(s).
  • l2c: 2-norm ceiling on the weights. It bounds norm(w, 2) <= l2c * k, where k is the homogenisation variable, so the ceiling holds on the weights the result reports and the budget does not scale it. Smaller l2c forces a more evenly spread portfolio. Used as a diversification floor via the reciprocal: l2c = 1 / sqrt(m) requires at least m effective assets (inv(norm(w, 2)^2) >= m). Norm-constraint family with lpc and linfc. The bound is Num_NormCeilCal under the time-dependent wrapper, so the slot takes the ceiling itself, an AbstractNormCeilingCalibrationAlgorithm that computes it from the prior result, or a plain function of the same five arguments.
  • lpc: p-norm ceiling(s) on the weights at an arbitrary norm order. Each LpRegularisation supplies a norm order p and a bound val, enforcing norm(w, p) <= val * k. Smaller val forces a more evenly spread portfolio. Used as a diversification floor via the reciprocal: val = m^(1/p - 1) requires at least m order-p effective assets (sum(abs.(w) .^ p)^inv(1 - p) >= m). On weights whose absolute values sum to one, this count is number_effective_assets taken to an arbitrary order. Norm-constraint family with l2c and linfc.
  • linfc: ∞-norm ceiling on the weights. It caps the largest absolute weight, norm(w, Inf) <= linfc * k. So linfc = 0.2 caps the largest weight at 20% of a fully invested portfolio. Used as a diversification floor via the reciprocal: linfc = 1 / m spreads the portfolio across at least m assets. Norm-constraint family with l2c and lpc. The bound is Num_NormCeilCal under the time-dependent wrapper, so the slot takes the ceiling itself, an AbstractNormCeilingCalibrationAlgorithm that computes it from the prior result, or a plain function of the same five arguments.
  • l1: L1 regularisation coefficient. It is the ambiguity radius of a type-$\infty$ Wasserstein ground metric, whose dual norm is the 1-norm, so the bound is Num_AmbRadCal under the time-dependent wrapper and the slot takes an AbstractAmbiguityRadiusCalibrationAlgorithm that computes it from the prior result, or a plain function of the same five arguments.
  • l2: L2 regularisation term(s).
  • lp: Lp regularisation specification(s).
  • linf: L∞ regularisation coefficient. It is the ambiguity radius of a type-1 Wasserstein ground metric, whose dual norm is the $\infty$-norm, so the bound is Num_AmbRadCal under the time-dependent wrapper and the slot takes an AbstractAmbiguityRadiusCalibrationAlgorithm that computes it from the prior result, or a plain function of the same five arguments.
  • xbgt: Whether to pin the long/short decomposition exactly. When false (the default), lw and sw are upper bounds on the positive and negative parts of w, so bgt, sbgt and gbgt bound the realised exposures and do not pin them. A short budget of 0.3 then means at most 30% short. When true, the long/short binary indicators force lw == max(w, 0) and sw == max(-w, 0), so the budgets hold exactly, at the cost of turning the problem into a mixed-integer program. It reuses the indicators the cardinality, threshold and fee builders already create (see short_mip_threshold_constraints) rather than adding its own, and is ignored when the weight bounds admit no shorts.

Keywords correspond to the struct's fields. A slot typed TD_Option can hold a TimeDependent schedule in place of a static value, as the slot of the same name in JuMPOptimiser can.

lcse, sgcarde, smtx, sgmtx, slt, sst, sglt, sgst, tn and ple take a vector that mixes the members of their element type. The keyword constructor narrows it through narrow_mixed_vector.

Validation

  • If sbgt or gbgt is a number: it is finite and >= 0.
  • If lcse, cte, smtx, sgmtx, tn, tr, ple, l2, lp or lpc is a vector: !isempty.
  • If card, l2c, linfc, l1 or linf is a number: it is finite and > 0.
  • lp holds no norm-ceiling rule, and lpc holds no ambiguity-radius rule, see assert_penalty_coefficient_role and assert_norm_ceiling_role.
  • The shapes of scard, smtx, slt and sst agree, see assert_subgroup_mip_fields. The shapes of sgcarde, sgmtx, sglt and sgst agree, see assert_subgrouped_mip_fields.
  • If a slot holds an estimator keyed by name (name_keyed): !isnothing(sets).
  • If a slot holds a TimeDependent: the constructor runs again once for each entry of the schedule, see assert_time_dependent_substitution.

The checks that read a field of the owner as well, such as assert_gross_budget_admissible, run in the constructor of the owner.

port_opt_view(
    cbe::ConstraintBlock,
    i,
    X::AbstractMatrix{<:Union{Number, AbstractJuMPScalar}}
) -> ConstraintBlock{_A, _B, _C, _D, _E, _F, _G, _H, _I, _J, _K, _L, _M, _N, _O, _P, _Q, _R, _S, _T, _U, _V, _W, _X, _Y, _Z, _Z1, _Z2, _Z3, _Z4, _Z5, Bool} where {_A, _B, _C, _D, _E, _F, _G, _H, _I, _J, _K, _L, _M, _N, _O, _P, _Q, _R, _S, _T, _U, _V, _W, _X, _Y, _Z, _Z1, _Z2, _Z3, _Z4, _Z5}

Returns a copy of cbe restricted to the assets at the indices i.

The method of the owner calls it, see port_opt_view(opt::JuMPOptimiser, i, X).

Algorithm

  1. View at i the slots that can hold a value for each asset: wb, lt, st, smtx, sgmtx, slt, sst, sglt, sgst, tn, lcse, sets, ccnt and cobj. When smtx and sgmtx hold the same object, view it once, so that the two views are one object too. The same holds for slt and sglt, and for sst and sgst.
  2. View tr at i with X. A tracking measure gives X to the risk measure that it tracks.
  3. Keep every other slot. An estimator in cte, gcarde or sgcarde resolves its names against the viewed sets. A precomputed constraint in one of them keeps its width, because no view can narrow its matrix, see port_opt_view(::LinearConstraint, i). ple reads the viewed prior of the owner. The other slots hold no value for each asset.
  4. Rebuild the block with its keyword constructor, which checks the viewed slots again.

Arguments

  • cbe::ConstraintBlock: The block.
  • i: The indices of the assets that the view keeps.
  • X::MatNum: The returns matrix of the full universe, with one column for each asset.

Returns

  • ConstraintBlock: The block restricted to the assets at i.
