PortfolioOptimisers.AbstractPriorEstimator — Type
abstract type AbstractPriorEstimator <: AbstractEstimator

Abstract supertype for all prior estimators.

A prior estimator computes a prior result from asset returns, from factor returns, or from both. Every concrete prior estimator subtypes one of the families below.

Interfaces

To implement a new prior estimator, subtype the family that names the returns it reads, and hold every parameter in a field of the struct. The families are AbstractLowOrderPriorEstimator_A, AbstractLowOrderPriorEstimator_F and AbstractLowOrderPriorEstimator_AF for a low order estimator. They are AbstractHighOrderPriorEstimator_F and AbstractHighOrderPriorEstimator for a high order estimator. Then implement this method:

  • prior(pe::AbstractPriorEstimator, X::MatNum, F::Option{<:MatNum} = nothing, pnl::Option{<:AssetPanel} = nothing; dims::Int = 1, kwargs...) -> AbstractPriorResult: Estimate the prior from the returns matrices and the Asset Panel.

The family sets the signature. A member of the _A family declares F as args... and does not read it. A member of a _F family declares F::MatNum and requires it. A member of the _AF family, or of the high order root, declares F::Option{<:MatNum} = nothing and reads F when the caller gives it.

pnl is the Asset Panel of the ReturnsResult, and the ReturnsResult method gives it to every estimator. An estimator takes it and ignores it, unless the estimator fits on a panel, as CrossSectionalFactorPrior does. An estimator that wraps another over the assets passes pnl to it unchanged, so that the wrapped estimator can also fit on the panel. An estimator that wraps a prior over the factors does not pass it, because no panel describes a factor axis. An estimator that declares args... takes pnl there, and needs no other declaration.

The method returns the prior result of its own order. A low order estimator returns a LowOrderPrior, and a high order estimator returns a HighOrderPrior. An estimator that wraps another rebuilds the wrapped result with forward_prior, not with a hand-written constructor call. Every field that the wrapper does not name then keeps its value.

This file defines the ReturnsResult method of prior, so a new estimator does not implement it.

Arguments

  • pe: Prior estimator.
  • X: Data matrix observations × assets if the dims keyword does not exist or dims = 1, assets × observations when dims = 2.
  • F: Factor returns matrix, or nothing.
  • pnl: Optional AssetPanel, the panel that the returns data held. A wrapping prior forwards it unchanged, so that it can compose an estimator that is fitted on a panel. An estimator that reads no panel ignores it.
  • dims: Dimension along which the computation runs.
  • kwargs...: Additional keyword arguments passed to the nested estimators.

Returns

  • pr::AbstractPriorResult: Result object containing the estimated prior.

carry_folds (optional)

  • carry_folds(pe::MyPriorEstimator) -> Bool: Returns true when the carry fold of a CrossSectionalFactorPrior folds the prior as its factor prior, one row at a time.

A prior that returns true also implements two methods. partial_fit!(pe, f::MatNum) -> pe folds factor returns into a state that the prior holds, and prior(pe; strict::Bool = false) -> LowOrderPrior reads that state. The fallback returns false, which is correct for every prior. The cost of false is on the carry fold. FoldOrRefit fits the factor prior again over every carried factor return at each step, and FoldOnly refuses the prior.

returns_source (optional)

  • returns_source(pe::MyPriorEstimator) -> Option{<:AbstractReturnsSource}: Returns the source of the returns that the prior fits on. This is usually a field x_src::Option{<:AbstractReturnsSource}, which the keyword constructor checks with PortfolioOptimisers.assert_returns_source(x_src, PortfolioOptimisers.DATA_RETURNS_SOURCES, :MyPriorEstimator).

The ReturnsResult method of prior reads the source through this method, and the frame walk of an optimiser also reads it. The fallback returns nothing, so a prior with no method reads the raw returns rd.X. A prior that holds another reader in a field refuses a source on that reader, with PortfolioOptimisers.assert_inner_reader in its keyword constructor. The outer prior picks the returns.

keeps_observations (optional)

  • keeps_observations(pe::MyPriorEstimator) -> Bool: Returns true when the result carries one scenario for each observation that the prior receives, for every configuration and all data.

A prior that reweights observations, such as EntropyPoolingPrior, reads this method on the prior that it wraps. It reads the count of the scenarios of the wrapped prior before it fits that prior under the prior probabilities of a caller. When the wrapped prior returns true, the count needs no fit. Otherwise the count runs only the steps that drop rows. The wrapped prior fits once more only when no method of PortfolioOptimisers.scenario_count gives the count. The fallback returns false, which is correct for every prior and costs at most that one fit. A prior that drops rows, such as one that holds a Scenario Cap, keeps the fallback. A prior that wraps another returns the answer of the prior that it wraps.

PortfolioOptimisers.AbstractPriorResult — Type
abstract type AbstractPriorResult <: AbstractResult

Abstract supertype for all prior result types.

A prior estimator returns a prior result. The result holds the moments, the asset returns and the factor returns that the estimator computed.

The library has two prior result types. LowOrderPrior holds the returns, the mean and the covariance. HighOrderPrior holds the co-moments, and wraps a LowOrderPrior.

Interfaces

To implement a new prior result type, subtype AbstractPriorResult, hold every value in a field of the struct, and implement these methods:

  • reconstruct_prior(pr::AbstractPriorResult, patch::NamedTuple) -> AbstractPriorResult: Rebuild pr through its own constructor with patch applied. forward_prior calls it. Each result type writes its own method, because the method names the constructor and does not find it by reflection.
  • port_opt_view(pr::AbstractPriorResult, i, args...) -> AbstractPriorResult: Restrict pr to the assets at index i, for hierarchical and subset optimisation.

prior_field_values reads the field list from the type, so a result type that gains a field needs no other method. An @pprop field can name only a field of LowOrderPrior or of HighOrderPrior, because prior_result_property_pool writes those two types by name. check_propagatable_contracts refuses a name that only a new result type has.

Arguments

  • pr: Prior result.
  • patch: Named tuple of field overrides.
  • i: Asset indices the view keeps.
  • args...: Additional arguments the view reads.

Returns

  • pr::AbstractPriorResult: A prior result of the same type as the input.

Examples

PortfolioOptimisers.LowOrderPrior — Type
struct LowOrderPrior{__T_X, __T_o_X, __T_mu, __T_sigma, __T_chol, __T_w, __T_ens, __T_eoc, __T_kld, __T_ow, __T_rr, __T_fpr, __T_x_src, __T_ss_gaps, __T_pc} <: AbstractPriorResult

Carries the returns, mean and covariance a low order prior estimator produced.

Every low order prior estimator returns a LowOrderPrior. It holds the asset returns, the mean vector and the covariance matrix. It can also hold a Cholesky factor, the observation weights and three diagnostics of them, a factor block, and the original returns. The last fields record the source of the returns, the marks of a Shared Series cut, and the cache of an opinion pool. The constructor checks every field.

Fields

  • X: Data matrix observations × assets if the dims keyword does not exist or dims = 1, assets × observations when dims = 2.
  • o_X: The returns matrix of the caller when the X of the prior result is a different matrix, and nothing otherwise. The estimators that lift a factor-axis prior onto the asset axis overwrite X, with the reconstruction F * transpose(M) .+ transpose(b) or with scenarios of the factor model. o_X holds the asset returns that they received, over the same observations and the same assets. Read it as original_X, which is always a matrix, and not as this field.
  • mu: Expected returns vector assets × 1.
  • sigma: Covariance matrix assets × assets.
  • chol: Cholesky factorisation of the covariance matrix.
  • w: Observation weights of the fit of the prior, observations × 1, see ObsWeights, or nothing when the fit used no weights. It binds ens, eoc, kld and ow, which are diagnostics of it and counts of the moments that it weights, see forward_prior.
  • ens: Effective number of scenarios of the weights w, or nothing. An entropy pooling prior and an opinion pooling prior write exp(entropy(w)). It is a diagnostic of w, and w binds it, see forward_prior. It is not the count of the moments, which eoc states.
  • eoc: Effective number of observations of the moments, a tuple (T_mu, T_sigma) with one count for mu and one for sigma. An entry of nothing means size(X, 1). EmpiricalPrior writes the count of its me and of its ce from effective_observation_count. That is the Kish count of a weighted estimator, and the number of observations of the fit when a Scenario Cap max_scenarios keeps fewer rows in X. A pooling prior refits its prior under its weights w and keeps the counts of the refit. An estimator that reads w states the Kish count of w. w binds the field, see forward_prior. A wrapper forwards it. A consumer that needs a sample size reads it, and not the number of rows in X: the denoiser of a matrix that a prior assembles, a normal uncertainty set and a calibration rule.
  • kld: Kullback-Leibler divergence of w from the weights from which it came. It is a scalar against the prior observation weights for one reweighting, or one entry per opinion when an opinion pool made w.
  • ow: The penalised opinion probabilities of the opinion pool that made the result, one entry per opinion, or nothing when no pool made it.
  • rr: Regression result.
  • fpr: Prior result over the factor axis, or nothing. Its X is the factor returns matrix, so its moments describe factors and not assets. It has the same observations as the asset block.
  • x_src: The source of the returns on which the prior fitted, nothing or an AbstractReturnsSource. prior records the source that the prior estimator states. It does this when it fits on the returns data, and when it reads out the state of an online fold. nothing means that the fit stated no source, or that the caller gave a returns matrix, so a reader of the Result reads X as raw returns. The outer problem of a meta-optimiser reads it, see outer_returns_source.
  • ss_gaps: One mark for each observation of the returns data that the prior read, true at an observation that the prior dropped for a Shared Series gap, or nothing when it dropped none. The rows of X are the last size(X, 1) observations that the marks keep, so a reader that holds the returns data finds the observation of each row, see shared_series_record. prior writes it when it fits on the returns data, and when it reads out the state of an online fold. An optimiser writes it on the prior that it fits after its own cut. A returns-matrix method of prior drops no observation, so it leaves nothing.
  • pc: The cache of the opinion pool that made the result, (; X, w, pe2), or nothing. X holds the rows of pe1 that the opinions read, or nothing when the pool reads the returns. w holds the pooled weights, and pe2 holds the cache of the result of pe2. A pool fitted with cache_reg = true stores it. An entropy pooling prior that wraps the pool reads it when it fits again, so no opinion runs again. Every other fit leaves it nothing.

Keywords correspond to the struct's fields.

The factor block

A prior that a factor model fits carries two distributions. The fields of the LowOrderPrior hold the distribution over the assets. The field fpr holds the distribution over the factors, as a nested LowOrderPrior. A nested result, and not a set of flat fields with an f_ prefix, gives the factor distribution every field of a LowOrderPrior. These are w, ens, eoc, kld and ow as well as mu and sigma. A field added later also applies to it with no second edit. Its X is the factor returns matrix, over the same observations as the asset X.

fpr and rr are the factor block, and the constructor requires them together or not at all. rr projects the block onto the assets, mu ≈ rr.M * fpr.mu + rr.b. A factor distribution with no loadings has no relation to this asset axis.

The bound of rr is AbstractLoadingsRegressionResult. A member of that root carries the loadings matrix M, so the field admits a Regression and a CrossSectionalFactorModel. The bound selects by the loadings, and not by the method of the fit. Every check of the constructor on the block reads rr.M alone, and fpr is on the axis that the columns of M name. Every consumer of the field reads M, or reads L, which returns M when L is not set.

The field does not tell one property of the block, so a consumer that needs it must ask. A member fitted in a re-based Factor Family answers true to has_family_rebasis. Its fpr.sigma is then singular, because the raw factor axis is a linear image of the re-based axis. A projection through M stays correct, and HighOrderFactorPriorEstimator does such a projection. An inverse or a factorisation of fpr.sigma has no answer. The inverse raises no error, and returns a result whose scale looks usual. For this reason, BayesianBlackLittermanPrior refuses such a prior result.

The flat names read the nested block, so code written for the old shape still works. pr.f_mu, pr.f_sigma and pr.f_w return fpr.mu, fpr.sigma and fpr.w, or nothing when there is no factor block. pr.f_ens, pr.f_kld and pr.f_ow work in the same way. They are properties, not fields, so forward_prior and prior_field_values see only fpr.

Which read to use

Read the factor block as pr.fpr.mu. The flat names with the f_ prefix stay so that code written for the old shape still works. They also help where a read must return a value or nothing with no branch.

The flat names do not cover the block, and the set does not grow. There are six flat names for fifteen fields. fpr.X, the factor returns matrix, has no flat name, and neither have fpr.chol, fpr.eoc and fpr.rr. The set has six names here, and seven on HighOrderPrior. A field added to LowOrderPrior later is available as pr.fpr.<name>, and gets no flat name, so no field needs an edit in two places.

The two reads are different when there is no factor block. pr.f_mu returns nothing, but pr.fpr.mu raises an error, because fpr is nothing. First check the block with assert_prior_regression, and then read through fpr. The check reads rr only, which is enough, because rr and fpr are present together or not at all.

Composition: what a wrapping estimator forwards

Most prior estimators wrap another, and build their prior result from the result that they receive. forward_prior enforces one rule for the fields that the wrapper keeps. A wrapper forwards a field when the value stays correct. It drops a field only when the forwarded value would state something false. The docstring of the estimator names every field that it drops.

The returned result must be consistent. A wrapper must not remove a value that the caller computed to get that consistency. The default is to forward, and the docstring of each estimator lists the fields that it drops and the reasons. Three bindings tie a field to another, so a wrapper never forwards the bound fields alone:

  • sigma binds chol. When chol is present, every consumer reads it in place of sigma, and a stale chol replaces the changed covariance with no error.
  • w binds ens, eoc, kld and ow. These are diagnostics and counts of the weights.
  • rr binds o_X. rr records the projection that made X from o_X.

forward_prior refuses a forward that breaks a binding.

The original returns matrix

Four estimators overwrite X, and o_X exists for them. FactorPrior, FactorBlackLittermanPrior and AugmentedBlackLittermanPrior write a reconstruction from the factors. CrossSectionalFactorPrior writes scenarios from the factor returns, the loadings and the standardised idiosyncratic returns. On their results, X is the asset distribution that the prior states, and not the returns of the caller. o_X holds the returns of the caller. It is nothing on every other result, where X is the returns of the caller.

The two matrices are different. The reconstruction of the first three estimators spans only the factors. It has rank size(F, 2), and it has no residual. A consumer that fits a moment on the sample again must read the original. Otherwise it gets a singular matrix when there are more assets than factors.

Read the original returns as original_X, not as o_X. The property is always a matrix. It is the field when the field holds one, and X when it does not. A consumer needs no fallback. The field is storage, and it answers a different question. isnothing(pr.o_X) tells whether this prior result changed X. The field holds this state, and the property does not. forward_prior rebuilds through the keyword constructor with every field named. A nothing has no effect there, but a matrix in every result would become stale after a change to X.

o_X requires rr. Every estimator that overwrites X now builds it from a factor prior and loadings, and carries the loadings in rr. A prior result that has an o_X and no rr is a defect. This is a rule of the present library, and not of the domain. A new estimator that changes X with no regression must change this rule on purpose.

The source of the returns

x_src records the frame of X. prior writes in it the source that the prior estimator states, through stamp_returns_source. It does this when it fits on a ReturnsResult, and when it reads out the state of an online fold. A returns-matrix method of prior cannot know the frame of the matrix that it receives, so it leaves nothing. A consumer that receives the Result in place of the estimator reads the frame from this field. The outer problem of a meta-optimiser adds the benchmark back to X when the field is ExcessSource, see outer_returns_source. A HighOrderPrior holds no such field, and answers x_src from the LowOrderPrior that it wraps.

The observations of the rows

ss_gaps records the observations of the returns data that the fit dropped for a Shared Series gap. A fit also drops rows at the start. A Scenario Cap keeps the last rows, and a CrossSectionalFactorPrior drops the rows of its warm-up and of its exposure lag. So the rows of X are the last size(X, 1) observations that ss_gaps keeps. When ss_gaps is nothing, they are the last size(X, 1) observations of the returns data.

A reader that holds the returns data that the prior read pairs its rows with the rows of X through the marks, see shared_series_kept_rows. A reader that holds the returns data after the same cut has fewer observations than the marks, and pairs the last rows. That was the rule before the record existed. prior writes the marks after it fits on the returns data, and after it reads out an online fold. A returns-matrix method of prior drops no observation, so it leaves nothing. A HighOrderPrior answers ss_gaps from the LowOrderPrior that it wraps.

Validation

  • X, mu, and sigma must be non-empty.
  • size(sigma, 1) == size(sigma, 2).
  • size(X, 2) == length(mu) == size(sigma, 1).
  • Every entry of sigma between two investable assets is finite. An investable asset has a finite mu and a finite variance. Raises an IsNonFiniteError.
  • If w is not nothing, !isempty(w) and length(w) == size(X, 1).
  • Each entry of eoc that is not nothing is finite and positive, through assert_moment_counts.
  • If kld is an AbstractVector, !isempty(kld).
  • If ow is not nothing, !isempty(ow).
  • rr and fpr must be provided together or not at all.
  • If the factor block is present, size(rr.M, 2) == length(fpr.mu) == size(fpr.sigma, 1), size(rr.M, 1) == length(mu), and size(fpr.X, 1) == size(X, 1). The two blocks describe the same observations. The constructor of the factor block checks the inside of the block, such as its own w against its own X.
  • If o_X is not nothing, o_X !== X, size(o_X) == size(X), and rr is not nothing. o_X !== X tests identity, not equality. So o_X = copy(X) passes, and o_X = X raises an error. The two calls look the same, but only the first holds a matrix that a later change to X does not change. The check refuses a prior result whose original is the same object as its X. It does not refuse a matrix with equal values.
  • If chol is not nothing, !isempty(chol) and length(mu) == size(chol, 2).
  • The rules of assert_shared_series_gaps on ss_gaps.
  • If pc is not nothing, length(pc.w) == size(X, 1), and size(pc.X, 1) == size(X, 1) when pc.X is a matrix, through assert_pool_cache.

View parameters

LowOrderPrior defines its own port_opt_view method, and does not make one from field tags.

  • It reads no argument after i. It takes and ignores more positional arguments.
  • rr recurses through port_opt_view with i, which cuts the loadings on their asset axis.
  • X, o_X, mu, sigma and chol are cut to i on the asset axis. o_X takes the same cut as X, so the original returns of a subproblem are the returns of the caller for the assets of that subproblem.
  • w, ens, eoc, kld and ow pass through unchanged. They are on the observation axis, and i indexes assets.
  • fpr passes through unchanged, because it is a distribution over factors and not over assets. The view thus keeps rr and fpr together, as the rule of the factor block requires.
  • ss_gaps passes through unchanged. It is on the observation axis.
  • pc is dropped. Its rows hold every asset, and a fit of the subset of assets has no cache of its own.

Carries the coskewness and cokurtosis a high order prior estimator produced, over the low order prior it wraps.

Every high order prior estimator returns a HighOrderPrior. It wraps a low order prior result, and holds the cokurtosis matrix, the duplication, elimination and summation matrices, the coskewness matrix, and the negative spectral coskewness. It also holds the matrix processing estimator of the coskewness, and the factor co-moments. The constructor checks every field.

Fields

  • pr: Prior result.
  • kt: Cokurtosis matrix assets^2 × assets^2.
  • D2: Duplication matrix.
  • L2: Elimination matrix.
  • S2: Summation matrix.
  • sk: Coskewness matrix assets × assets^2.
  • V: Sum of the negative spectral slices of the coskewness matrix assets × assets.
  • skmp: Coskewness matrix processing estimator.
  • eoc: Effective number of observations of the higher moments, a tuple (T_sk, T_kt) with one count for the coskewness and one for the cokurtosis. An entry of nothing means size(X, 1). The property pr.eoc of the result reads the four counts (T_mu, T_sigma, T_sk, T_kt), with the two counts of the low order result first.
  • fpr: Prior result over the factor axis, or nothing. Its X is the factor returns matrix, so its moments describe factors and not assets. It has the same observations as the asset block.

Keywords correspond to the struct's fields.

The counts of the moments

The field eoc holds the effective number of observations of the coskewness and of the cokurtosis. The property pr.eoc reads four counts. The first two are the eoc of pr, the counts of mu and sigma. So pr.eoc[k] is the count of moment k on both result types, and moment_observation_count reads it. A read of the field itself, with getfield, gives the pair. reconstruct_prior reads the fields so, and keeps the pair.

The factor block

A high order prior that a factor model fits carries factor co-moments as well as asset co-moments. The field fpr holds them as a nested HighOrderPrior, and not as the flat fields f_kt, f_sk and f_V. The factor block thus has every field of a HighOrderPrior. These are D2, L2, S2 and skmp as well as kt, sk and V. A field added later also applies to it with no second edit. The flat names still read the nested block. pr.f_kt, pr.f_sk and pr.f_V return fpr.kt, fpr.sk and fpr.V, or nothing when there is no factor block. pr.f_D2, pr.f_L2, pr.f_S2 and pr.f_skmp work in the same way.

fpr.pr is the factor block at the low order, the LowOrderPrior over the factors. pr.pr.fpr, the factor block of the low order result, is the same distribution. The constructor requires that the two are the same object, see the validation below.

fpr is a field of the HighOrderPrior, so a read of fpr finds the field before the forward(pr) block. It names the high order factor block. Before the nested block existed, it named the low order factor block. Reads through it give the same values. The nested HighOrderPrior forwards to its own pr, which the constructor requires to be pr.fpr. So hop.fpr.mu is the factor mean in both cases, and hop.fpr is the factor prior at this order.

Which read to use

Read the factor block as pr.fpr.kt, for the reasons that LowOrderPrior gives. The seven flat names here are f_kt, f_sk, f_V, f_D2, f_L2, f_S2 and f_skmp, and the set does not grow. A field added to HighOrderPrior later is available as pr.fpr.<name>, and gets no flat name.

The two reads are different when there is no factor block. pr.f_kt returns nothing, and pr.fpr.kt raises an error. Check the block first, and then read through fpr.

Validation

Let N = length(pr.mu).

  • If one of kt, L2 or S2 is given, all three must be given and not empty, with size(kt) == (N^2, N^2) and size(L2) == size(S2) == (div(N * (N + 1), 2), N^2).
  • If sk or V is given, both must be given and not empty, with size(sk) == (N, N^2) and size(V) == (N, N).
  • If the three matrices of the first rule and sk are given, D2 must be given and not empty, with size(D2) == size(transpose(L2)). D2 has no other rule. It is the one moment field that the constructor admits alone, and a HighOrderPrior that holds only D2 is valid.
  • If fpr is given, pr.fpr must be given, and fpr.pr === pr.fpr. The factor co-moments are computed against the factor block of the low order result, not against a copy of it. The opposite rule does not apply. A low order factor block with no factor co-moments is usual, so fpr === nothing always passes. The constructor of the factor block checks the inside of the block, such as its own shapes against its own N.

View parameters

HighOrderPrior defines its own port_opt_view method, and does not make one from field tags.

  • It reads no argument after i. It takes and ignores more positional arguments.
  • pr recurses through port_opt_view with i, which cuts every low order field.
  • A fourth-moment index derived from i indexes kt, and i does not. kt is $N^2 \times N^2$ over ordered pairs of assets, so the asset index does not address it.
  • sk is cut by i on its asset axis, and by the same fourth-moment index on its pair axis.
  • V is computed again from the cut sk, and is not cut. It is a spectral quantity of the coskewness matrix, so the submatrix of V is not the V of the submatrix.
  • D2, L2 and S2 are built again for the number of assets of the subproblem, and are not cut. They depend only on that number, and hold no data of a specific asset.
  • skmp passes through unchanged. It is the matrix processing estimator that the new computation of V reads.
  • eoc passes through unchanged. It is on the observation axis, and i indexes assets.
  • fpr passes through unchanged, because it holds co-moments over factors and not over assets. The view forwards the same object, so fpr.pr === pr.fpr stays true. The low order view forwards its own factor block in the same way.

Compute a prior result from the returns data with a prior estimator.

prior reads the asset returns and the factor returns from rd, and gives them to pe with the other data that rd holds. Every caller uses this method, and this file defines it once. Each estimator implements the returns-matrix method that this method calls. AbstractPriorEstimator states that contract.

Algorithm

  1. Check that rd carries asset returns, so that the estimator does not receive nothing for X.
  2. When needs_factor_returns answers true, check that rd carries factor returns. The predicate reads the whole tree, so it finds a factor estimator inside an outer estimator whose factor argument is optional. The check runs here, so the caller gets a named error about rd.F. Without it, the caller gets a MethodError from the inner estimator one call later.
  3. Read the source that pe states with returns_source. Call it x_src.
  4. Drop the observations of a Shared Series gap with shared_series_view. These are a gap of a vector benchmark under x_src = ExcessSource(), and a gap of the factor returns when needs_factor_returns answers true. Every field of rd loses the same observations.
  5. Read the asset returns X with benchmark_relative_returns under x_src. X is rd.X, or rd.X - rd.B under ExcessSource().
  6. Call the returns-matrix method of the estimator with X, rd.F and rd.pnl. Pass rd.iv, rd.ivpa, rd.ne, rd.E, strict and cache_reg as keyword arguments. A wrapper prior passes its keyword arguments to the estimator that it holds. The Exogenous Series gets to a CrossSectionalFactorPrior whose observed factors read it, and every other estimator ignores it. The call passes dims = 1, because a ReturnsResult holds its observations along the rows. The keyword dims has no effect.
  7. Record the observations that step 4 dropped with shared_series_record. A reader that holds rd then pairs the rows of X with the correct observations.
  8. Record x_src in the prior result with stamp_returns_source.

The Asset Panel is the third positional argument for the same reason that rd.F is the second. A wrapper prior holds no ReturnsResult. It can hold an estimator that fits on a panel only if the panel gets to the returns-matrix method of that estimator. Every returns-matrix method takes the argument. Every wrapper prior passes it unchanged to the estimator that it holds over the assets. An estimator that reads no panel ignores it.

Arguments

  • pe: Prior estimator.
  • rd: Returns data that holds the asset returns, and the factor returns when the estimator reads them.
  • strict: Passed to the returns-matrix method of the prior, where it decides if a scenario fill or a coverage peel raises in place of a warning.
  • dims: Accepted and ignored. A ReturnsResult holds its observations along the rows, so the call passes dims = 1. The method takes no other keyword that it does not list: an unknown keyword raises the MethodError of the language, and no estimator swallows it.
  • cache_reg: If true, a prior stores on its result the cache that its refit under new scenario weights reads: a CrossSectionalFactorPrior the active mask and the Return Forecast history on its block, and an OpinionPoolingPrior the rows of pe1, its pooled weights and the cache of pe2 in pc. The refit of an entropy pooling prior around it then runs no regression and no opinion. Every other prior forwards it to the prior that it wraps. Default is false.

  • !isnothing(rd.F), when needs_factor_returns(pe) === true.
  • The rules of shared_series_rows.

forward_prior(
    pr::AbstractPriorResult;
    overrides...
) -> AbstractPriorResult

Forward a wrapped prior result, and name only the fields that the wrapper estimator changes or drops.

This function applies the composition rule of the prior results. A wrapper forwards a field when the value stays correct. It drops a field only when the forwarded value would state something false. The docstring of the estimator names every field that it drops.

The default is to forward, and the caller writes nothing for it. A wrapper cannot return fewer fields than the result that it wraps by mistake. The call site names every change. A new value is field = value, and a drop is field = nothing. A search of the source finds every drop. A hand-written call to the constructor names all fifteen fields of a LowOrderPrior, and does not show which of them it changes.

The rebuild goes through the keyword constructor of pr, see reconstruct_prior. Every @argcheck runs, and a forward that leaves the result inconsistent raises the same error as a hand-written constructor call. A caller can name only a field of pr. A forwarded or computed property is a view of a nested value, so a value for it can mean only a value for the field that holds it.

The three enforced bindings

Three fields are bound to the value of another field. To forward one of them past a change to its field states something false. The function enforces each binding. When the caller names the field on the left, the caller must also name the fields on the right, with a rebuilt value or with nothing.

  • sigma binds chol. When chol is present, every consumer reads it in place of sigma. A stale chol makes the optimisation ignore the posterior covariance with no error.
  • w binds ens, eoc, kld and ow. These are diagnostics of w and the counts of the moments that w weights, so they are false for a different w.
  • rr binds o_X. o_X says that X is a reconstruction, and rr records the projection that made it, so the constructor refuses one without the other. A drop of the factor block also drops the original returns.

A binding has no effect when the bound field is nothing, or when pr has no such field. No stale value is then present.

The constructor checks the rest. rr and fpr must be given together or not at all. The constructor checks w, chol, o_X, ss_gaps and pc against the shape of X and mu again.

What does not fit

FactorPrior and FactorBlackLittermanPrior lift a factor-axis prior into an asset-axis result. AugmentedBlackLittermanPrior merges two priors. None of the three forwards one wrapped result along its own axis. Each calls the constructor of its prior result directly, and does not use this function. Each still uses forward_prior on the factor block that it builds, because that is a usual forward of the factor prior.

Algorithm

  1. Collect the keyword overrides into the named tuple patch. When patch is empty, return pr itself, because a forward that changes nothing rebuilds nothing.
  2. Compare the names of patch with the fields of typeof(pr). Call the names that are not fields extra. When extra is not empty, raise an ArgumentError that names the fields of pr.
  3. Enforce the binding of chol to sigma. When patch names sigma and not chol, and bound_field_is_stale says that pr holds a chol, raise a ConflictingArgumentError.
  4. Enforce the binding of o_X to rr with the same three tests. A failure raises the second ConflictingArgumentError.
  5. Enforce the binding of ens, eoc, kld and ow to w. When patch names w, collect into stale each of the four that patch does not name and that pr holds. Raise when stale is not empty.
  6. Rebuild pr through reconstruct_prior. It merges patch over prior_field_values and calls the keyword constructor, so every @argcheck of typeof(pr) runs on the result.

Arguments

  • pr: Prior result that the wrapped estimator returned.
  • overrides...: Field overrides. Each is a value to replace, or nothing to drop.

Validation

  • When overrides names sigma, it also names chol, unless pr.chol is nothing.
  • When overrides names w, it also names each of ens, eoc, kld and ow that pr states.
  • When overrides names rr, it also names o_X, unless pr.o_X is nothing.
  • Every name in overrides is a field of typeof(pr).
  • Every @argcheck of the constructor of typeof(pr).

Returns

  • pr::AbstractPriorResult: The wrapped result with overrides applied, or pr itself when overrides is empty.

Rebuild a prior result through its keyword constructor, with the fields that patch names replaced.

Each prior result type has one method, because the method names the constructor of the type and does not find it by reflection. A generic method needs Base.typename(T).wrapper or a dependency on ConstructionBase, and neither gives more. prior_field_values already reads the field list from the type, so a result type that gains a field needs no change here. Only a new prior result type needs a method. Until it has one, a call raises a MethodError that names this function, and no generic code rebuilds a type that it does not know.
