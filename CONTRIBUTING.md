# Contributing to PortfolioOptimisers.jl

Thanks for your interest. Contributions of all kinds are welcome: code, documentation, examples,
bug reports and questions.

The full guide is in the documentation:

- [Contributing guidelines](https://dcelisgarza.github.io/PortfolioOptimisers.jl/stable/contribute/1-contributing)
  : bug reports, discussions, and how to work on an issue.
- [Developer documentation](https://dcelisgarza.github.io/PortfolioOptimisers.jl/stable/contribute/2-developer)
  : how to set up the package locally, run the tests and build the documentation.
- [Code health](https://dcelisgarza.github.io/PortfolioOptimisers.jl/stable/contribute/3-code-health)
  : the automatic checks that every change must pass.

Follow the [code of conduct](CODE_OF_CONDUCT.md) in every interaction.

## Before a pull request

1. Open an issue, or comment on an existing one, and describe the change that you plan.
2. Wait for a reply when the solution is not clear. A clear fix can go straight to a pull request.
3. Read [`CODING_STANDARDS.md`](CODING_STANDARDS.md) for the rules of the code, and
   [`GLOSSARY.md`](GLOSSARY.md) for the names of the domain.

## Support

Ask for help, report a bug or request a feature in an
[issue](https://github.com/dcelisgarza/PortfolioOptimisers.jl/issues). Support is best effort,
and there is no fixed response time. If an issue gets no reply after a few days, comment on it
again.

## Governance

PortfolioOptimisers.jl has one maintainer, Daniel Celis Garza, who reviews and merges every
change and decides the design questions. The decisions are recorded as architecture decision
records in [`docs/adr/`](docs/adr/README.md).
