Problem. __init__ reads eleven Preferences.jl keys from the active project and applies them to the global caps. The value check is Integer && !Bool && > 0, so there is no ceiling: a file raises every cap the library has, silently, before any user code runs. Reachable — reproduced in a fresh process, not only through the function.

Direction. Bound the load-time channel against the shipped defaults, or announce with a warning each cap a file changed, and correct the docstring, whose fail-closed claim covers invalid values alone.

  • caps: unbounded raise → bounded
  • a load-time raise is announced
  • docstring matches the behaviour
  • blast radius: one function, 11 keys
  • no caller loses a runtime setter
  • closes a code-free attack path
ADR 0041 (one resource cap per sink). The ADR accepts that a caller may resize a cap. It does not decide whether a file may, silently, at load. That is the new surface, and it is the part to settle.

Problem. The guard rejects 0, a negative value and NaN, but 1e-9 is positive and admits every candidate — exactly the failure the message describes.   • guard matches its own rationale
  • the shipped default is unaffected
  • blast radius: one @argcheck
ADR 0026 (lenient constraint names with suggestions). The ADR sets the info-leak-safe boundary this guard exists to hold. The finding is that the guard is placed below the boundary, not that the boundary is wrong.

Before — measured
state_key(p, :te_dr_,  11) == :te_dr_11
state_key(p, :te_dr_1,  1) == :te_dr_11   # equal

state_set!(m, p, :te_dr_,  11, v1)
state_set!(m, p, :te_dr_1,  1, v2)
length(object_dictionary(m))  → 1
m[:te_dr_11]                  → v2
# v1 is gone. No warning, no error.
After — re-registration fails closed
function state_set!(model, prefix, name, i, val)
    key = state_key(prefix, name, i)
    @argcheck(!haskey(model, key),
      ArgumentError("Model State key `$key` is \
       already registered …"))
    model[key] = val
    return val
end

Problem. Symbol(prefix, name, i) concatenates, so a name that ends in a digit and a smaller index compose the same key as a shorter name and a larger index. state_set! then overwrites without a warning, and a constraint binds the wrong variable — a silent wrong result, not a crash. This is how :te_dr_11 was born. Latent: I checked all 240 shipped name tags for every prefix pair whose remainder is digits, and no pair collides today. Nothing stops the next tag.

Direction. Make state_set! refuse a key that is already registered. The interface already carries the idempotent case in a separate verb — state_build! returns an existing entry untouched, and mark_state! is documented as idempotent — so a repeated state_set! has no legitimate reading. The cheaper alternative is a fourth seam-lock rule that runs the 240-tag census in CI.

  • fails closed on a duplicate key
  • closes the class, not the instance
  • silent wrong result → typed error
  • blast radius: two methods
ADR 0037 (Model State accessor interface). The seam-lock rules police the spelling of a key and the access to one. Neither can see that two well-spelled keys compose the same Symbol, so the collision class stays open. Confirm first: no build was run against a solver — none is installed in the test environment — so a build-time census of duplicate registrations is the step that proves the guard breaks nothing.

4 · Two new total functions, opposite default polarity

Worth exploring Low input-validation
src/13_Prior/03_FactorPrior.jl:255–257 · src/19_RiskMeasures/01_Base_RiskMeasures.jl:227–229
range_tails — fails closed
function range_tails(r::AbstractBaseRiskMeasure)
    return throw(ArgumentError(
      "`range_tails` is not defined for \
       `$(typeof(r))`. …"))
end

range_tails(Variance())
→ ArgumentError, and it names the type
factor_residual_config — fails open
function factor_residual_config(
             ::AbstractPriorEstimator)
    return nothing
end

factor_residual_config(EmpiricalPrior())
→ nothing        # correct: no residual block
factor_residual_config(MyNewFactorPrior())
→ nothing        # a forgotten method reads
                 # the same as a correct answer

Problem. The same delta added two per-type total functions with opposite defaults. factor_residual_config cannot separate "this estimator has no residual block" from "the author forgot the method", so an extension silently drops its residual block. The consumer then reads .rsd / .ve / .pdm off the returned value with no shape check. Latent: no untrusted input reaches this — it is an extension-author surface, and every shipped type declares correctly.

Direction. Give the fallback the same polarity as range_tails: throw and name the type, and let a type that genuinely has no residual block say so with an explicit method. Check the returned shape before the property access.

  • one default polarity, not two
  • a forgotten method fails closed
  • shape checked before property access
  • blast radius: one method, plus declarations
ADR 0046 (wrapping priors forward by default). The amendment made factor_residual_config total. Whether "total" here means "answers for every type" or "throws for an undeclared type" is the open question, and it is the maintainer's call.

Top recommendation — bound the load-time preferences channel

Close finding 1 first. It is the only finding in this pass that an attacker reaches without running code: a LocalPreferences.toml is data, it travels with a cloned project or a template, it is often untracked, and it is applied at using PortfolioOptimisers with no warning. One file disarms every guard the last three passes installed — the six ResourceLimits caps that turn an OOM kill into a typed error, the two EquationLimits caps that hold the string→AST boundary, and the ADR 0026 info-leak boundary of finding 2. The fix is local to one function and costs no caller a runtime setter. Finding 3 has the worse blast radius — a silent wrong result — but it is latent, so it is second.
