ProblemUnconstrainedNearOptimalCentering is the default alg, and it is the only one of the five JuMP optimisers that never calls assemble_jump_model! — so about twenty JuMPOptimiser settings are carried, validated and silently dropped.

AlsoIts objective omits add_custom_objective_term! and add_penalty_to_objective!, which its constrained sibling has. Deletion testThere is no module to delete — that is the finding. assemble_jump_model! concentrates (one ordering, five callers). What is missing is a membership statement, so opting out happens by omission and no configuration error can be raised.

SolutionMake "does not run the middle" a declared property of the formulation, and let the head refuse the settings that formulation cannot honour. Route both objectives through the same envelope so the Objective Penalty is structurally present even when empty.

leverage: one place says what is honoured
locality: new field forces one decision
tests: the drop becomes assertable

ADR 0036 §7 is contradicted in effect on this path (the typed fallback never runs because the hook is never reached) and warrants an amendment.

ProblemTwo families are steppable but unroutable. ProblemADR 0053 makes scale a Combination Weight and enumerates four sites. Stacking.scale is a fifth, and the weight never reaches the combination. Under any cv it is entirely inert; without one, its only observable effect is a tilt of the benchmark column. The documented math w* = opto(Σ s_k W_k) describes something the code does not do.

ContrastSubsetResampling applies its scale at the combination and divides by sum(scale); Schur cancels it by renormalisation. Both are named in ADR 0053. Stacking was not measured.

Deletion testDelete it today and almost nothing changes — the diagnosis, not the recommendation. A real "apply the weight to the synthetic universe" module would concentrate four consumers that each currently decide independently, three of them by accident.

ADR 0053 states the rule binds "every site" and enumerates four. This is a site it did not measure — a factual addition, not a reversal. Cheap to amend. The correct semantics is a domain call for the maintainer.

Top recommendation

01 — Declare which optimisers run the Model Assembly middle

It is the default alg, it is the only one of the five JuMP optimisers that skips assemble_jump_model!, and every setting it drops was constructed and validated first — so the caller has been told the configuration is good and gets a portfolio that ignores it. The fix is a declaration, not a rewrite: ADR 0008 §6 already decided this formulation has no middle, and stating that in the interface lets the head refuse what it cannot honour.

Take 02 (the Frontier sweep) alongside it — the drifted k lives in the same two files, and both are latent for the same reason.
