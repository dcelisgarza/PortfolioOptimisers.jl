ADR 0041 — one cap per sink. This sink is linear in n, so a linear cap is the right shape, and the field already mirrors max_n_subsets in every other respect. get_n_subsets caps at the resolution seam precisely because a constructor cannot see what a callable rule ultimately returns; resolve_separation is the same seam and type-checks the answer without capping it.

Problem. Reachable through one keyword: n drives for i in 0:n; P .+= A^i at three readers, costing roughly n · log n · N³ flops, so a large value wedges the session on compute rather than memory.

Direction. Add a fifth ResourceLimits field and assert it in both places max_n_subsets is asserted — the HopCount constructor and the resolve_separation seam that resolves a caller-authored rule.

  • blast radius: process wedge
  • linear cap bounds a linear sink
  • copies the proven twin exactly
  • closes constructor and resolution seam

Floating CI inputs have already bitten this repository. The recent red workflows tracked as #332/#333 were traced to a Julia point release arriving through a floating version selector, not to any source change. That is the same class of exposure, and it argues the pinning question is live rather than theoretical. Testing against the current 1.x is a deliberate choice; running an unpinned action is not, since nine sibling workflows pin it.

Problem. Reachable on every push to main and on every pull request: @latest resolves at run time to whatever the action owner last published, and Aqua.yml pairs that with no permissions: block, so the job token falls back to the repository default rather than an enumerated set. Seven of eleven workflows declare no permissions block.

Direction. Pin both to @v2, and add permissions: contents: read to the workflows that only read, as FormatCheck.yml already does.

  • supply-chain: mutable ref → pinned
  • brings 2 workflows under Dependabot
  • least-privilege: default → read-only
  • blast radius: two-line fix

Top recommendation — close the string arm of pipeline_lens first

Finding 1 is the only reachable path in this pass that both produces a silent wrong result and writes into the object being tuned: a grid key of "steps" or "names" resolves against a real Pipeline field, so cross-validation sets grid values into the pipeline's own step table instead of tuning a step. It is also the cheapest to close — the Symbol method nine lines below already contains the guard, the suggestion call and a comment explaining why the fallthrough is wrong, so the fix is to apply the same three lines to the arm that callers actually use. Take Finding 2 next: it is the other silent-wrong-result path, and it likewise only needs the check its own sibling branch already performs.
