# Review plan for PR #261 — eleven blocks

This PR is 110 commits, 503 files, +89,169 / -12,693. It is not reviewable as one diff. It is
split below into **eleven blocks**. Each block is a contiguous range of commits with one theme,
and each block ends on a commit whose CI was green.

## How this works

1. Review **one block at a time**, in order. Open its compare link and read only that range.
2. Raise comments against that block. Prefix each with the block number, for example `[B3]`.
3. The author addresses them. Fixes land as new commits at the tip of `dev`.
4. Tick the block's boxes when the item is satisfied.
5. **A block closes when every box is ticked and every `[BN]` comment is resolved.** Only then
   open the next block.

One wrinkle of block review on a single PR: a fix for block 3 arrives as a commit after block 11's
commits. When you re-check a block after fixes, read the block range **plus** the fix commits, not
the block range alone.

Edit this comment to tick boxes. It is the single source of progress.

**Not a B5 defect, and worth carrying to ADR 0049 anyway.** The two unsafe DBHT aggregations the
ADR names are **unreachable with a negative weight** at `HEAD`: `DBHTs` is the only caller of the
bubble machinery, its `Rpm` is `PMFG_T2s(S)[1]`, and `PMFG_T2s` refuses a negative or a `NaN`
before it returns. The reachable residue is the **exact zero**, which ADR 0049 admits by decision
("Non-negative, not positive"). A zero weight is not a weak edge: `A = W ⊙ ((A + A') .== 1)` makes
it an **absent** edge, so an exactly-zero similarity deletes PMFG edges — measured 21 of 30 on a
12-asset fixture — and `clusterise` then dies with a `BoundsError` inside
`turn_into_Hclust_merges`. It is pre-existing, it predates this PR, and the route the ADR cites to
justify admitting zero (`LogDistance` at an exactly zero correlation, `exp(-Inf) = 0`) is the route
that reaches it.
